## What was built

### (1) Per-runner routing (Q82): `holon.eval.holon_run.route`

Opt-in: the protocol names `run_routing "per_runner"`. Without it the run step is I110's two calls, unchanged (every
earlier protocol; I111's tests pass as before). Under it, every derived law is grouped by the runner of its rule
family, read from `laws/<M>/DERIVATION.json`, mirroring `holon/__main__.py`'s dispatch:

| runner | laws | arguments beyond `--milestone --laws --out --gen-dir` |
|---|---|---|
| disch | rule DISCH, `holon.disch.run.SUBFORMS` | `--sidecar --disch` and `--section-errors unknown` |
| fact | rule FACT | `--sidecar --fact-sidecar` |
| typed | SORT `as_member`/`realize`/`reinterpret`, UNDO, SYM | `--sidecar` |
| milestone | everything else (PAR, route C's families) | none (holon run's own dispatch: `holon.pipeline`, gox, ...) |

One `holon run --laws` per non-empty group, in that order; a failed call is recorded and the next runs. The stage
detail is aggregates only (per runner: laws, status, exit, records, section errors); each runner's own output, which
names law ids, goes to the vault (`run_outputs.json`), never the row (Q72). The row carries `run_runners`.

**Coverage for the composed route (found on the planted fixtures).** A DISCH law over a Solidity transitions document
could never get a record: `holon.records.coverage_field` reads `gen/<M>/coverage.json`, which `holon coverage` writes
from the milestone's `spec/*/lib/extract_*.json` sidecars, and the composed driver keeps its generated sidecars beside
its documents. So every such law raised in the record writer. `holon coverage --sidecars a,b` now accounts for the
given extraction sidecars (the frontend's own walk, unchanged), and the composed driver runs it, under
`run_routing` only, before the run step (stage `coverage`). Without `--sidecars` the report is computed as before.

### Section errors (Q82): `holon run ... --section-errors unknown` (`holon.disch.run`)

Without the option, a `SectionError` while building one document's DISCH section propagates and stops the runner, as
before. With it, `Run.section_error` builds the document's section once; if that raises `SectionError`, every DISCH
law of the run over that document is recorded UNKNOWN by `Run.section_record`: kernel verdict and checker `not_run`,
no witness, `attempts [{kind: section, error}]`, bound "the DISCH section of <model> is refused: <error>". Nothing is
attempted for it. Every other document's section is built and decided as before; S3's seeds come from the same
document's laws only, so another section's error changes no verdict. Only `SectionError` is caught.

### (2) O1 widened (Q81, the lead's correction): `holon.sorts.opaque.classes` / `class_of`

Under `types_fallback "opaque"`, the sidecar may name `types_opaque_classes`, a non-empty sorted subset of
`gen_error` (any `model3.GenError`), `member_layout` (`holon.machine.MemberLayoutError`, a new `ModelError` subclass
raised exactly where `holon.machine` refuses a field that is not the compiler's member layout, its text unchanged)
and `unsupported` (`holon.extracted_eval.Unsupported`). Any other value, or the key without `types_fallback`, is
refused. Absent, the classes are I111's (`gen_error`) and every output is I111's byte for byte (no `class` field).
A named class makes the document opaque under I111's O2-O7, unchanged, and its miss records `class`. Every other
error, `ModelError` included (a family not in the compiler's layout at all), still refuses the milestone.

### (3) `withhold()` in the driver: `holon_run.withhold_gen`

Every file under `<id>/gen/` whose path or text names a derived law id, and every `large_files.json` entry whose path
does, is removed from the committed output (the vault keeps the whole `gen/`), recorded as `<id>/gen_withheld.json`
`{files, sha256}` in I111's tool's canonical form; every law id in a stage detail becomes `<law id withheld>`.

### (4) Q80's preflight: `holon_run.preflight`

Under `preflight "toolchain_sets"`, before any entry: every `solc_set` release (the protocol selects by pragma) is
present with its pinned sha256, and every `go_set` release (by go directive) prints its pinned version line (the set
pins the go tarballs, not the installed binaries, so the version line is the check). Otherwise `holon eval holon`
exits 2 and writes nothing. The check is recorded in `corpus.json` `preflight`. On this container: 42/42 solc and 2/2
go.

## Soundness

- **Routing** changes which process decides a law, never how: each runner decides its laws exactly as when `holon run`
  is called on them alone (the same entry points `holon/__main__.py` dispatches to). A law no runner records is
  UNKNOWN.
- **A section error never yields a decision.** The record is UNKNOWN with no proof, search or witness, so it can only
  remove decisions. Other sections are unaffected: a section is one document's, built from its own model, and the
  search's seeds are per document.
- **The new opacity classes are I111's O2-O4.** An opaque document contributes no model, state, action or law, so it
  only removes constraints; a typed neighbour's model does not read it (another contract is an A-env free answer).
  P4 and P5 check, for each new class, the three planted shapes: alone (no law), cross-document (the neighbour's laws
  byte-identical and records equal), constrained-state (the control decides what the opaque document leaves UNKNOWN).
- **Coverage** only annotates a record (`coverage` field); it is not a premise.
- (3) and (4) decide nothing.
- Every REFUTED still needs its replay: route A's replay and filter stages are unchanged (the binding is null, so the
  replay is `not_applicable` and a REFUTED is a model-level finding, handled under Q56 below).
