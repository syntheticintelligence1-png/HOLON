## Surprises

1. **Rule V1 was wrong, and was caught blind.**
   - As preregistered, a storage name declared twice was an error. The development target's own extracted rollup
     declares `__gap` three times, in OpenZeppelin's upgradeable bases, so the rule could not have built that diagram.
   - The rule was amended before the seal opened: one carrier per storage entry, with the id `<declared_in>.<name>`
     when a name repeats. The amendment is `spec/M4/amendments/I49.jsonl` line 1; the new sha256s are in the test's
     AMENDED_PINS.
   - The held-out document repeats `__gap` too, so the amendment matters there.
2. **Two test-instrument defects, found after the seal opened.** Both are target-independent and amended (lines 2-3):
   - rule S4 and the test took solc's whole version text, but the frontend compares only the number before `+`;
   - the test compared `extraction.sidecar` with a path, but the frontend records `{path, sha256}`. The new
     assertion is stricter.
3. **G8 and dead code.** This is the frontend's rule as built: "a statement neither extracted nor debt, including one
   the walk never reached (dead code), is unaccounted". The held-out contract has a statically dead branch, so G8
   cannot pass on it with the pinned frontend. Fixing it would need a frontend change, for example a `dead_code` debt
   kind. The frontend is record-pinned, and changing it after the seal would tune the extractor to the target. So it
   stays as it is, and the miss stands.
4. **I47's development target re-extracts the wrong document.**
   - `targets/morph/target.json`'s extract command runs `holon extract solidity --milestone M2` without `--sidecar`.
     That takes M2's default sidecar, the header layout, and writes it under the rollup document's name. So `holon
     target extract --target morph --check` and I47's drift on Morph compare the wrong document.
   - With `--sidecar spec/M2/lib/extract_rollup.json` the frontend reproduces the committed rollup document byte for
     byte.
   - Not fixed here: it is I47's file and outside the seal protocol. It is reported for I47's PR.
5. **Dependencies.**
   - The pinned sol_deps hold `@openzeppelin/contracts-upgradeable` 4.9.3. The target's `yarn.lock` resolves the same
     version.
   - The target checkout has no `node_modules`, so rule S6 lists the 5 OpenZeppelin units as dependency_version debt
     ("the target's own version is unknown"). They are listed, not hidden.
