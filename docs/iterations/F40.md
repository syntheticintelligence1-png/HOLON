## The problem (Q36)

On a partial-M3 run, the DISCH law `L_disch_rev_initializable_120_d9a34b48` (the generalized chain_revert of
`initialize4`: every action excluded under the blocked condition reverts while it holds) had no non-vacuity inhabitant,
so G11V could not confirm its premises are reachable. The inhabitant is a reachable state where the blocked condition
holds and `initialize4` is called on an action of the law's set. `initialize4` succeeds only when two guards it reads
hold (`contracts/contracts/l1/rollup/Rollup.sol:210-211`):

- `msg.sender == sload(<ERC-1967 admin slot>)` — the caller must equal a value the deployment stored (the binding's
  proxy admin, `0x…ad`);
- `len(code(_newSubmitter)) > 0` — a parameter must name an account that holds code.

I30's witness search (`holon.sorts.search3`) could satisfy neither:

1. **The caller pool** (`pools_of`) kept only stored values above `0xff` and the hints' addresses. The admin value is a
   stored word the guard compares with `["caller"]`, but nothing fed the *compared* value into the caller pool, so the
   admin caller was never tried.
2. **The environment held no code.** The search's base environment set `code` only from `init["code"]`, which the
   deployment never produced, so every account — the target included — read empty code, and the `len(code(..)) > 0`
   guard could never pass.

Both are generic gaps in the search, not anything specific to `initialize4`: any guard that compares the caller with a
stored slot or family, or that reads an account's code, hit them.

## The fix (two generic changes, each in a generator)

Commits on `f40`, oldest first:

- `d342c27` — **the caller pool keeps the values the document compares with the caller.** `holon/sorts/search3.py`:
  `caller_reads(doc)` collects every operand `X` of a guard/check `["==", X, ["caller"]]` (either order) with `X` a
  `["sload", slot]` or `["storage", family]`; `caller_values(model, state, doc)` evaluates those reads on the state
  (the slot's word, or the family's bytes shifted and masked) and keeps the plausible address-range values
  (`0 < v < 1<<160`). `pools_of` puts them after the stored addresses, so the earlier callers keep their order
  (determinism): `callers = sorted(stored) + compared + sorted(rest)`.
- `35b7c65` — **the deployment's runtime code is in the environment of the steps that read code.** A new module
  `holon/sorts/envcode3.py` runs the same capture as `holon.sorts.deploy3` (unchanged — it is in the holon-ir/0.2 and
  0.3 generator closures) and keeps the two code tables the capture already records: the target's runtime code and its
  implementation's. `holon/sorts/run3.py` threads it into the model's init as `init["code"]` (`with_code`).
  `holon/sorts/search3.py` gives that table to the environment of a step **only when its action reads an account's
  code** (`_code_reads` over the action's document entry; for the rollup, `initialize` and `initialize4`), so the
  environment of every other action is unchanged; and a failing check that reads `code(X)` offers `X` the addresses
  whose code the environment holds. `envcode3` is reached only from I30's GEN3 closure, so `deploy3`'s place in the
  0.2/0.3 closures is untouched.

## Surprises

- The binding's proxy admin is a stored word (`sload` of the ERC-1967 admin slot), not a hints address, so it reached
  the caller pool only once the pool kept the values the document compares with the caller. (The first analysis of Q36
  read the admin slot as 0; it is `0x…ad`, a value the capture stores.)
- **The Q36 inhabitant is never replayed, so the real proxy does not reject it.** The brave-wright session flagged that
  OpenZeppelin 4.9.3's `TransparentUpgradeableProxy` rejects `initialize4` called by the admin `0x…ad` as a plain call
  (the admin cannot fall through to the implementation; it reaches `initialize4`'s body only via the admin's
  `upgradeToAndCall`). This does not affect F40: the DISCH non-vacuity inhabitant is never replayed on the real contract
  (`holon/disch/run.py:390`), so it is a Bend model proof only. The typed model has no proxy layer, so the plain admin
  call is the faithful model image of the implementation body running with `msg.sender == admin`, a reachable real
  execution. And a REFUTED law's witness that checks but does not replay is rejected, leaving the law UNKNOWN
  (`holon/disch/run.py:598-617`) — never a false REFUTED — so the widened caller/code search cannot manufacture a
  false REFUTED through a non-replayable admin plain-call.
