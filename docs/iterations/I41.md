## Done

### `holon/intake.py` (`python -m holon intake`)

It names no law id and no target, and it never imports `tests/reference` (TestContract).

**`REASONS`.** These are the eleven refusal reasons, in the order the checks run. The first check that fails decides.

1. **`bad_submission`.** `proofs/inbox/<law_id>/` must be a real directory that holds exactly two regular files, `PROOF.bend` and `submission.json`. Nothing is followed through a link. `submission.json` must hold exactly the keys `law_id`, `prover` and `statement_hash`, with:
   - `law_id` equal to the directory name;
   - `prover` matching `agent:[A-Za-z0-9][A-Za-z0-9_.-]{0,63}` in full, so `"generator"` is refused;
   - `statement_hash` of the form `sha256:<64 hex>`.

   `PROOF.bend` must be UTF-8.
2. **`unknown_law`.** No milestone (`laws/<X>/REGISTRY.json`, X `[MT][0-9]+`) has both `laws/<X>/<law_id>.json`, stating that id, and `results/<X>/<law_id>.json`.
3. **`statement_mismatch`.** The submission's hash is not the record's.
4. **`not_unknown`.** The record is neither UNKNOWN nor PROVED with an `agent:` prover.
5. **`escape_hatch`.** `holon.bend.escape_hatches` finds a hatch, comments included. `hatches` lists the classes.
6. **`declares_law`.** `holon.bend.declares_law` finds a law declaration, with comments removed as Bend removes them. This is G3's rule for files under `proofs/`. The scan moved from `holon.gate` to `holon.bend`, and the gate imports it, so the gate and the intake share one rule.
7. **`missing_expected_law`.** `holon.mpipeline.law_import_problem` fails for the proof at its layout path.
8. **`law_file_changed`** and 9. **`generated_file_changed`.** These are G1 against `Regeneration` (below). `differs` lists every differing law, model or core path, sorted and repo-relative. A law path decides `law_file_changed` before a model or core path decides `generated_file_changed`.
10. **`kernel_rejected`.** A required kernel finished and did not accept the proof.
11. **`over_budget`.** `bend2` did not finish within the budget. `holon.bend.run_budgeted` runs the checker in its own process group and kills the whole group at the budget. `seconds` is the wall time.

No kernel runs on a submission that any of the first nine checks refuses.

**`Regeneration`** is G1 for the law's milestone. It runs once per milestone and CLI run, in a fresh temporary directory, with `HOLON_BUILD_DIR` set to a fresh build directory. From the frozen IR, the facts and the committed records, it produces:
- the model of every law's facts, through `holon.mpipeline.run_model` (the instrumented model where `DERIVATION.json` holds SORT-site laws). For M0 it uses `holon.gen.model`;
- the core library, through `holon.gen.core.emit`, for M2 and later;
- each law file as `holon run` writes it, in the run's law order: the statement for a PROVED record, and the counter-law for a REFUTED one, with the record's `failing_conjunct`.

A law that `holon run` writes no Bend file for has no law file and no statement. Those laws are:
- a SORT-width law, which `holon.mpipeline.decided_without_bend` sends to `holon.sorts.width`;
- a statement the emitter or the IR or oracle rules reject.

When a law path differs:
- A decided law's file differs when it is present and different, or when it is missing.
- An UNKNOWN law other than the submission's own differs when a law file is present at its path, since holon run writes none.
- The submission's own law file may be absent. If it is present, it must equal the regenerated statement.

**Kernels.** The proof is checked only inside a fresh directory. That directory holds exactly the regenerated model of the law, the regenerated core library and the regenerated law file, at the layout paths. The kernels run in this order:
1. `bend2` within the budget;
2. `bendtt` (`--verdict`), when `holon.bend.verdict_enabled()`;
3. `lean4`, for I9's Lean-covered set: the Lean text `holon.lean.emit_for` gives for the PROVED verdict, checked by `holon.lean.check_text`.

`required_kernels(M, root)` gives exactly that list. Temporary paths in a kernel's output are replaced by `<regenerated>`, so decisions are deterministic.

**CLI.**
- `python -m holon intake [--milestone M] [--root DIR] [--inbox DIR] [--law ID ...] [--budget-s S] [--json]` prints `{"inbox", "budget_s", "decisions"}`, with decisions sorted by law id and each holding the contract's keys. Exit status:
  - 0 iff every decided submission was accepted, and 0 for an empty inbox;
  - 1 otherwise;
  - 2 on a usage error: a budget outside `0 < S <= bend.budget_s_per_file`, checked before anything is read; an unknown milestone; a missing `--inbox`; or a `--law` naming a submission that is not there.
- `--list` prints `{"eligible": {M: [ids]}}`.
- The CLI writes nothing under the repository. The deterministic-and-writes-nothing test snapshots `laws`, `gen`, `results`, `spec`, `proofs`, `build`, `config`, `docs`, `holon` and `tests_m3`.

### `holon run` (`holon/mpipeline.py`)

The generators and the refuter run first. Then every law they leave UNKNOWN that has an entry in `<root>/proofs/inbox/<law_id>` is decided by `holon.intake.decide_in_run`, through `intake_decision`:
- The run's own outcome stands in for the record: status UNKNOWN, and the run's statement hash.
- The files the run has just written are the regeneration, so G1 inside the run finds nothing changed.
- The kernels see a fresh directory holding the run's model of the law, its core library and the statement.
- The budget is the configured one.

**Accepted.**
- The generators' leftovers in the law's layout dirs are removed.
- The statement is written to `gen/<M>/laws/<id>/LAWS.bend`, and the inbox bytes to `gen/<M>/proofs/<id>/PROOF.bend`.
- The record follows the PROVED path:
  - `artifacts`, `checker` from the intake's `bend2` run, `kernel.verdict` from its `bendtt` result (no second `--verdict` run and no `verdict` attempt), and `kernels` and `independence_class` from `holon.records`;
  - `bound: null`;
  - `non_vacuity` from `holon.inhabit`;
  - `prover: agent:<session>`;
  - the generators' attempts, with `{"kind": "intake", ...}` last.

**Refused.** The record stays as the generators left it, plus that attempt, which also carries `detail`.

A SORT-width law with a submission gets the refused attempt, because there is no law file to check against.

## Surprises

1. **The base holds 4 UNKNOWN M2 laws, not 2. Two of them can never take an agent proof, and a preregistered helper crashed on them.**
   - I20 merged two SORT-width laws, `L_sort_width_batchheadercodecv0_144_1abeb29c` and `_166_8ad80b42`. `holon.sorts.width` decides them over the extracted model, which has no Reach predicate, and both are UNKNOWN.
   - The contract makes them eligible, because eligibility is the record's status, and `--list` names them.
   - Their records name no model: `artifacts` has no `"model"` key. So `tests_m3/test_intake.py::real_wrong_proof` raised `KeyError: 'model'` in three TestRealM2 tests (P5 real half, P8, and the stale-hash R3) before the intake was even called. No implementation could have passed them.
   - **Amendment** `6313204`, line in `spec/M3/amendments.jsonl` (`foundation_conflict`). For a record without `artifacts.model`, the helper's proof imports the model holon would name after the law's facts document. No assertion changed. `holon audit prereg --milestone M3` reports it as amended.
   - **The decision for these laws is a refusal only because there is nothing to check.** The intake regenerates no law file for a law that `holon run` writes no Bend file for, so bend2 fails on the missing import, and the closed REASONS vocabulary makes that `kernel_rejected`. The `detail` says why. A proof of a width law could become acceptable only once the extracted model has a Reach predicate and the width statement an emission.
2. **Every record gaining `prover` moves the I6 records pin** (`tests_m2/test_target_agnostic.py::norm_record`). Amended as for I9, I14, I16 and I19: a record whose prover is `"generator"` is compared without the key, and an agent prover is kept. `RECORDS_PIN` is unchanged. The line is in `spec/M2/amendments.jsonl` under I6.
3. **`bound: null` on an agent-PROVED record, but no `bound` key on a generator-PROVED one.** The contract asks for `bound` null, and `test_the_accepted_proof_is_labelled_in_its_record` reads `r["bound"]`. A generator-PROVED 0.3 record with an unbounded statement has no `bound` key. The two compare equal under `.get`, but not as JSON.
4. **G1's regeneration costs about 35 s on an idle machine and up to about 90 s under the parallel builders' load. The prereg's slack argument expected seconds.** Almost all of the time is the core library's case-choice search (`holon.gen.core.solve`). Its cache lives in the build directory, and the contract requires a fresh one. P7's wall time was 102.5 s against the test's 130 s limit in the evidence run, so the margin under load is thin.
5. **`results/M1/metrics.json` was already stale at the base** in its gate-derived `canary_acceptance` (total 21 against the committed M1 gate report's 24). `holon metrics` rewrites it, but G1 never compares that section. It was not touched.
6. **The order of the last two reasons needed a reading.** `REASONS` puts `kernel_rejected` (10) before `over_budget` (11), yet `bend2`, the first kernel, is the one with the budget. The reading taken:
   - `kernel_rejected` means a kernel finished and refused.
   - A `bend2` timeout is `over_budget`, and no later kernel runs, so `bendtt` stays `not_run`, as P7's test requires.

   With this reading the two reasons never compete.

## Questions for the human

1. **Should a law with no Bend statement be eligible at all?** These are the SORT-width laws, plus any statement the emitter or the IR rules reject. Today the contract lists them in `--list`, but any proof is refused `kernel_rejected` without a law file to check against. Possible alternatives:
   - exclude them from eligibility;
   - give them a reason of their own.

   Either would change the preregistered vocabulary.
2. **Please review the `real_wrong_proof` amendment** in `spec/M3/amendments.jsonl` (line 1). It was needed to run three preregistered tests at all. Revert it if the intended reading is that those tests fail at this base.
3. **Imports in an agent proof are not restricted to the model, the law and the core.** The kernel directory holds only the regenerated files. A relative import that climbs out of it reaches the file system, and Bend still checks whatever it imports: the I41 reviewer's probe showed it refuses unsafe or foreign code reached through an import, and an imported law must be proved too. Should the intake add a whitelist of import paths? That would need a new reason or an amendment of `missing_expected_law`.
