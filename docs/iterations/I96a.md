## What the build changed (`c1f63433`)

- **The step.** `python -m holon disch-r0 --milestone <M> [--check]` lives in `holon/disch/r0.py` and is
  dispatched from `holon/__main__.py`.
  - **Input.** It reads the DISCH sidecar's documents and, for each, the deployment record
    `gen/<M>/binding/<stem>.json` that `holon binding` writes.
  - **Output.** It writes the sidecar's `r0` and `model_sidecar`, and nothing else.
  - **`--check`.** Exits 0 when the sidecar's bytes are what a run writes, and 1 otherwise.
  - **The rule (ruling 3; the contract's R).** Paths come through the document's layout:
    - a scalar path holds its exact deployed word;
    - a non-zero address-typed word is `T`;
    - a mapping family holds `{0}` plus its written keys' words (per member path for a struct family). Its keys
      come from the record's 64-byte keccak256 preimages;
    - every other path is unlisted;
    - `proxy_slots` are the written slots that no layout path holds;
    - `derived_from` pins the record's sha256.
  - **Refusals.** The step refuses what it does not read: array families, nested mappings, and dynamic keys. It
    never guesses.
  - **Target-agnostic.** It names no target (B1).
- **`model_sidecar` (ruling 1).** The step writes the milestone's typing sidecar, `spec/M3/lib/sort_types.json`,
  explicitly. `holon/analysis/closure.py` is unchanged and has no default. `expected` is never written.
- **The lead takes the step.** `spec/M3/lib/disch.json`'s r0 is now derived.
- **Landing.** `holon/land.py`'s REGEN runs `disch-r0` and then `disch` after `binding`, so every landing re-derives
  r0 and the closure on the merged tree.
  - `disch` was added because `merge --key` reverts `gen/M*/disch/` like the binding record, and `derive` refuses a
    stale closure.
  - The sidecar lives outside `gen/M*/`, where `land check` does not look. So CI gains a `tests-m3-disch-r0` job,
    which runs `tests_m3.test_r0_i96a.TestBuild`, including the step's `--check`.
- **The I96 brief.** `spec/M3/lib/blind_session_i96.md` is I95's brief with one change. The session no longer writes
  r0 or model_sidecar; it runs `python -m holon disch-r0 --milestone M3` after `python -m holon binding --milestone
  M3`. I96b adds typing to it.
