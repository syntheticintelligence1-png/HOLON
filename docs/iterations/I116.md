## What was built

The rules themselves are unchanged. Each stage gets one opt-in, read from that stage's own sidecar, so every consumer
of the stage reads the same fallback. The composed driver opts in from the protocol's `document_fallback`. Without
the opt-in, every output is as before, byte for byte (P6; Morph's sidecars name none).

### (D) DISCH: `holon.analysis.closure` (sidecar key `document_fallback "unknown"`)

`Sidecar.analyses` is what `holon disch`, derive's rule DISCH (`holon.rules.disch._fresh`) and `holon run`'s DISCH
runner (`holon.disch.run`) all read. Under the key, it analyses each document on its own. A document whose analysis
(D1-D10) raises `ClassError` (class `class_error`), or a `KeyError`, `TypeError` or `IndexError` (class `malformed`;
before, the refusal "malformed"), falls back:
- It has no analysis, no class, no closure, no basis element and no DISCH law: its DISCH laws are UNKNOWN.
- It is a recorded miss in `gen/<M>/disch/fallback.json` `{document, sha256, model, class, error}`.
  `closure.json` and `conjuncts.json` list the analysed documents only.
- `fallback.json` is written only under the key. `holon disch --check` and derive's freshness check compare it like
  the other two files, and derive lists it as an input.

Any other value of the key is refused (exit 2). Milestone-wide input errors still refuse the milestone:
- the sidecar or a pinned input;
- a document missing, not JSON or not a transitions document;
- two documents naming one model;
- r0 naming a path no document declares.

### (E) Evidence and derive: `holon.diagram.evidence` (adoption-sidecar key `document_fallback "unknown"`)

`build` (and `build_milestone`, which `holon evidence` and derive's `_committed_par_inputs` both call) reads the key
from `spec/<M>/lib/derive_extracted.json`. Under it, an adopted transitions document whose E2 atoms raise for a
construct the rule over transitions documents does not map (`holon.diagram.transitions.TransitionsError`) falls back:
- It keeps its model and anchors (`transitions_anchors`, unchanged) and gets no atom (class `e2_unmapped`). This is
  exactly the model a build without committed diagrams gives an adopted document.
- The miss is recorded under the evidence document's `fallback` `{document, sha256, model, class, error}`. The key
  is written only when a document falls back, so a set with none is byte-identical in body.
- Derive rebuilds the set from the same sidecar, so the derive refusal "the evidence set cannot be rebuilt" for that
  document falls back with it.

Every other evidence error still refuses: a component's construct, the anchors, stale or missing inputs, two documents
sharing a model name.

### The composed driver: `holon.eval.holon_run`

- `_rules` writes `document_fallback` into the DISCH sidecar it generates when the protocol names
  `document_fallback.disch`.
- `adopt_fallback` writes it into the adoption sidecar when the protocol names `document_fallback.evidence`, but only
  when the installed `spec/<M>/lib/derive_extracted.json` is byte for byte the one `holon roles` generated for the
  entry (`sidecars/roles/`). It never touches a hand sidecar.
- Each composed row carries `fallbacks {disch, evidence}: {documents, classes}`, as counts and classes only. DISCH and
  evidence run before any decision (Q72).
- `derive_args` is factored out unchanged: the same argv as before.

## What a fallen-back document contributes, and what other documents may assume

The key's thresholds `disch_fallback` and `evidence_fallback` define this before any build commit:
- **(D)** The document contributes nothing to DISCH: no law, no section and no search seed. Its typed model, its laws
  of every other family and its evidence are unchanged. Other documents may assume nothing about it. Each document's
  DISCH analysis reads only its own document and the sidecar's r0, and an external call is an A-env unknown.
- **(E)** The document contributes its anchors and no atom. Other documents may assume nothing about it. E2 pairs are
  pairs of one document's own actions, so every other model's anchors and atoms are byte-identical (P4).

## Soundness

A fallback only removes constraints, never adds them.
- **(D) removes claims.** Every DISCH claim over the fallen-back document is removed, and none is added. No other
  document's analysis reads it, so no other DISCH law, section or verdict changes. P2's cross-document shape checks
  this: Counter's laws are byte-identical and its records equal Counter alone. A law over the fallen-back document is
  never derived, so it is never PROVED. P2's constrained shape checks this: the control TwiceKept decides DISCH laws
  that Twice leaves underived, and no record over Twice is PROVED where the same law over the control is not.
- **(E) removes atoms only, and atoms are triage.** No statement, premise, proof or verdict reads an atom of a
  transitions model:
  - PAR's components take only the atoms of their own component model (`_par_part`, `par_lossy`), and a transitions
    model is never a PAR component.
  - Records read atoms only for `evidence_levels` and `evidence_triage`.
  - So every verdict over the fallen-back document is the checker's verdict on the same law and model, and a law over
    it carries the evidence levels [] (P4).
- **Milestone-wide errors** stay refusals (P5), so a fallback never hides an input that is wrong for every document.
- **Every REFUTED still needs its replay.** Route A's replay and filter are unchanged, and a REFUTED on deployed code
  or on corpus code outside Q56 (4)'s exemption is handled under Q56.

## Surprises

1. **The fallbacks fire on the spent targets, but the next walls stand right behind them.** On Aave V3 these are:
   - the composed coverage stage, which walks every extraction sidecar and refuses over one document's term size,
     although types already set that document aside;
   - `holon bind`, which exits 1;
   - the typed runner, which exits 1.

   On EigenLayer, nothing is derived from 17 typed documents.
2. **Evidence's adoption sidecar is the stage's only sidecar, and the sorts pass does not read it.** So the opt-in
   moves no typed output.
3. **The planted Listed** was first typed-opaque, because a dynamic array is outside the typed model, which made its
   shapes vacuous. It is amended to a static array before any run.
4. **The prereg was refused once** for a workflow edit in the same commit. It was undone locally and recommitted (see
   the prereg sequence).
5. **`spec/schemas/evidence.schema.json`** has `additionalProperties: false` and no `fallback` key. An evidence set
   with a fallen-back document would fail GEVID's schema check. GEVID never runs on the composed scratch milestone,
   and no Morph set has the key, so the schema is unchanged here.
