## Surprises

1. **A defect in my replay harness. It was recorded at the gate and noticed after the run.** holon/mutate is frozen
   from the first record, so it is unfixed.
   - **The defect.** `holon/mutate/replay.py` `_Eval.value` returns Python `None` both for "this call has not run
     yet" and for a role whose value is none. The instrument (replay.semantics) says dec_go is None when validate()
     errs, so none is dec_go's value. When a mutated encoder writes a header that dec_go rejects, the claim
     `dec_go(enc_sol(h)) == some(view(h))` therefore raises "the claim's evaluation did not finish" instead of
     evaluating to false. The whole batch of hits then records `replay: null`.
   - **Why the frozen rules keep the status.** kill_criterion.errors keeps the law REFUTED, because the run decided
     it by a Bend-checked counter-law. The contract's `law_how` then reads the empty replay as "no hit replays",
     which makes the law a replay disagreement.
   - **Affected entries.** Six:
     - control C3: L_rt_go_v1 and L_rt_go_v2, written by the gate before the run;
     - A001: L_rt_go_v0, L_rt_go_v1 and L_rt_go_v2;
     - A058: L_rt_go_v1.
     
     Both catalog mutants are killed anyway, by L_par_hdr_v0/v1 and by L_par_hdr_v1. A related effect: after a failed
     replay, `fits_entry` sees no calls and returns true, so these entries' witness_fits_entry is true. No equivalent
     mutant is involved, so nothing reads it.
   - **Evidence.** A diagnostic re-evaluation, never committed, read dec_go's none as a value. In each of A001's and
     A058's four entries, all 16 hits then replay on the mutant and none on the original. The first local hit equals
     the recorded witness, and the counter-laws check. So all four would be K1.
   - **What it costs.** No catalog outcome and no rate changes. The miss of P17 is due to it, and so is part of the
     misses of P2, P4 and P6. It alone flags A001 as an extraction defect.
   - **Why I missed it.** On the original code dec_go never returns none at the candidates, so the gate's model and
     null checks never exercised it. The gate's controls check did exercise it, in C3, but that check reads only the
     expected laws and so passed. I did not read C3's other entries before starting the run.
2. **Seven error outcomes, predicted none.** Every one is the two M2 width laws
   L_sort_width_batchheadercodecv0_144/166, scoped as the instrument says.
   - **I20 (A076, A098, A100, A101, A104).** A SORT-width law reads its widths from the unit's own i20_step run (the
     contract's step 3). On these mutants the mutated Rollup reverts at the I20 harness's first step: A076 with
     "batch header length too small", and the four loader offsets with "zero data hash", "invalid versioned hash"
     and "zero state root". The frozen I20 harness then fails the whole chunk, so the widths do not exist. The trace
     replays of L_sort_site_rollup_363 and _636 fail on the same five mutants (10 entries), so the masked-obstruction
     test could not run for them.
   - **Ledger (A116, A120).** The mutated widths give derived facts with no ledger bundle. `holon run` then refuses
     them, with "no registered base bundle ('spec/M2/facts/morph_header.extracted.json')", rather than reuse the
     reviewed assumptions. The same refusal hit A027 and A031, which are killed anyway.
   - **Effect on the rates.** Errors are not kills, so the headline rate is the same as if they had survived. The
     non-error variant is 0.555.
3. **Nine records cannot be reproduced byte for byte** (independent review, M1), which breaks AGENTS.md rule 7.
   - **What leaks.** run.py passes raw tool output into step errors at :761 and :980. The channel errors are cleaned
     (channels.py error_text); these are not. So the step errors carry forge timings ("finished in 1.43ms …") in A076,
     A098, A100, A101 and A104, and runner scratch paths (`/home/runner/work/_temp/work/<id>/…`) in A027, A031, A116
     and A120.
   - **The carry mode changes the error set.** decide_m2 runs every non-carried M2 law in one `holon run` call, and
     marks them all error when that call fails. So a ledger refusal under `--no-carry` would make more laws error
     than it did here, where only the two width laws were in the call.
   - **Not caught by the determinism test.** Its preregistered sample has none of these nine records.
   - **Fixing it.** Records are generated files, so the fix belongs in the generator: clean step errors as channel
     errors are cleaned, and isolate a failing M2 law. That means a new run.
4. **Channel failures are never retried** (review, M3). The instrument says a failing step is retried once, but the
   channel functions catch every exception and return an incomplete run, so `_retry` never fires. The five I20
   failures look deterministic (each reverts at gas 2968), so I see no effect here.
5. **Trace-law replay is constant for M1x.** The contract makes a law without a site hold on every trace, so every
   M1x replay entry is false on both trees. M1x masked obstructions therefore cannot be measured by this harness.
6. **The panel judged 17 mutants equivalent**, including A018 and B002-B006. The predictions filed A018 as
   proof_lost_unwitnessed (P4) and stratum B as rule_gap or extraction_gap (P16), without an equivalent class. A
   survivor's class lists equivalent first, so those predictions miss.
7. **Speed.** Each planted control took about a minute, and the 242 mutants took 46 minutes on 24 GitHub runners.
8. **Problems found and fixed during the build, before P:**
   - `GOPROXY=off` broke Go extraction and the I16 channel, so it was dropped.
   - The harness raised on site-less M1x laws; the contract makes such a law hold on every trace.
   - The baseline record's "baseline" field read "absent"; it is now the baseline's own status.
   - Staging needed absolute paths.
   - The gate's model check had a second implementation; it now calls `replay.model_check`.
