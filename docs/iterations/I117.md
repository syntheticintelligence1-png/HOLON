## What was built

### (1) Go integer semantics: `holon.gen.goint`

Every definition quotes its rule from The Go Programming Language Specification (the module docstring). A value of an
integer type T of n bits is the 64-bit two's complement of its mathematical value, sign-extended for signed T and
zero-extended for unsigned T (Bend's `Word(64n)`, LSB first; Base has no 64-bit type and its `Nat` is unary). `fit(v, T)`
truncates to n bits and reads them in T's signedness.

| op | definition (spec section) |
|---|---|
| `+ - *` | the 64-bit result fit to T ("Integer overflow": modulo 2**n; n divides 64, so the low bits agree) |
| `/ %` | truncated division: \|a\| / \|b\| unsigned, negated when the signs differ; the remainder takes the dividend's sign; MinInt / -1 = MinInt, MinInt % -1 = 0; a zero divisor panics ("Integer operators") |
| `<< >>` | the left operand's type; arithmetic for signed, logical for unsigned; no upper limit (a count of 64 or more saturates); a negative signed count panics ("Arithmetic operators") |
| unary `- ^` | 0 - x and all bits flipped, fit to T |
| `& \| ^ &^` | bitwise on the representation, fit to T |
| conversions | sign or zero extension, then truncation ("Conversions") |
| comparisons | signed order for signed T, unsigned order for unsigned T ("Comparison operators") |

int, uint and uintptr are 64 bits (the pinned linux/amd64 toolchain). Any operand not of an integer type (float,
complex, string, a named type whose underlying type the document does not give) has no definition (`Undefined`).

The model's definitions (`goint.PRELUDE`, Bend) are total and structural: 64-step restoring division over a state
record, shifts by repeated single shifts under a saturation test, signed order by the sign bits then the unsigned
order. They are generated text, never trusted: Bend evaluates them when it checks a counter-law.

### (2) The frontend's opt-in `ops "typed"`

Config key `ops "typed"` (config holon-go-frontend/0.3; any other value refused), passed by the composed driver from
protocol `go.ops "typed"` and never to the Go machine frontend. Under it:
- every path-enumerated function, codec-shaped or not, emits its paths and a `typed` section: each typed term's Go
  type (a term met with two types is recorded null), each parameter's array length, and `stale`;
- the reasoner's linear forms read an op or unop term as one variable, never as an exact linear combination (Go
  integers wrap), so no branch is pruned by unbounded arithmetic;
- a path that loads a term after a store through memory the enumerator does not model, or after a call other than
  len or cap, marks the function `stale`.

### (3) The straight-line class: `holon.gen.gostraight`

For an op whose Go-op entry has the typed section and no loop body (goloop's loop class is unchanged and tried first).
- **bytes:** a byte-array parameter of known length n; cell k is byte k; cell map (1, 0, n), the same carrier value as
  a loop op reading every byte.
- **fields (Q91 (1)):** any other parameter; the leaves are the field paths the component's ops read (integer and bool
  fields, a field compared with nil, a field's len), each two U32 cells at its place in the component's sorted
  leaves, so every op of the component reads one carrier value. A nil receiver is not a value of the model
  (declared: `A-goloop-fields`).
- A path is the conjunction of its atoms, each evaluated in Go's semantics; its outcome is its end (OPanic, OErr,
  ORet).
- **Unsupported** (the op undefined, its laws unbound and UNKNOWN): a term outside the class or of no or two recorded
  types; a division by a non-constant or a shift by a signed non-constant count, whose panic the frontend's paths do
  not record; a stale field op; a continue path; paths that do not partition the sample points.
- Candidates: per op, the first sample point at which it is OPanic, then OErr, then ORet (0, 1, 2, the type's
  extremes, every constant of the op and its neighbours). A law is REFUTED only by a counter-law Bend accepts at a
  candidate; there is no proof route (UNKNOWN otherwise, gap G6).
- The model of a document with no straight-line op is byte-identical to before (`TestRegressions`).

### (4) Q91 (3): the mpipeline binding check before the emitter

Under `--unbound unknown`, `holon.mpipeline` checks the binding on the statement's IR roots before the emitter. A law
that cannot be bound is UNKNOWN with exactly one attempt (kind `binding`), no law or proof file, and no agent intake.
The check on the decided text, after the decision, stays as a second guard. Without the option nothing is computed.

## Soundness

- **Each definition is the specification's rule,** quoted in the module, and is compared with the pinned toolchain on
  every edge case, through both the Python reference and the compiled model; a sample is re-checked by Bend's kernel.
- **An undefined op can never make a law PROVED.** Its model definitions are not generated, so a statement naming it
  has no binding: I115's check makes the law UNKNOWN before anything is attempted, on every path (Q91 (3) closes the
  mpipeline one). The class has no proof route at all, so it cannot make anything PROVED either.
- **A REFUTED needs a counter-law Bend accepts at a concrete witness;** the planted tests replay every such witness as
  real Go and match the outcomes.
- **Nothing the frontend cannot see is given a meaning.** A term with no recorded type, or one that could panic where
  the paths do not say, is never modelled. The reasoner change and the stale flag only keep paths or refuse ops; they
  never drop a reachable branch.
- **Declared abstractions:** a nil receiver and unread fields are not modelled (`A-goloop-fields`); the 64-bit widths
  (`A-goint`). Leaving out a nil receiver can only lose refutations: every witness is a non-nil value.
