## Done

- **`holon/sorts/`** (pure Python, standard library and `holon` imports only, no Morph identifier in any module):
  - `grammar.py`: the §7.1 grammar as text (`parse`, `render`; unions render their members sorted), the §7.2 table as `affine(op, a, b)`, the R1 realization (`unsigned`), base families (what flow unifies), torsor pairs and roles, and the writer-label function of R4. The keys of holon-facts/0.1 documents are documented here: one `<Record>.<field>` per record field, typed `Mach(8·width)`.
  - `flow.py`: one walk over definitions, actions, migrations and observers. It emits flow, affine, compare, call, write and subtraction events, the register-read graph of R3 and the syntactic writer sets. Definitions are monomorphic (parameters are keys `<def>.<param>`, results `$<def>()`); records are abstracted by type (`<T>.<g>`); literals carry no sort. Ghosts are not read: a ghost state field, a ghost record field or a ghost definition yields no variable and nothing flows into or out of it. Unknown facts sections, action or guard keys, operators and functions stop the pass.
  - `constraints.py`: type constraints (Bool binders; `Mach(w)` for 0.1 fields), one seed per variable listing every ground (the sidecar's lexical rules, plus the structural ground `disch.delay` → Dur), and one constraint per flow, affine node and comparison (membership builtins compare an element with a list's elements). Each constraint carries everything `satisfiable` reads.
  - `solve.py`: `satisfiable(constraints)`. A union-find unifies base families (flow, compare, link). Seeds and types fix families. Affine constraints link classes into components. A component lives in one torsor pair (Time/Dur or Idx[k]/Cnt[k]) or one closed sort, named by its fixed classes. Inside a pair, each class is a point or a group element, decided exactly by arc consistency and backtracking. So the oracle is exact and monotone. `System.family` returns what every solution agrees on, and `difference_sorts` gives site sorts.
  - `core.py`: `minimal_core` by QuickXplain over positions (unhashable items work), followed by a deletion pass that re-checks irreducibility. A satisfiable input raises `ValueError`.
  - `unions.py`: members of the union-capable families (digest kinds, roles) travel along flow constraints, in the direction of flow, from seeds. Labels come from writer sets, merged over strongly connected components of the register-read graph (R3). Union entries group variables that carry the same union.
  - `assign.py`: the pass. Conflicts are found by repeated minimal cores; each conflict sets aside its first affine or compare constraint (else its last flow). Then come the frozen assignment, the sites, the unions and the unresolved variables. `sorts_sha256` is the sha256 of the canonical JSON of `assignment.json` without `sorts_sha256` and `inputs`.

## Surprises

- **A second signed site: `btot - bn` is SIdx[queue] with a sign obligation** (Idx − Cnt, §7.2).
  - It sits in `finalizeBatch`'s guard `bn == 0 || qpend == btot - bn`. The facts give that guard the span of the message queue's pop check (`L1MessageQueueWithGasPriceOracle.sol:325`).
  - In the pinned source the subtraction itself is `Rollup.sol:742`, `startIndex = totalL1MessagePopped - l1MessagePopped`, inside an `unchecked` block, so it wraps rather than panics.
  - No guard of the action implies `btot >= bn`, so the site keeps the guard's span. The invariant "tot is the previous tot plus n" should discharge it in I15.
  - It was not predicted; it is reported, not tuned.
- **The union holds eight keys, not two.**
  - `Entry.hb` (the header's blob field) receives the same value as `Entry.bvh`, so it carries the union too. So do the lets that hold the value on its way (`bvh` in the three commit actions, `commitBatchWithProof.stored`) and the definition parameter `bvh_at.s_bvh`.
  - P4's two registers are in it, as predicted.
- **`qlen` gets the fallback label `wcf8ad7dc`.** Its writer set `{sendMessage}` matches no sidecar rule. **`Entry.n` is `Cnt[queue]_inc`**: it is written by the commit actions, and the affine table forces the input `n` to be a count, since `tot + n` is written to an index.
- **Every batch-index site is `Nat (unrefined)`**, `:636` included. The sidecar seeds no batch-index family: `lastFinalizedBatchIndex` and `batchChallenged` do not match `QueueIndex`. So the whole index component (`lfi`, `bc`, `rri`, the `idx` and `parent` inputs, `lci`) stays unseeded and nothing is guessed. See Questions: I15 predicts `:636` PROVED by `coercion_guard` as a signed site.
- **Both readings of R3's "reads" give the same strongly connected components.** One reading counts every register occurring in the written expression (conditions and index terms included); the other counts value flow only. Under both, the only multi-register component is `{Entry.bvh, s_bvh}`, which is a digest and carries no label. The implementation uses the literal reading; P3 does not depend on the choice.
- **The structural seed is redundant.** `wait.dt` is forced to Dur by the affine rule on `t := t + dt` once `t` is a Time.
- **The honesty suite runs in about a second.** `copy_repo` plus four `holon diagram` and four `holon sorts` runs are fast: the pass takes about 0.1 s on the three documents.

## Questions for the human

1. **Time − Dur and Amt − Amt.** §7.2 has no Time − Dur row, and the grammar has neither a signed Time nor a signed amount.
   - I13 returns Time for Time − Dur (the torsor action) and Amt[a] for Amt[a] − Amt[a], with no sign obligation. That is weaker than the pinned Idx − Cnt = SIdx row.
   - No site of the M1 facts is affected.
   - Should the grammar gain STime/SAmt? Or should the table call these ill-sorted?
2. **The label branch of R5.** Under R2, values carry base sorts and never labels, so a register has exactly one label, a function of its writer set or its component (R3). Then "Idx[k] with distinct labels" unions cannot arise.
   - If R5 meant that values carry the label of the register they were read from, `qpend` would be `Idx[queue]_fin + Idx[queue]_inc`, since `finalizeBatch` writes `qpend := btot`, a value of `Entry.tot`. P3 would then fail.
   - I13 implements the first reading (labels do not travel), which is what R2 and R3's "a one-way copy (b := a) does not merge labels" say. Please confirm.
3. **I15 and the `:636` site.** BUILD_PLAN I15 predicts that the `idx−1` site (`:636`) is PROVED by `coercion_guard`, as a signed-to-unsigned site. Under the frozen I13 assignment it is `Nat (unrefined)`, because the frozen sidecar seeds no batch-index family.
   - Should I15 generate obligations for unrefined subtraction sites? Or should a later sidecar version (a new prereg) add a batch-index rule?
4. **holon-facts/0.1 keys.** The header's fields are typed `Mach(8·width)` from their declared widths, and the lexical rules are not applied to their `sol`/`go` texts (they are not `doc`s).
   - Applying them would make `Header.blobVersionedHash` `Dig[VH]`. That clashes with `Mach(256)` at the family level unless Mach is treated as a representation layer below the refined sorts.
   - Which reading is intended for E5 (I14)?
5. **Definitions are monomorphic, and their subtraction sites are reported per definition** (span `<model>:<def>` or the def's src). The contract allows either; per-call reporting would multiply the `w`, `lci` and `bvh_at` sites by their call sites. Is per definition right for I15's SORT-site laws?
6. **Ghost detection is by facts markings only** (`ghost_state`, `types.<T>.ghost`, `"ghost": true` on a definition). The `tag` lets of `commitBatch` and `commitBatchWithProof` carry no marking, so they are ordinary lets. They hold literals and are assigned `Nat (unrefined)`, so they read nothing hand-written. A ghost tag computed from real values would need a marking on the let.
7. **`disch.delay` as a structural ground.** It is facts structure (the DISCH cost model), not one of the listed hand hints, and it is redundant on the M1 facts. Is it acceptable as a seed ground?

## Lead's notes on the audit

An independent audit of `56a6f1d` found no violation, no test gaming and no false claim: every prediction, honesty mutation and gate line reproduces. It raised three minor points. They are recorded here and change no output.

1. **R5 is inconsistent with R2 in the contract the lead wrote.** R5 lists "Idx[k] with distinct labels" as a union case, which presumes that values carry labels. R2 and R3 make a label a property of the written register (a function of its writer set), never of the value.
   - The implementation follows R2 and R3, so R5's label branch can never fire.
   - Under the other reading, `qpend := (bn == 0 ? qpend : btot)` would make `qpend` the union `Idx[queue]_fin + Idx[queue]_inc`, and I13-P3 would be a miss.
   - The lead resolves the contradiction in favour of R2 and R3, the rules that define labels. P3 is reported as passing under that reading. The human should confirm it; if R5's branch was meant, P3 must be re-scored as a miss, not re-tuned.
2. **A structural seed outside the sidecar.** The `disch.delay` field of the facts schema (a DISCH profile's delay) seeds Dur. It is facts-schema semantics, not target vocabulary, and a probe shows it is redundant: removing it changes no sort. It is accepted as a generic structural ground. A future sidecar version may move it.
3. **Affine rows beyond the §7.2 table:**
   - Time − Dur = Time, with no sign obligation. By contrast, Idx − Cnt = SIdx.
   - Amt ± Amt and Mach ± Mach.

   No M1 site uses them. The human should decide whether Time − Dur should be signed (an STime) with a sign obligation when realized in Nat, as Idx − Cnt is.
