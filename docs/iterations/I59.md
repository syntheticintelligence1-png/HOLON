## Done

### `holon/historical/` (pure Python, plus the existing models and two Go harnesses)

- **`net.py`.** HTTP with one pacer per host (the interval grows on a rate limit and shrinks on success), bounded retries with exponential backoff, JSON-RPC single and batch calls. Every output names a source by its host only. Error text is scrubbed of the values of `ETH_RPC_URL` and `ETHERSCAN_API_KEY` and of every long segment of `ETH_RPC_URL`.
- **`store.py`.** The content-addressed snapshot outside the repo (default `~/.holon/historical`, env `HOLON_HISTORICAL_DIR`, flag `--snapshot`; a path inside the repo is refused):
  - `objects/<aa>/<sha256>` holds the raw bytes of logs, transactions and receipts;
  - `objects/<aa>/<sha256>.gz` holds a blob's 131072 raw bytes, gzip-compressed on disk (Morph blobs are largely zero padding). The name is the sha256 of the raw bytes, and every read re-hashes;
  - `state.sqlite` records the log pages done, and each item's sha256, source host and status.

  A log, transaction or receipt is stored as the canonical JSON of a fixed set of fields with lowercase hex, so its bytes are a function of the chain, not of the provider. Checked: the 43 logs of the last page hash identically from `ethereum-rpc.publicnode.com` and `gateway.tenderly.co`.
- **`fetch.py`.** `python -m holon historical fetch [--milestone M2] [--from N] [--to M] [--index PATH] [--snapshot DIR] [--workers N] [--blob-workers N] [--batch N] [--offline]`.
  - Phase 0: the window end's hash. For the sidecar's `to_block` it must equal the frozen `to_block_hash`, or nothing runs.
  - Phase 1: `eth_getLogs` over the proxy and the sidecar's five topics, in pages of at most 1972 blocks aligned at the window start (a page refused as too large is split).
  - Phase 2: `eth_getTransactionByHash` for every transaction a log belongs to, in JSON-RPC batches, with the first source rotating per batch.
  - Phase 3 (concurrent with phase 4): every blob of every commit transaction. Inside the beacon retention window it comes from `/eth/v1/beacon/blob_sidecars/<slot>`, and the sidecar's commitment must hash to the versioned hash. Otherwise it comes from `api.blobscan.com /blobs/<versioned hash>/data`, one request per blob, paced at 0.15 s with a 60 s host pause on a refusal.
  - Phase 4: `eth_getTransactionReceipt`.
  - Phase 5: the index, canonical JSON (sorted keys, indent=1), items sorted by (block, tx, kind, log_index, sha256), `index_sha256` over the canonical (compact) document without it. Blob items also carry `versioned_hash`, `position`, `commitment` (beacon only) and `kept: false` when the disk was short (it never was).

  A source that refuses history with an explicit message ("Archive requests require a personal token") is not asked again at or below that block. A null result is retried on the next source. `--offline` writes the index from the state alone. Exit 2 means a log page could not be fetched (no index is written), 1 means a transaction or receipt is unavailable, 0 otherwise. A blob no source serves is `unavailable`, never faked.
- **`abi.py`.**
  - Decoding uses the pinned ABI only: the ABI JSON the pinned solc (sha256 checked against `config/holon.json`) emits for `IRollup.sol` at `3e44e79` of the pinned checkout. Decoding is strict: offsets and lengths in bounds, `uintN` in range, clean address, bool and `bytesN` words.
  - Naming uses every revision of `IRollup.sol` in that checkout's own git history (16 revisions, all compiled with the same solc), plus the elementary-typed external functions of `Rollup.sol`'s revisions. A historical selector names a function, so an older `commitBatch` is still a commit. It never makes a transaction "decoded".
- **`checks.py`.** `holon.historical.header_checks(header) -> dict` on the frozen M0 model (the `.mjs` engine, per `results/M2/native.json`'s recorded fallback):
  - `length` and `version`;
  - `keccak` (`holon.keccak`);
  - `ok_sol` and `ok_go`;
  - `roundtrip`: `enc_sol(dec(header))`, where `dec` is the model's `dec_go`, whose getters fill the Header (a getter the version skips fills zeros);
  - `diff_cells`;
  - `ssvh_zero`: the `dec_go` getter's cells for `sequencerSetVerifyHash`.
- **`replay.py`.** `python -m holon historical replay [--milestone M2] [--index PATH] [--out PATH] [--morph PATH] [--work DIR]` writes `replay.json` and `disagreements.json` as canonical JSON, deterministically (checked byte for byte across two runs).
  - Commits are found by selector, plus any transaction with a CommitBatch log whose selector names no other known function. `importGenesisBatch` transactions are listed under `genesis`: the contract's "(or genesis import)".
  - For each decoded successful commit, the parent is checked as follows:
    - the header checks;
    - linkage against the latest CommitBatch event with the header's batch index before the transaction;
    - the real Go decoders, run through the I16 harness and binding unchanged (`replay/M2/go/holon_codec_test.go`, `common/batch` `BatchHeaderBytes.validate` and getters, on a scratch copy of `/root/work/morph` at `3e44e79`).
  - For each blob:
    - its source;
    - `commitment_ok`: the KZG commitment that `kzg4844.BlobToCommitment` of the pinned checkout's go-ethereum computes from the blob's own bytes (`holon/historical/go/holon_kzg_test.go`) hashes to the transaction's versioned hash. A commitment served with the blob must equal it.
  - Reverts with the recommit block, and a summary of counts.
  - Supplementary fields, never read by the tests:
    - `legacy_parent`: the same checks on parents decoded with their historical signature;
    - `rebuild`: the encoder edge on real inputs. `enc_sol` is run on a Header built from a commit's own calldata and its parent, and compared with the header the chain hashed;
    - `blobs[i].kzg`.
  - `disagreements.json` holds the model against the real Go decoders (`dec_go`, `ok_go`) and against the chain's acceptance (`ok_sol`). Ids come from `holon.refinement.disagreement_id`, and classes from `holon.refinement.classify`, from links only. It holds no raw chain bytes (inputs by keccak, decoder outputs by sha256).

## Surprises

1. **The public RPC does not serve history.** `ethereum-rpc.publicnode.com` refuses `eth_getLogs` below its recent horizon with HTTP 403 ("Archive requests require a personal token"). It returns `null` receipts at old heights.
   - This contradicts `docs/HUMAN_ANSWERS.md` ("Transactions, receipts and logs at any height work without one").
   - It goes beyond the sidecar's `limits.observed`: the prereg probed only the most recent ~2000 blocks.
   - Transactions by hash do work at any height.
   - The full fetch used `ETH_RPC_URL=https://gateway.tenderly.co/public/mainnet` (public, no key). Other public endpoints probed: `eth.drpc.org` caps ranges at 10 000 blocks on its free plan; `cloudflare-eth.com` caps at 800 blocks; `rpc.mevblocker.io` rate-limits; most others want a key.
   - The sidecar itself was not edited.
2. **P4 missed.** Version 2 headers began at batch 54 332, under a legacy ABI. Every header the pinned ABI decodes is version 2. Offending items: all 1695 decoded commits (`replay.json`, `parent.version == 2`).
3. **P5 missed, as a consequence of P4.** A version-2 header stores keccak256 of all the transaction's blob versioned hashes, as the pinned `Rollup._computeBlobVersionedHash` does for version 2. It does not store the first hash.
   - All 1695 checked batches (60 477..62 171) differ.
   - Recomputing the version-2 rule explains every one of them, and every one of the 6145 legacy version-2 headers too: 7840 of 7840. Not one difference is unexplained.
   - The prediction encoded the version 0/1 rule.
4. **P6 passed in full, but only because of a third-party archive.**
   - 60 853 of the 62 192 blobs (97.8%) are older than the beacon's ~18-day retention and came from `api.blobscan.com`. The beacon alone would have served 2.2%, and P6 would have missed.
   - The archive is a single point of failure for re-fetching, though not for trust: every blob's KZG commitment is recomputed from its bytes and checked against the versioned hash the chain committed to.
5. **The blob archive throttles.** `api.blobscan.com` answered HTTP 503 to bursts, at times for minutes, and twice before my fetch had sent more than a handful of requests. Its `/healthcheck` returned 503 while `/blobs` worked.
   - One request per blob at about 6.5 requests/s held.
   - The blob phase is the long pole of the fetch (about 2.7 hours).
6. **Two genesis imports and no revert.**
   - `importGenesisBatch` ran twice: block 20 999 915 with batch hash `0x9032f3…` and block 21 007 528 with `0x77ee6c…`. An Upgraded event at 21 007 191 lies between them, so the first import was superseded.
   - Batch 1's parent links to the second import.
   - There is no RevertBatch event in the window, so P8's revert clause holds vacuously, and so does P1's "reverts and recommits included".
   - Eight ChallengeState events.
7. **L_dom_hdr on mainnet.** Batches 1..7574 include 2954 version-0 headers of 281 bytes: 249 bytes plus a 32-byte skipped-L1-message bitmap of the legacy codec.
   - The chain accepted every one as a parent, and so does the pinned Solidity `_loadBatchHeader`.
   - The pinned Go `BatchHeaderBytes.validate` rejects every one. That is the M0 refutation L_dom_hdr ("a version-0 header longer than 249 bytes, Solidity true / Go false") realized by real chain bytes.
   - The model's `ok_sol` and `ok_go` match the two real sides exactly, so this is agreement, not a disagreement.
   - These are legacy headers, outside the preregistered set.
8. **sequencerSetVerifyHash on the full history.** The legacy code wrote a nonzero value in every header from batch 1 to 60 476 and in the pinned set's first parent (60 477). It wrote zero only in the genesis header (batch 0) and from 60 478 on.
   - Over the preregistered set, P3 holds.
   - Over the full history, "nonzero is a prefix" fails only because of the genesis header.
9. **Pre-existing test failure.** `tests_m2/test_target_agnostic_exhaustive.py` fails at the base `b0b9975` on `holon/frontends/go/paths.py` (identifier `Sl`, from I18). This iteration does not touch it.
