## Done

- **Probe `bend/notes/p_core_import/`** (hand-written).
  - **(a)** A proof that imports `core/LAWS.bend` alone and uses an unproved law as a lemma is rejected: "an unfilled law is a dead claim: live code cannot use it". This happens under bend and `--verdict` alike. Prediction I8-P1 holds.
  - **(b)** Importing a `PROOF.bend` puts that file's proofs into the importer's checked closure:
    - a wrong helper in the imported proof file fails the importer (`b/user_bad`);
    - an imported core with an open law reports "1 TODO found" in the importer;
    - with a fully proved core, `C.c_ok(3n)` checks when both the core PROOF and the core LAWS are imported (`b/user`).
  - So the import rule is: generated proofs import `../core/PROOF.bend` together with `../core/LAWS.bend`, and call lemmas through the LAWS alias.
- **Core library (`holon/gen/core.py`).** Lemma statements are data (the `CATALOG`). Each names a proof class, and no proof is hand-written.
  - The classes are `absurd`, `nat1`, `nat2` and `bool1`. Each fixes a case skeleton: a match on the first one or two binders.
  - Every case body is chosen from the class's candidates: `{==}`, a hypothesis, ex falso on a hypothesis or on an inequality applied to `{==}`, or the induction hypothesis (an inequality is transported to the successors).
  - **Bend drives the search:** the case on the line Bend rejects advances to its next candidate.
  - The search proves all 9 lemmas: `core_false_ne_true`, `core_le_refl`, `core_is_eq_refl`, `core_le_zero`, `core_lt_add`, `core_lt_not_le`, `core_is_eq_false`, `core_and_left`, `core_and_right`. The choices are cached by catalog hash.
  - `emit(gen_dir, omit=None)` writes `<gen>/core/{LAWS,PROOF}.bend`, and `omit` is the canary. `paste_text` gives the same lemmas as plain defs, and `bare_laws_imports` is the G3 rule.
- **M2+ milestones** (every milestone other than M0 and M1, including the test milestones `T*`) emit the core into `<gen>/core/`, and every generated proof imports it (`mproofs.CORE_MODE`).
  - `holon run --core paste` pastes it instead; that is the cost baseline.
  - M0 and M1 are untouched: they keep their pasted `CORE` and emit no Reach.
- **Reach.** For M2+ milestones, `machine.py` emits `type Reach<-s: HSt> is Type` with constructors `R0{e: {s == s0()}}` and `RStep{a, p, r: Reach<p>, e: {s == step(a, p)}}`. The index is a parameter that carries its equation, which is the encoding Bend accepts for a value-indexed family.
  - The IR 0.3 binder type `Reach` is emitted as the state plus its evidence (`for +s: M.HSt`, `for r_s: M.Reach<s>`).
  - A witness is a trace from s0. Its evidence is the chain `R0`, `RStep`, …, with every equation by computation (`mlaws.reach_chain`, `binder_parts`).
- **`mproofs.ReachProof` (the class `reach_invariant`).**
  - **The proof.** It inducts on Reach through `*_reach(-s, r)`. Recursion on the evidence is structural, and `s` is erased, so the termination check passes.
  - **The invariant.** It is the claim's conjuncts plus the strengthening facts, one def per component.
  - **The step lemma.** One lemma per action, which matches action and state together (Bend's binder order), with one exec lemma per action generalised over the decision (`Rev`, `Ok`).
  - **With a strengthening**, each strengthened field is rewritten to its constant. Equations are `Type`, never `Data`, so each is consumed once: the goal and the target hypotheses are rewritten together through a function-typed motive, and the result is applied to the hypotheses.
  - **The search.** Every component of every branch is a slot whose candidates are the hypotheses and `{==}`. `mpipeline.reach_search` lets Bend pick the slots: first without a strengthening, then with houdini's proposals.
- **`holon/js/houdini.mjs`** (untrusted) proposes Nat and Bool fields that are constant on every explored reachable state. Proposals live only in the proof file, as a comment and defs. The law file is the frozen statement.
- **Explorer.** A Reach binder ranges over the reachable prefixes only, and is evaluated as a state.
- **G11V.** A law with a Reach binder counts as premised. Its inhabitant states the evidence: `exs s`, `exs r_s: Reach<s>`, at the witness `run([], s0)` with `R0{{==}}`. The witness is reachable by construction.

## Surprises

- **An action input named `d` broke the generated model.** The input was captured by `exec_*`'s decision binder. This is a latent generator bug that M1 never hit. It is fixed by fresh binder names, with M1 byte-identical.
- **Equality proofs are `Type`, not `Data`,** so a destructured equation cannot be used twice. The first strengthened proof rewrote the goal and transported the hypothesis with the same equation and was rejected ("consumed more than once"). The fix rewrites both through one function-typed motive.
- **A destructuring let cannot take a computed value**: "a match cannot scrutinize a computed value". Projections out of the invariant go through a def of their own.
- **Importing the core is cheaper than pasting it** (0.87×), although the prediction allowed it to be up to 20% dearer. Probe (b) shows the core is still re-checked in every importer's closure, so this is not because the check was skipped. We did not investigate why.
- **Bend accepts a value-indexed family `type Reach<-s: HSt>`** whose constructors carry index equations. The primer does not document this. It is recorded as a Bend fact for the human.
