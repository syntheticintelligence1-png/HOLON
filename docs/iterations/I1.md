## Surprises

1. **The plan conflicted with a frozen test.** BUILD_PLAN I1 said that building a record over facts the ledger does not know "fails loudly", including `--no-registry` runs. Frozen `tests/test_31_mutations.py` requires such runs over planted mutations to succeed. Resolution:
   - a run over facts derived from a registered file uses that file's bundle and is flagged `ledger_match: "derived"`;
   - the v2 schema rejects that flag, so it can never be committed;
   - it raises if any definition in the cone is not classified by that bundle;
   - facts with no registered base raise.

   The preregistered `test_unknown_facts_bundle_is_an_error` exercises `model_assumptions()`. The review found that, at first, the record path did not call it. The record path now goes through it, and `test_i1_review.py` covers `resolve_bundle` directly.
2. **One preregistered test caught my own rendering.** The test requires premises to contain no `{`, and my first rendering used `s \ {f}`. I changed the rendering, not the test.
3. **Instruments were written after the prereg.** The v2 record schema and the IR 0.2 schema were both written after the prereg commit. I1-P5, and the schema halves of I1-P3 and I1-P4, therefore cannot fail by construction, and they do not count toward prediction accuracy. BUILD_PLAN §0.1 now requires such instruments to be committed with the prereg.
4. **The cone parser is shared, not independent.** The "independent" cone in `tests_m2/_m2.py` and the one in `holon/records.py` use the same token-and-closure approach. Both over-approximate when a local name is spelled like a definition. I2 builds the cone from the generators' own definition index.
5. **Ledger wording overclaimed.** The ledger's no_assumption reasons first said that the fidelity of all transcribed definitions is "measured by replay". That is false for the M0 encoders, the decoders and `mig_eta2`, and it was corrected after the prereg. The ledger is a sidecar, so this is reported here, not amended.
6. **Two texts still repeat the false zero-blob claim.** `laws/M1/L_fact_Z.json` notes and `spec/M1/facts/morph_rollup.json` constants_doc still say "HypZ ... oracle-checked", and the facts cite Rollup.sol:24. Neither was edited: the facts hash is in every M1 statement, and I1-R2 keeps `laws/M1` untouched. The ledger text records the correction. The law notes are fixed with the statement lifecycle (I10).
7. **The review confirmed 25 findings.** An adversarial review (4 lenses, each finding checked by an independent skeptic) confirmed 25 of 32 candidate findings. All were fixed in I1 except the token-graph cone, which I2 replaces.
