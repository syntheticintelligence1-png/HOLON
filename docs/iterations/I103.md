## What changed

**D1. Toolchains.** Every selection rule is opt-in. A hand sidecar or config never reaches one, so Morph's
documents keep the toolchains they name today: solc 0.8.24 and go 1.24.7. Regression R2 checks this.
- **`config/toolchains.json`** (a new file) pins two sets:
  - `solc_set`: 42 releases, each with the sha256 from binaries.soliditylang.org: every final 0.8.x from 0.8.0 to
    0.8.38, plus the last release of 0.5, 0.6 and 0.7. 0.8.24's sha256 equals the `replay.solc_sha256` pin.
  - `go_set`: 1.24.7 (replay's toolchain) and 1.25.14 (the go.dev tarball's sha256).
  - `tools/install_toolchain_sets.sh` installs both and checks every sha256.
  - `config/holon.json`, `replay.*` and the 13 CI pins are byte-unchanged. PINS ALL PASS (13/13).
- **Solidity** (`holon/frontends/solidity/toolchains.py`). A sidecar with `compiler.version: "pragma"` compiles with
  the newest pinned release that satisfies every `pragma solidity` of the units solc reads. The pragma grammar is
  solc's: `^ ~ = < <= > >=`, partial versions and `||`.
  - Under that rule `evmVersion` is the release's own default.
  - The document records `extraction.toolchain.solc.selected_by` and `arithmetic`. The facts 0.3 schema admits both
    as optional fields.
  - If no pinned release satisfies the pragmas, the unit is Refused and the reason names the pragmas and the set.
- **Pre-0.8 arithmetic is never silently 0.8.** Below 0.8.0 the walker reads every operation as if it were inside an
  `unchecked` block: it wraps and emits no overflow panic (code 17). The document says `arithmetic: "unchecked"`
  (R3). Divisions, out-of-bounds indexes and enum conversions still revert, as they do in 0.5.
- **Two more pre-0.8 AST differences:**
  - Before 0.6, solc writes no `functionSelector`. Without one, the walker silently merged all of a contract's
    actions into one. The selector is now the ABI's own: keccak of `name(types)`.
  - Before 0.6, inline assembly has no Yul AST. Such assembly is now a refusal that names the construct.
- **Two solc command-line differences:** a release before 0.6.9 has no `--base-path`, so it gets `--allow-paths .`
  with the same base. A release before 0.8.8 has no `--include-path`; if a dependency tree is needed, the unit is
  Refused.
- Under a selection, every refusal ends with `[compiled by solc X (selected by pragma [...])]`, because the corpus
  record keeps only a reason's tail.
- **Go** (`holon/frontends/go/toolchains.py`). A config with `toolchain: "go_directive"` runs the lowest pinned
  release at or above the go directive of the source's go.work or go.mod. That is the toolchain Go's own
  `GOTOOLCHAIN=auto` would move to.
  - A chosen release with its own goroot builds its own ssadump, cached in a separate directory. The default
    toolchain keeps its cache path and digest.
  - The document's `extraction.tool.selected_by` records the choice.
  - If ssadump names no cause for a failure, `go list -e` adds one.
- **go.work** (`holon/eval/gowork.py`, rule `main_module`). In workspace mode Go stops with "conflicting
  replacements" when two used modules replace one path differently.
  - The generated go.work now carries the replace of the package's own module, which is the replace Go applies
    outside workspace mode.
  - A conflict the package's own module does not settle becomes the document's reason.
  - The go line is the highest go directive among the used modules.
- `holon eval holon --protocol P` runs any protocol. Run with I51's protocol it writes exactly what it wrote
  before: same doc strings, same row keys.

**D2. The total sort pass** (`holon-sort-types/0.3` = 0.2 plus rule T1, in `holon/sorts/extracted.py`).
- A term whose head has no sorts rule now becomes an opaque fresh variable, handled as the documented opaque heads
  are (`keccak256`, `calldata`, `unknown`, ...). Its operands are walked and nothing flows in or out. Each
  occurrence is a coverage-debt entry (head, action, record, count).
- A `?` with the wrong arity and a non-list term are treated the same way.
- A write without a family is not a term: no opaque value can stand in for a write that could change any family.
  The walk records it and goes on, and the pass then refuses the document with every refusal listed at once.
- `holon sorts` writes `coverage_debt.json` under 0.3 only.
- On a document with no unknown term, 0.3's walk equals 0.2's: same events, grounds and subtraction sites. Test F6
  checks this on Morph's document and on c17's.
- Only a sidecar that names 0.3 gets this pass. No milestone sidecar does (`typed_sidecar.VERSIONS` admits it).

## Soundness

1. **An opaque term constrains nothing.** T1 gives an unknown term the same treatment the pass already gives its
   documented opaque heads: a fresh variable with no flow in or out and no seed ground. Its sort is therefore the
   least informative one the solver can assign. T1 adds no constraint; the most it does is withhold information.
   So no sort the pass infers depends on a property of the opaque value. Any law built on that inference is no
   stronger than what holds for every value of the term.
2. **The pass proves nothing itself.** Its laws are candidates, decided on the model generator's model by Bend. A
   term the model generator cannot evaluate leaves the law UNKNOWN. A PROVED law is therefore proved over the model,
   and an opaque value reaches it only as an unconstrained input, so the law holds for every value.
3. **Refusals stay refusals.** Writes the pass cannot attribute stay refusals (point D2 above): skipping such a write
   could make a family look more constrained than it is.
4. **REFUTED still needs its replay.** Nothing in I103 touches the refuter or the replay. No REFUTED law came out of
   this run.
5. **Pre-0.8 arithmetic is modelled as wrapping, never as 0.8.** A missing overflow panic can only remove a revert
   path that 0.8 would add. That makes the model match 0.5's semantics; it never assumes a check the bytecode lacks.

## Surprises

1. **`config/holon.json` already dirties the whole of M3 on the lead.** I first put the sets in `config/holon.json`,
   saw 204 dirty laws, and moved them to `config/toolchains.json`. The F2/F4 tests were amended to match:
   `instrument_fix` lines in `spec/M6/amendments/I103.jsonl`. Diffing against the unmodified lead later showed the
   same 204 laws dirty there too. The amendment's stated reason ("would dirty the whole set") is therefore only half
   right: the set was already dirty. The move is still the better design, because it does not change the file every
   Morph law reads.
2. **Contract test F6 was wrong at prereg.** It injected the unknown head into a guard's own `expr`, which the pass
   never walks. It was amended (`instrument_fix`) to inject into `checks[0]`. The rule and the expected count are
   unchanged.
3. **Pre-0.6 ASTs merged every action into one.** `actions_of` deduplicates by `functionSelector or kind`. My first
   0.5 run "extracted" 9 of 10 compound documents, each with one action. That was an incomplete document, not a
   success. It is fixed by computing the ABI selector, and the honest count is 7.
4. **c17 now compiles with solc 0.8.38, not 0.8.24.** It is the newest release its pragmas `>=0.4.21 <0.9.0`,
   `>=0.6.9 <0.9.0` and `^0.8.0` admit. Its document still extracts and runs through derive (0 laws). This is the
   pragma rule doing what the source states, but it does change the document from I51's.
5. **The protocol's doc text still says `config/holon.json solc_set`.** The text was frozen at prereg, before the
   sets moved, and I left it as written. The code reads `config/toolchains.json`.
6. **The first corpus run lost the selection named in the reasons.** The record keeps only a reason's last 1,500
   characters, and the selection was at the front. It is now appended to every refusal, and the run was repeated
  .
