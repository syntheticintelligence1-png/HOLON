- **`holon/gen/implication.py`.** It emits S′ ⇒ S as one Bend law, built as IR and rendered by the existing `holon.gen.mlaws.Emitter`:
  - S's binders, all `for`;
  - S's premises, then every conjunct of S′'s claim, as `for hK` premise binders;
  - S's claim as the claim.

  The emitter refuses the obligation (UNSUPPORTED) in four cases:
  - an existential binder;
  - different facts files;
  - an S′ binder that is not an S binder of the same type;
  - an S′ premise that is not among S's rendered premises (the textual-inclusion rule).

  The proof classes are the existing ones (`holon.gen.mproofs.GENERATORS`) and then **`pick`**, which holds when every conjunct of the claim is one of the premise binders as rendered. The proof is a tuple of those binders. A generator that crashes is recorded and skipped.

  Files are written to a temporary directory under the build dir, in the separated layout:
  - `model/<name>.bend`, copied from `CompiledMachine.build`;
  - `laws/<id>/LAWS.bend`;
  - `proofs/<id>/PROOF.bend`.

  An obligation counts only when Bend accepts it, `--verdict` too when it is enabled, the law file states exactly the expected law, and neither file has an escape hatch.
  - `strengthening_checked`: the obligation is proved by the existing `hyp` class, which returns `h1`. Bend and BendTT both accept it.
  - `cross_with_implication`: the same.
  - A three-conjunct claim against a two-conjunct one is proved by `pick`, which returns `(h0, h2)`. This was checked by hand during development and is not in the committed tests.
  - `strengthening_false`: no class applies, so the obligation stays UNKNOWN and the entry is rejected.
- **`holon/audit/regress.py`** implements `python -m holon audit regress --from A --to B [--json] [--root DIR]`, wired into `holon/__main__.py`.
  - It reuses `holon.audit.prereg`'s read-only `Git` and `preflight`, which refuse shallow clones, grafts and replace refs. It runs only `rev-parse`, `rev-list`, `log`, `ls-tree`, `cat-file` and `merge-base --is-ancestor`, and never checks anything out.

For 0.1 and 0.2 that is `ir.statement_hash`; for 0.3 the refs are read from the facts file at the same commit. `REGISTRY.json` is skipped. A deleted law is reported with `new: null`. A fake-git check confirmed three cases: a notes-only edit is not reported, a statement edit is, and so is a deletion.
  - "First" means earliest in the topological order of B's whole history. A law added before A still gets its first commit.
  - Prediction entries are `laws[].law_id` items of `spec/<M>/predictions.json`, or of the frozen `predictions/<M>.json`. The two files have the same format, and M0 uses the frozen one.

## Surprises

- **The false strengthening is rejected for want of a proof, not because the implication is false.** In `strengthening_false`, S is "n ≠ 5 ∧ small" after one action from s0. That is true on the toy model, where n ≤ 1 after one step. So S′ ⇒ S holds semantically. The generator rejects it only because no class proves a conjunct from premises that do not contain it: `act_split` refuses laws with premises, and `pick` and `hyp` need the conjunct as a premise. A later proof class that case-splits under premises would accept this entry and turn `test_mislabelled_strengthening_is_rejected` red, while behaving correctly. `cross_no_proof` has the same shape: both statements are true, and it is rejected only because no entry covers the link.
- **The M2 spec prose for I8 says M2+ proofs import `../core/PROOF.bend`.** Under the separated layout a proof sits two levels below `gen/`, so its core import is `../../core/PROOF.bend`. `layout()` returns that prefix as `up`. The I8 tests find law files "whatever the layout", so this is a merge note, not a conflict.
- The docstring's three A3 flags do not cover a result committed after the law with the prediction later or together. That case gets `result_later_prediction_later_or_together`, and a law with a prediction but no result gets `no_result`.

Its payload convention should be reviewed when the first key is added: canonical JSON of the entry without `signature`.
