## Soundness

The flip only removes implications from the Go path reasoner (an op or unop term is an atom of the linear forms), so
the default keeps every path the old reading kept and adds the ones it pruned through unbounded arithmetic: a sound
over-approximation of Go's wrapping semantics. No verdict was carried: every affected record was re-made and
re-decided by the checker on (b)'s inputs, and the facts form only lets a law file whose sole change is a reproduced
document's sha256 be re-hashed, its record still re-decided. The 3 changed verdicts go from decided to UNKNOWN: the
model the flip produces cannot state those laws at all, which is a loss of decisions, not a new claim.

## Surprises

1. **A trace's directory listing depends on whether Python has written bytecode.** Python's import system lists every
   package directory it imports from (importlib's FileFinder calls `os.listdir`, which raises the audit event), and
   `holon/trace.py` records that listing keyed by its sorted names, `__pycache__` included. So a trace made where a
   package's `__pycache__` existed fails `trace.check` on a tree where it does not, and the reverse. This is why the
   facts form refused 100 lines on the assembled tree. Fixing it changes `holon/trace.py`, which every traced process
   loads, and the meaning of every recorded listing, so it is proposed as a ledger entry for the lead (instrument). The
   publishing PR's facts form cannot accept these lines on a CI tree until it is fixed.
2. **I115's `--unbound unknown` pre-check disagreed with the post-decision check** (F-M6-15): it made attempt 3 an
   instrument failure, and the lead found it had reached every corpus run since I115. Fixed in #212.
3. **Attempt 2 crashed** because the re-make template's PAR command has no `--unbound` (F-M6-04).
4. **The case-(b) count was 107, not 5** (I119's report).
5. **A pre-filter count is not a verdict count.** My per-job comparison read each job's output before the filter; two
   differences there disappeared once the filter ran. The count that decides is the post-filter one on the full tree.
6. **Rule slips, disclosed.** The second re-application commit (0e632268) was made with `git commit --amend` on a
   just-created, never-pushed revert commit. The two Q116 revert commits (8815f4d3, 78c53744) carry git's default
   message without the attribution footer; they are not amended.
