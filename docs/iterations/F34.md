# F34: modular equivalence proofs; the probe that rules them out, and what the real walls are

Fix iteration (not preregistered; milestone M3). Base `fbd14d3`. Branch `f34`, worktree `.claude/worktrees/f34`.
Scratch and logs: `scratchpad/b2-F34/` (the session's scratchpad). Nothing is pushed to the lead's branches.

**Outcome.**
- **Step 1, the probe, decided the plan.** Bend 2 checks imported definitions again; it does not trust them. A file
  that imports a module re-checks that module, and so on through every import, in the same process. BendTT
  (`--verdict`) does the same: the kernel text it checks holds every imported definition. So a module costs at least
  as much as everything it imports. The top module of any proof DAG imports the whole cone, so it costs as much as the
  one-file proof. Splitting the proof cannot get every module under the 120 s per-file budget or holon's 180 s bend
  timeout, as the measurements below show. **I did not build the modular emitter.** It could not meet its own
  acceptance criterion, and building it would have changed the generator closure (see Surprises) for nothing.
- **The two real walls, measured:**
  1. **bend2 time.** The whole :363 cone checks in bend2 as one file. That file holds all 1308 lemmas: the 851 F33
     found, plus the first-class (congruence) candidate of each of the 457 F33 never reached, generated by the
     current generator and never checked before. It is 8.7 MB, and bend2 printed ALL PROOFS CHECK in **224 s**, over
     the 180 s `bend.timeout_s`. So every one of the 457 has a bend2-accepted lemma: F33's wall was check time,
     never a missing proof.
  2. **BendTT fuel.** The BendTT kernel runs **out of fuel** on 4 of the 851 lemmas bend2 accepts:
     `q_wr_commitBatchWithProof_13`, `q_wr_commitBatch_3`, `q_wr_commitState_3` and `q_wr_finalizeBatch_2`. These
     are the storage-write congruence lemmas, 142 to 200 KB each. With those 4 removed, along with the 53 items that
     use them, BendTT accepts the rest (189 s). Every root law reaches them, so under Q22 (no fuel re-pin) no proof
     built from these lemma texts can be PROVED, whatever its file layout or time limit.
- So all three typed laws stay **UNKNOWN**. No binding_change line was appended, `holon bind` was not run, and G2
  still fails on these three laws and only on them. The fix is a generator change: smaller motives (Not done).
- **G11 (step 5).** The three records were regenerated with `holon run --milestone M3 --laws <the three> --resume`.
  The search checkpoints did **not** match, so every search ran again (see Surprises and the Results table).

F31's criterion is unchanged: PROVED needs bend2 and BendTT to accept the whole proof, holding exactly the expected
laws and no escape hatch. No budget, timeout or fuel setting was touched.

## Done

### 1. Probe: Bend 2's import semantics (`tests_m3/test_bend_imports.py`, new)

Evidence, from running the pinned checker (`bend 2.0.36`, fingerprint pinned by GENV) and from its source
(`~/.holon/bend/bend2`):

| question | answer | evidence |
|---|---|---|
| Does checking a module that imports another re-check the imported definitions? | **Yes, every time.** | `USE.bend` imports `A.bend`. If `A.lem_a`'s proof is wrong (`{==}` for `Nat.add(x, 0n) == x`), checking `USE.bend` fails with `Location: lem_a`. Source: `main.ts book_read` loads the file and all its imports into one book (`Bend.book_load`, recursive), then calls `Bend.book_valid(book, 0)`, which checks every definition at index 0 or later. Only `--checkup` seeds Base, and Base is the only definition set ever skipped. |
| Does a checked import save time? | **No.** Imports are additive. | Real lemmas of the :363 cone, levels 0 to 2 (250 lemmas, 1.37 MB) as `M0.bend` take 4.1 s. Level 3 (145 lemmas, 3.0 MB) as `M1.bend` importing `M0` takes 41.9 s. The same lemmas in one file take 41.6 s. |
| Does BendTT `--verdict` follow imports the same way? | **Yes.** | `cli_verdict` runs `Safe.safe_check(book)` on the same book. `safe_book` translates every definition outside Base (`b !== true`), imported or not. `bend PROOF.bend -o PROOF.bendtt` contains `A.lem_a`, `B.lem_b`, `S.dbl` and `LAWS.both`. `--verdict` fails when an imported proof is wrong. |
| Can a law file import several lemma modules? | **Yes.** | `PROOF.bend` imports `./LAWS.bend`, `./A.bend` and `./B.bend`, and `A` and `B` both import `./S.bend` (a diamond). `S` is loaded once (`book_load`'s `seen` map). The file is accepted by bend2 and by BendTT. |
| Is there any trusted-import mechanism? | **None that is sound and available.** | Hub imports (`0x…/`) go through the same `book_load`. Publishing does not mark anything trusted. Only an escape hatch (`law` without def, `@unsafe`, foreign code) would skip a proof, and AGENTS rule 3 forbids those. |

The test keeps the first, third and fourth rows as executable facts. It has 3 tests, all passing in 3.3 s.

lemmas that a root law needs.

every item that names it, then rerun the kernel; `scratch s/fuel.py`) gives exactly four fuel failures, all in levels
3 and 4, and then ALL PROOFS CHECK on the remaining 794 lemmas in 189 s of kernel time. Q22 says to fix fuel in the
generators, not by a re-pin, so these lemma texts can never be PROVED.

The 1308-lemma file is the current generator's text. 842 of F33's 851 cached texts are reproduced byte for byte by a
non-eqprove class of the current generator. The other 9 are the eqprove lemmas F33 counted. The 457 others are their
congruence candidates (`s/full.py`, `s/same.py`).

## Surprises

- **Imports are re-checked, not trusted.** The whole plan rested on the opposite assumption (task step 2). Bend 2
  builds one book from a file and everything it imports and checks all of it in both kernels. There is no separate
  compilation and no interface file.
- **F33's wall was never a missing proof.** All 457 definitions F33 left unproven have a congruence candidate that
  bend2 accepts on the first try. The whole cone passes bend2 in 224 s. The search could not see this because each
  of its batch files re-checks about 7 MB of proven lemmas, and runs into the 180 s timeout or a stack overflow.
- **BendTT runs out of fuel on bend2-accepted lemmas.** No equivalence lemma file had reached BendTT before: F31's
  were small, and F33 never built a final file. The four storage-write lemmas (`q_wr_*`) are motive-heavy
  congruence proofs. Each motive repeats the whole `sstore` chain with every let inlined (the `o0..o6` chain of
  `wr_finalizeBatch_2` becomes 17 rewrites of 10 to 20 KB terms). This is the A30 fuel story again (Q22), now on the
  proof side.
- **The run3 resume key also covers the statement and the whole generator closure,** not only the facts, the
  assignment, the compiled model and the checker. `Ctx.resume_dir` hashes the law's registry statement (moved by
  I27's holon-rules/1.3) and `generator_sha256(root)`, the holon import closure of the run3 generator (106 files,
  including `holon/gen/equivalence.py`, `eqsearch.py`, `statement_diff.py` and `bindings.py`, all changed by
  F31 to F33). None of the five checkpoint directories under `~/.holon/cache/run3` matched (the current keys are
  `…363…-3e6f44fb12cbf286`, `…279…-5f8f2393ef16a2f1` and `…406…-944b3e95b52e5675`), so every search ran again.
  The same rule means any later change to the equivalence generator invalidates these checkpoints and the records'
  `generator_sha256`.
- bend2's stack overflow struck again at load about 3: the same 7.7 MB file passed in 144.8 s and overflowed in
  99 s.
- F33's lemma cache file (`~/.holon/cache/eqv/32a0…/594f….jsonl`) no longer matches the current generator hash (as
  F33 said). A cold search would rebuild it. I used its texts only as scratch input for these measurements.

## Questions for the human

1. **May an equivalence proof rest on separately checked modules, linked outside the kernel?** Bend 2 offers no
   trusted import, so a split proof is either re-checked whole (no gain) or linked by holon. Under holon linking,
   each module would prove its lemmas with the lemmas it uses as explicit hypotheses (kernel-checked conditional
   statements). holon would then check textually that every hypothesis is byte-identical to a lemma proven in
   another module, and that the module graph is acyclic. That linking step is sound, a chain of modus ponens, but it
   is not checked by a kernel. F31's criterion ("one PROOF.bend checked whole") forbids it, so I did not build it.
2. **The 180 s bend timeout for the final equivalence check** (`bend.timeout_s`). The whole :363 cone needs 224 s in
   bend2 at load about 3. Unless the generator shrinks the lemmas, the final check needs its own bound. That is a
   configuration decision (F33 Q1, still open).
3. **bend2's nondeterministic stack overflow** on files of 7 MB or more (F33 Q2, still open). The 8.7 MB whole-cone
   file passed once. It may overflow on another run.
4. Still open from F31 to F33: BEND_PRIMER §5.6 (compiled JS encodes Bool as a plain JS boolean; the primer is
   frozen), the four hand-written lemmas in `prelude3_lemmas.py`, and the Q31 item 1 deviation.
