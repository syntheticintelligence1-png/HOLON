## Done

- **`holon/gen/targetlib.py` (holon-lib/0.1).** Target libraries sit next to the facts (`spec/lib/*.lib.json`, then `<facts dir>/../lib/*.lib.json`) and are read as input.
  - They supply builtins as call templates (`$0..$9`, `$args`, `${param:NAME:DEFAULT}`; kinds `nth_default`, `set_default`, `default`), prelude blocks, record blocks and shadow values.
- **The Morph code moved out of the generators.**
  - `spec/M1/lib/morph_rollup.lib.json` holds the window and challenge helpers, the ghost-tag and header projections, the aggregate stand-in and `b_blob_count`.
  - `spec/lib/go_slices.lib.json` holds the Go append and growth library.
  - Both were extracted from the old generator's own output, so every generated byte is the same.
  - `machine.py` has no Morph code left, `mproofs`' deadline class matches library kinds instead of names, and the `mlaws` model-function regex is generic.
- **Search hints.** `holon/js/policy_lib.mjs` moved to `spec/M1/policy_hints.mjs`, next to its facts. Machines without hints use `holon/js/policy_gen.mjs`, which takes its actions from `facts.search.domains`.
- **Explorer.** Prefix binders are classified structurally, so a law in sorted-key form searches like the same law in authored order.
- **Records.** `generator_sha256` now also covers the target libraries and the search hints. A facts file may carry a sidecar `ledger.json` (the toy fixture uses one).
- **Toy machine.** `tests_m2/fixtures/toy_queue` runs end to end: the planted true law `L_toy_reach` is PROVED and the planted false law `L_toy_small` is REFUTED, both checked by both kernels.

## Surprises

- **The explorer's prefix detection depended on key order.** `isPrefixVar` matched the substring `JSON.stringify` produced, and `write_json` sorts keys. So a canonicalized law silently lost its prefix search: the toy's false law stayed UNKNOWN after 13 tries. This is fixed with the structural `hasFromS0`.
- **The toy fixture needed a ledger bundle.** Adding it to the global ledger broke the I1 ledger test (every global bundle must have a gen model), so the fixture carries a sidecar ledger instead.

- **Found later, by the I11 full-suite run: I6 broke `tests_m1/test_m1_mutations`.** The test writes each mutated facts copy at the repo root. The library and hint lookup next to the facts path then found nothing ("unknown function win_at"), so M1 mutation adequacy went unchecked from I6 until the fix.
  - The fix is in `holon/mpipeline.py`: a `--facts` override stands in for the registry's facts and takes their libraries and hints.
  - The test passes again. I6's own predictions did not cover this path, and the full suite was not run at I6.
