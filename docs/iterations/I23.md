## Surprises

1. **P1 missed: the deployed implementation is the pinned source built with optimizer runs 200.** Neither of the checkout's two declared configurations reproduces the runtime code at `0x213ce22b…`: the dispatcher's selectors are identical, but jump targets differ from byte 71 on, and the deployed code is shorter (19 192 bytes against 21 830 and 25 833). A diagnostic outside HOLON's outputs (a scratch script compiling the same source with other settings) found the match: solc 0.8.24, cancun, `bytecodeHash: none`, optimizer runs **200**, immutables masked, equal byte for byte. runs 1, and viaIR at 200 or 10 000, do not match. So the deployed code is the pinned `Rollup.sol` at `3e44e795`, but not under either configuration the checkout declares. The prediction is scored as written; the instrument's configurations and the output are unchanged.
2. **Etherscan's proxy module does not serve historical state.** The task suggested it first; it answers `historical state … is not available` even at `to_block`. The instrument's public archive gateway served everything. The fetch is therefore reproducible only while that gateway stays keyless (I59's Question 2).
3. **The b - 1 answer is not the in-transaction answer, and 131 differ at b.** `getFirstUnfinalizedMessageEnqueueTime` changed within the step's block 131 times (another transaction of the same block touched the queue). The contract fixes `b - 1` as the answer, and the model agreed on every observable with it, so no difference reached status, events, storage or the calls observable. A transaction trace would give the in-transaction answers; none is reachable (`debug_traceTransaction` is refused).
4. **Discovery needs about 25 passes.** Each pass advances every step by one storage read (a read's slot depends on earlier values). Fetching at the gateway's measured budget took about 65 minutes in all.
5. **No defect was found in I20's model, I16's harnesses or I59's modules.** No extraction_defect, no fix commit.
