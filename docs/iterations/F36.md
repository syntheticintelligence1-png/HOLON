# F36: Lean G3 reads the code Lean compiles

Fix iteration (not preregistered; milestone M3; Q35 priority). Base `7fd9755` (the lead's pushed branch).
Branch `f36`, worktree `.claude/worktrees/f36`. Nothing is pushed to the lead's branches.

**Outcome.** `holon.lean.strip_comments` was a character scanner. Lean 4.34.0 starts a comment only at a token
boundary, so a file could hide forbidden code from Lean G3 while Lean compiled it. Of 45 probe files, the pinned Lean
accepts 39; 34 of those hold a forbidden construct in the code Lean compiles, and the old scan missed 19 of them (one
only through the gate's text-mode read). The new scan catches all 34, still passes the three accepted probes whose
construct sits in a real comment and a CRLF file, and passes all 9 committed Lean files. No committed Lean file fails
the new G3.

## Done

- **A lexer that mirrors Lean's tokenizer** (`holon.lean.lex`). It was written from the toolchain's own source,
  `src/lean/Lean/Parser/Basic.lean` (`whitespace`, `finishCommentBlock`, `strLitFnAux`, `charLitFnAux`,
  `rawStrLitFnAux`, `numberFnAux`, `identFnAux`, `tokenFnAux`) and `Init/Meta/Defs.lean` (`isIdFirst`, `isIdRest`,
  `isLetterLike`), then checked against the probes with the pinned binary. It lexes these atomically:
  - `«…»` identifier parts and dotted identifiers, including name literals;
  - identifiers with primes (`x'`), so a quote inside an identifier never starts a char literal;
  - char literals with Lean's escapes;
  - strings with the same escapes plus gaps;
  - raw strings `r"…"` and `r#"…"#` (no escapes, `#` delimiters);
  - numbers (`0x`, `0b`, `0o`, `_` separators, scientific), and projections `x.1` as digits only;
  - line, block, doc (`/--`) and module-doc (`/-!`) comments, which all nest. After a plain `/-`, Lean also skips
    the third character, so `/-/-` opens one level, not two.
- **It refuses what it cannot classify the way Lean would** (`LeanLexError`; `forbidden()` reports
  `unlexable: <reason>`, so the file fails G3 and `check_text` returns `forbidden` before running Lean):
  - `{` in a string literal: the same text is an interpolated string, which runs code inside `{…}`, wherever the
    grammar expects one (`s!`, `m!`, `throwError`, …);
  - `--` right after `<`, `-` or `/`, and `/-` right after `/`, `=` or a backslash. These come from the token table
    of Lean 4.34.0 with `import Lean` (a superset of what an import-free file sees), as the characters that some
    token holds before a `-` or a `/`, such as `<-`, `//` or the ASCII "or";
  - a quote right after `#` (Init's scoped token `#'`). A quote right after `]`, `⊕`, `Σ` or `×` is the end of a
    global token (`]'`, `⊕'`, `Σ'`, `×'`), so it is lexed as code;
  - a carriage return outside a CRLF pair: Lean does not end a line comment there;
  - unterminated literals, escapes or comments, malformed numbers.
- **The scan reads the Lean names** (`scan_text`). Comments are dropped, and each identifier appears as its Lean
  name between spaces, so `«sorry»` reads as `sorry` and `«debug».«skipKernelTC»` as `debug.skipKernelTC`. String
  and char literals are emptied, which is safe now that they are lexed exactly and none is interpolated.
- **`FORBIDDEN_CMD` finds `#eval` and `#exit` anywhere**, not only at the start of a line: a command can start
  mid-line (`def x : Nat := 1 #eval …`).
- **`FORBIDDEN` gains four words:**
  - `sorryAx`, sorry spelled as its constant;
  - `binder_predicate`, `declare_syntax_cat` and `declare_simp_like_tactic`, the core commands that add tokens
    without a FORBIDDEN word. A new token may hold `--`: `binder_predicate x " ≺--" …` hid a
    `theorem u : False := sorry` on the same line.
- **Gate G3 reads Lean files as bytes** (`holon.lean.g3_violations`, called from `holon/gate.py`). Before, it used
  `read_text`, whose universal newlines turn a lone carriage return into a line end; Lean does not. With that, a `"`
  after the carriage return in a line comment opened a phantom string, and a later string closed it (probe
  `cr_line_comment2`).
- `check_text` runs `forbidden()` before `theorems()`.
- **Tests** (`tests_m3/test_lean_lexer.py`, new, 9 tests):
  - every probe Lean accepts and that hides a forbidden construct is caught;
  - the clean probes pass;
  - `lex` covers each source exactly;
  - lexer details;
  - `check_text` refuses before running Lean;
  - the gate's byte read;
  - every committed Lean file passes G3, lexes back to its exact text and declares a theorem;
  - with the pinned Lean, every probe's recorded acceptance holds, and each hidden `axiom bad` is really declared
    (`#print axioms bad`). The Lean tests skip with the reason when the toolchain is missing.

  The 9 tests ran in 33 s.
- **Records.** `holon/lean.py` is in the holon-ir/0.2 and 0.3 generator closures, so M1 and M2 were regenerated:
  `holon run --milestone M1` took 105 s and `--milestone M2` 250 s, both exit 0. A key-level diff of the 28 changed
  records shows only `seconds` (80 leaves) and `generator_sha256` (28).

## Surprises

1. **The hole is wider than «/-».** Besides the four `«…»` forms, these hid code too:
   - raw strings (no escapes, so `r"\"` desynchronised the old literal regex);
   - a `'"'` char literal (`forbidden()` blanked a quote-to-quote span that began inside it);
   - interpolated strings (`s!"{(sorry : Nat)}"` was blanked as a string);
   - `/-/-` (Lean skips the third character of the opener);
   - tokens ending in `-` or `/` before a `-` (`<--x`, `{ x : Int //-x = 0 }`, the ASCII "or" before `-`);
   - a mid-line `#eval`;
   - a token added by `binder_predicate`;
   - a lone carriage return read through Python's universal newlines.
2. **Doc comments nest like block comments**, including Verso docstrings (`set_option doc.verso true`): Lean locates
   their end with the same `finishCommentBlock`. `doc_nest_trick` and `modoc_nest_trick` are not holes. A Verso
   docstring's `{lean}` role did not declare anything (`verso_doc`).
3. **Lean ends a line comment only at LF**, and CRLF files are accepted.
4. **`sorryAx` was not forbidden.** The axiom audit of the checked theorem still catches it, but the text-level G3 did
   not.
5. **Application needs whitespace before an argument** (`f '"'` parses, `f'"'` does not), so the word-boundary probe
   `sorryλ…` is rejected by Lean. The new scan separates tokens anyway.
6. **M3 records.** The three `L_sort_*` M3 records carry the holon.sorts.run3 closure's `generator_sha256`, and that
   closure imports `holon/lean.py`, so these records are now stale. The 80 PAR and 8 UNDO records were stale before
   F36. `holon run --milestone M3` is the lead's and was not run (as in F31-F33).

## Questions for the human

1. **More forbidden words?** The `FORBIDDEN` list does not name these, which run code or relax checking without a
   lexical trick. None is used by a committed file.
   - `#guard`, `#reduce`, `#check_failure`: `#guard` evaluates compiled code during the build, like `#eval`.
   - `unsafeBaseIO`, `unsafeIO`, `unsafeEIO`: the word pattern for `unsafe` does not match them.
   - `elab_rules`, `simproc`, `dsimproc`, `grind_propagator`, `unif_hint`.
   - `set_option` beyond `debug.skipKernelTC`: the task text lists "set_option …" among the forbidden constructs;
     FORBIDDEN never did, and every committed Lean file uses `set_option maxRecDepth` or `autoImplicit`.

   F36 added only `sorryAx` and the token-adding commands, because those break the lexer's own assumption.
2. **`theorems()`** audits only theorems at the start of a line (`^theorem name`). A `private theorem` or
   `@[simp] theorem` is not passed to `#print axioms`. The expected theorem's transitive audit still covers what it
   uses. Should the audit list every theorem token?
3. **`tests_m3/_i42.py::lean_code`** (preregistered, not edited) uses its own comment stripper, with the same
   character-level design. The I42 amendment refuses `«` after the marker, and Theory.lean holds no string. Should
   I43 switch it to `holon.lean.strip_comments`?
