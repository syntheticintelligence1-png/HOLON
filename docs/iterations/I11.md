## Done

- **`holon/diagram/`.**
  - `model.py`: `Carrier`, `Edge`, `Diagram` with `to_json()`. Serialisation checks unique ids, known kinds and classes, and that every edge endpoint and access target is a carrier.
  - `build.py`: one adapter per facts section, in a table per facts version (`ADAPTERS_01`: 5 sections, `ADAPTERS_02`: 21).
    - A section with no adapter stops the build. So does any construct an adapter does not know: an unknown function kind, action key, guard key, operator or builtin.
    - So zero unmapped constructs is enforced, not just listed.
  - `access.py`: index-sensitive read/write sets, computed by walking the facts expressions. Lets are substituted and `defs` are inlined at the call, so a read inside `w(lfi,win,idx)` shows up as `[win, idx-lfi]` on the action that calls it. Terms are infix text without spaces.
    - Builtin roles come from the generic DSL vocabulary of `holon/gen/machine.py`, plus the `kind` a target library declares (`nth_default`, `set_default`, `default`). No target name appears in the module.
    - A library builtin with no declared kind is opaque: every state field passed to it counts as accessed whole (`*`), and the diagram records ACCESS debt.
  - `principals.py`: principal classes. A class is named by the actions' `principal` label up to its parenthetical. Its predicate is the action guards that mention the caller input `who` (after let substitution), and every action of the class must carry the same ones.

## Surprises

- **Session base.** The session's worktree branch was created from `origin/main` (`8eb6ed7`), which does not contain this preregistration. `origin/main` and `claude/holon-v2-bend2-c6z3cd` diverged at `9ffdf77`.
  - Resetting the branch was refused by the session's permission check, so the work is on a new branch `i11-diagram` from `bf135fa`.
- **Partiality (I11-P1).** The diagram marks a CODEC edge partial iff the facts declare its codomain an option type (`Maybe<T>`), following §8.3: "partial edges return an option type, so definedness is explicit". Only `dec_go` qualifies.
  - `enc_sol` also has a domain guard (`version <= 2`). Outside it the Solidity call reverts, and the M0 model returns a one-cell `UNDEF` byte list, not an option.
  - The guard is kept on the edge as `domain`. Read as "not total on its carrier type", Def 4.2 would make `enc_sol` partial too, and the count would be 2 (question below).
- **Two coordinate systems in the predicted index terms (I11-P4).** `(win, idx−lfi)` is a position in the model's window list. `(s_csr, lci+1)` is an absolute batch slot. No single key space yields both.
  - The diagram records a `key_space` per carrier:
    - `position` for model lists, keyed as the facts index them;
    - `slot` for residue lists, with `slot_base` and its provenance.
  - **Deriving the base.**
    - `bvh_at` and `tag_at` map an absolute index to a shadow position (`idx-lci-1`), so the base of `s_bvh` and `s_tag` is `lci+1`.
    - No definition reads `s_csr` or `s_bd`. They take that base only through a checked lockstep rule: every action that moves one shadow list moves all four with the same expression, and the only other writer (`legacy`) rewrites values in place.
    - So the predicted `["s_csr","lci+1"]` rests on that rule.
  - **Reads in slot terms.** The commits' reads of the residue at the slot they commit come out as `["s_bvh","parent+1"]` (and `s_tag`). That equals `lci+1` only under the later guard `parent == lci`, which the walker does not use for rewriting.
- **A ledger gap.** Abstraction 2 of `morph_rollup` ("committedBatches is not stored ...") is cited by no entry of `spec/ledger/assumptions.json`. Recorded as LEDGER debt. It may be meant as covered by `CF-keccak-headers`.
- **Pre-existing red tests in `tests_m2`.** None of these comes from I11.
  - `test_filter.TestBins.test_predicted_bins_new_replays` (I4-P5) and `test_replay_completion.TestConsumerSides.test_fact_z_consumer` (I4-P4) are the two `L_fact_Z` misses that `docs/iterations/I4.md` reports. This is intended (G1-like), but parallel iterations that edit the ledger will need a regeneration on merge.

## Questions for the human

1. **Def 4.2 partiality.** Is "partial" the §8.3 notion (option-typed codomain: `dec_go` only), or "not total on the carrier type", which also covers encoders with a domain guard (`enc_sol`, version ≤ 2)? The diagram keeps both pieces of information (`partial`, `domain`). Only the flag's meaning is in question.
2. **Index-term key spaces.** Should every per-batch register family be keyed by absolute slot? Then the window term would read `(win, idx)` and the snoc slot `lci+1`, and the prediction's `(win, idx−lfi)` would not appear. Or is the mixed convention intended: model positions for lists, absolute slots for residues?
3. **Access kinds for library builtins.** `bump_f`, `clear_chs`, `any_open`, `zero_csr`, `set_last_csr`, `win_last`, `tags_exact` and the three `go_*` builtins declare no access kind, so their accesses are over-approximated as `*`.
   - Adding kinds (for example "writes every slot but $1" or "reads the range $1..$2") would make those sets precise.
   - But it changes the library bytes, which are part of every M1 record's `generator_sha256`. I11-R1 forbids that here. May a later iteration do it?
4. **Version labels.** Facts 0.2 carry no version labels, so every 0.2 edge has `version: null`, and the MIG edges do not name S_k → S_{k+1}. `legacy` maps a state to the shape the pre-`reinitializer(2)` code would have left, so it is not a version step.
   - Should version labels wait for deployment-history extraction (I28)?
5. **Buffer and digest carriers.** No carrier is classified `buffer` or `digest`.
   - Facts 0.2 declare no backing identities: batchdata's heap and slice headers are ordinary state.
   - The hashes are stand-ins (HASH debt), so there is no digest carrier.
   - Should the batchdata heap or slices be buffers before I35 extracts backing identities?
6. **Abstraction 2 of `morph_rollup`.** Add a ledger entry, or is it covered by `CF-keccak-headers`?
7. **The I6 library lookup** breaks the M1 mutation test (see Surprises). Which iteration should restore it, and how should facts outside `spec/` find their target library?

No construct was forced into an edge kind.
- The facts sections that are not diagram structure are recorded as metadata and named as such in `mapped_sections`:
  - `policy` and `search` (explorer configuration);
  - `principals` (concrete ids; their class membership depends on state and is not computed);
  - `target` and `extraction` (provenance).
- The log write every TRANS edge carries comes from the facts-0.2 machine semantics (every step logs its outcome), not from an effect.
