### Builder B

- **`mproofs.coercion_guard`** (`holon/gen/coercion.py`). The generator reads the ghost section of the instrumented model the law imports (never the facts, the derivation or a site name) and mirrors it definition by definition: `site_<x>` by `match a` (`{==}` for an action that is no entry point), each entry point's chain head by `match s`, each decision helper `gs_<x>_<a>_<i>` by a lemma that takes the condition `c` and, when a hit below uses it, the equation `e: {<condition> == c}`, then `match c` (`{==}` where the action stops). Path conditions (`ite(Bool, C, X, Y)`) get a helper of the same shape, `Bool.and` is `C.core_and_intro`, a definition ghost `gd_<x>_<f>` is a lemma for every argument. At each hit the obligation `Nat.is_le(subtrahend, minuend)` comes from ONE passed fact, tried in the order the evaluation passed them: zero or more `C.core_and_left`/`C.core_and_right` projections (single-expression model definitions such as `d_in_win` unfold for the search; Bend unfolds them by computation), then one comparison lemma of `holon.gen.core.CATALOG` whose hypothesis matches the fact and whose claim matches the obligation. A fact moves into the one sub-proof that uses it (equations are `Type`). Every proof imports `gen/M2/laws/<id>/LAWS.bend as Laws` and `../../core/PROOF.bend` / `LAWS.bend as C`, and defines `Laws.<law>`.
- **Core library** (`holon/gen/core.py`): `core_le_of_gt` (a > b ⇒ b ≤ a), `core_le_of_not_le` (¬(a ≤ b) ⇒ b ≤ a) and `core_one_le_sub_of_not_le` (¬(a ≤ b) ⇒ 1 ≤ a − b), proved by their nat2 class; the ex-falso candidate through `Equal.sym(Bool, True{}, False{}, e)` for a hypothesis `{X == False{}}` (only such hypotheses get it, so the earlier lemmas keep their candidate lists). `core_le_of_lt`, `core_le_of_ge`, `core_and_left` were already there.
- **Refutation per entry point** (`holon/js/explore.mjs` `siteSearch`, `holon.mpipeline.refute_site`). S2: the explorer's reachable prefixes (BFS over successful policy actions, `prefixDepth` 3, `maxPrefixes` 3000; 1914 explored on the rollup), in order; the first (prefix, candidate) where `site_<x>` is false. ## Surprises

1. **F-M2-01 against the prereg's "UNKNOWN (scope bounded)"** (amended, `spec/M2/amendments.jsonl`). The I15 contract and two prereg assertions say an UNKNOWN site record has `scope: "bounded"`. The audit fix F-M2-01 (FX1, merged after the prereg) makes a holon-ir/0.3 record's scope its statement's, and the v2 schema then requires `scope: "unbounded"` for a statement whose scope is unbounded, which every SORT-site law's is: `test_every_m2_law_has_a_record_valid_under_v1_and_v2` asserted v2 validity and `scope == "bounded"` at once, which no 0.3 record can satisfy. Both assertions now check that the scope is the statement's and that `bound` (the search bound, kept in its own field by F-M2-01) is non-empty. The predicted status is unchanged.
2. **`holon bind` also appends to `spec/bindings/changes.jsonl`.** The expected amendment named only `spec/bindings/M2.json`; `holon bind` logs every new milestone with a `created` line, so the I6 tree hash changed through the log too. The amendment of `test_bindings_unchanged` hashes `changes.jsonl` with only its M0 and M1 lines; `BINDINGS_PIN` is unchanged.
3. **`DERIVATION.json` had no `links`.** FX1's G2 cross-milestone check (F-M2-08/23) requires a list of back-test links in `laws/<m>/DERIVATION.json`; A's derive (following the I15 contract, which lists no such key) wrote none, so G2 failed. Derive now writes `"links": []`; `laws/M2` was re-derived: only `DERIVATION.json` and the registry's `derivation_sha256` changed.
4. **The rollup's ledger bundle does not classify the M2 model.** A run over derived facts (MUT2) checks that every definition in a law's cone is classified by the base bundle, and the M2 model's `Reach`, `HO_agg`, `ap_agg` and `perm_<class>` (I8, I12, F-M2-26) are not, so the MUT2 run failed with `LedgerError` (it would have for any M2 law over mutated rollup facts). Editing `spec/ledger/assumptions.json` would change the diagrams (they hash it) and with them I14's `gen/M2/evidence.json`; instead `spec/M2/ledger.json` extends the bundle for milestone M2 (`holon.records.milestone_extensions`), and the ghost section is not classified at all (it is instrumentation, not model). See Questions.
5. **The prereg toy, rewritten with sorted keys, did not compile.** `test_toy_site_without_its_guard_is_refuted` writes the toy back with `sort_keys=True`, which puts def `after` before def `lci`; `holon.gen.machine` emitted defs in facts order, and Bend sees only definitions above. `gen_defs` now emits a stable dependency order (facts already in order, M1's included, are byte-identical).
