### The refusals (what makes overstatement fail)

`holon.m5.report` writes nothing and exits 1 when any of these holds:
- a metric differs from the measuring iteration's committed output;
- a truth file, or `preregistration.json`, is off its pin;
- `validate()` finds an overall that is not common.overall of its thresholds;
- a threshold differs from its re-judgement. The re-judgement uses the metric's own numbers and the preregistered op and target (V9 and the zero-count rules included);
- a threshold was judged on a measure that is not measured, or a label is not its denominator's;
- a pooled measure appears;
- an evidence check of a condition or limitation fails;
- an iteration report gives other than exactly one outcome per prediction;
- a record that claims checker evidence names no law in a committed `LAWS.bend`, or a game record's class verdicts are not the vector its committed module states.

## The adversarial phase (run by the builder, no subagent)

I tried to make the report overstate a metric, first on the build and then on HOLON's own records in a scratch copy of `spec/` and `results/`. Each probe that got through is now a refusal, with a test.

1. **A threshold flipped against its number.** In the first build, setting L9's `coverage` to meets in the document passed `validate()`. Overall still read misses because of the other thresholds, so the check caught only inconsistent overalls, not wrong verdicts. **Folded into the build:** every threshold is re-judged from its numbers and the preregistered op and target (A5, and A1's second case).
2. **An off-pin truth file** raised I55b's own RuntimeError instead of a refusal. Folded: the iterations' assembly errors become a ReportError (A1).
3. **A forged game record with its iteration output regenerated to match.** I set an untrusted class of `L_disch_blk_rollup_363…` to rational: payoff nonneg, a strategy length within the horizon, so V1–V8 still pass. I then re-ran I56b's `games corpus` in the copy, so `l6_corpus.json` agreed. The report accepted it and printed **decided 1/49**. I54's metric trusts the records' evidence fields by design: it runs no checker. **Folded:** each record that claims checker evidence must name a law that a committed `LAWS.bend` states, and a game record's class verdicts must be its module's vector (I56's B1). The forgery is now refused (A2), and so is evidence naming a non-existent law (A3). **Residual:** a forger who also edits the Bend module is caught only by re-running the checker. `games run --check`, `intent run --check` and `m5 env --check` do that; all three print CHECK OK on this tree.
4. **Doctored definitions.** Lowering L9's coverage target in `preregistration.json` would make the re-judgement agree with a wrongly met threshold. Folded: the file must be at the I58 key's pin (A4).
5. **Pooling.** I55's `l10.json` carries a pooled precision of 81/94, with control atoms added to target atoms. It is not carried, and `validate()` refuses a pooled key.
6. **A hard-coded sentence.** The first render said "No metric meets its preregistered level" as fixed text. It is now derived from the overall verdicts.
7. **Clobbering by landing.** A standalone `results/M5/metrics.json` would be overwritten by `holon land`'s `metrics --milestone M5` step. Folded: `holon.metrics` itself carries the block (Surprise 3).
8. **Not probed:** a different-family reading of anything, since none exists; the iterations' own instruments (each iteration probed its own); `holon land` run end to end.
