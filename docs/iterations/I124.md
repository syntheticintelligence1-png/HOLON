**F-M6-07 is a resource limit, not a generator defect (Q108).** The model in question:

- c19's second package's Trie machine, 22,370,984 bytes, sha256 prefix 91cb0e03, byte-identical in I120's counted
  run and in this sandbox.
- It compiles in Bend with exit 0 here, in 36-39 s, at a peak of 11.7 GB RSS on a 15 GB, 4-core container.
- I120's run stage took 120 s in total, so the checker's 180 s time-out was not the cause. The most likely cause is
  the OS ending the compile for memory.
- The error kept only the checker's output, never the cause. Hence (a): a resource kill depends on the environment,
  so the record now always names its cause.
- The model's size is ledger entry F-M6-10, for a later key at the generator.
- The preflight memory record (F-M6-11) is taken here, after the prereg, as build work: the lead's reading of Q108 (3)
  allows it when it is recording only. `holon.eval.holon_run.memory_record` adds MemTotal, MemAvailable and the
  cgroup memory limit, in bytes, to every preflight record under the key `memory`. It decides nothing and gates
  nothing, since the preflight's status is still the binaries' alone. It changes no existing test (I112's and I115's
  preflight tests pass), and the new test `TestMemoryRecord` is in the CI job. It is committed before the measured
  runs, so both of them record it.

F-M6-08 is a consequence of F-M6-06 on the corpus: the runner crashed before reaching some components. It is fixed on
its own anyway, because I118's per-document re-run also leaves a component's model unwritten.

## Soundness

No change makes a law PROVED that was not, and none can make a true law REFUTED:

- **F-M6-06.** `[]` is the exact term for the only value of a zero-cell carrier. Every decision is still a
  counter-law Bend accepts, its witness replayed on the real Go code (P2). Where Bend rejects the counter-proof at
  `[]`, the law stays UNKNOWN (Rest's totality, P2). Non-empty witnesses are written byte for byte as before (P1).
- **F-M6-07.** A document whose model cannot be built is decided by nothing: its laws are UNKNOWN with the cause, no
  proof or search is attempted, and the other documents run as they would (P5). The change only turns a runner stop
  into per-document UNKNOWNs, under the opt-in that already does this for refused sections. Without the opt-in nothing
  changes (P6). The generator is not changed.
- **F-M6-08.** The fix is scoped to the models the milestone runner writes lazily (`gen/<M>/model/`), which is the
  mechanism exactly; the lead accepted this scope (Q108 (2)). A model an earlier stage generates (a typed model) that
  is missing is a fault, not "never reached": it still fails as before, so I118's per-document fallback is unchanged
  where the protocol opts in. Within that scope: a law whose model was never generated has no record that the run decided, since the runner writes the
  model before it decides any law over it. The binding check still refuses any decided record of an unbound law (P8).
  Every bound law is bound exactly as before (P7). Every other failure still refuses (P9).

## Surprises

1. **F-M6-07 is a resource limit, not a generator defect** (above; Q108). The model Bend "failed to compile" compiles
   cleanly on the same bytes, at a peak of 11.7 GB RSS.
2. **I118's planted bind fault is the same shape as F-M6-08, one directory over.** I118's P5 removes a typed model
   (`gen/<M>/sorts/models/`, written by the sorts stage before the run) and expects I118's document fallback. My first
   build unbound any missing model, which changed that outcome. The fix is now confined to the runner's lazily
   written models (`gen/<M>/model/`), which is exactly the mechanism. A typed model missing after the sorts stage
   wrote it is a fault, not "never reached", and it still fails as before. tests-m6-i118 passes unchanged, and no
   test or amendment was needed.
3. **F-M6-06 hits four entries, not two** (c04, c09, c14, c19, per I120's report): every component of a type whose
   methods read none of its fields.
