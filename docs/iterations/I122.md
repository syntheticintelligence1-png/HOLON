## What was built

### (1) The frontend's opt-in `loops "shapes"`

It is config holon-go-frontend/0.3 and works only with `ops "typed"`. Any other value, or `loops` without `ops
"typed"`, is refused. The composed driver passes it from protocol `go.loops`, and never to the Go machine frontend.
Under it:
- **Wider emission:** loop_bodies are emitted for every function with a body, codec-shaped or not, and for counted
  loops of any constant non-zero step.
- **No init <= iv fact for a step other than 1.** That fact is false for a negative or wrapping step. The existing
  `loop_facts` give facts for step 1 only, unchanged.
- **Each entry carries `typed`:** `{terms, stale, iv_type, lengths}`.

Without the opt-in, every output is byte-identical, which P1's control checks.

### (2) The classes: `holon.gen.goshapes`

goloop tries them only after its I67 class refuses an op, and only for a loop body that carries `typed`. So an op in
the I67 class, and every document without the opt-in, is modelled as before, with one exception. `cells_literal`'s
empty case is not behind the opt-in: on the base path it turns F-M6-06's crash into the empty list (Surprises 6).

**S1 (range)**, "For statements with range clause":
- **Shape:** one loop with init 0, step 1, cmp <, and limit len(X), where X is the parameter or a field path from it,
  of slice type []E. E is an integer type of at most 32 bits.
- **Trip count:** the range expression is evaluated once, so the trip count is len(X), read from the carrier.
- **The index term is exact:** the frontend writes the index as (iv - 1) + 1 over int. That is iv exactly, since int
  is 64 bits and 0 <= iv <= len(X).
- **Cells:** one node per element. A signed element is stored in offset binary (value + 2**(n-1)), which keeps the
  signed order.
- **Model:** goloop's step and run, with the fuel being the sequence's length (`gs_len`).

**S2 (stride)**, "For statements with for clause" and "Integer overflow":
- **Shape:** one counted loop over a byte array of known length n, with constant init, limit and step s (not 0 or 1),
  and an induction variable of recorded integer type T.
- **Trip sequence:** iv_(k+1) = fit(iv_k + s, T), while cmp holds in T's order. It is computed concretely, up to 4096
  iterations.
- **Cells:** iteration k reads p[a*iv_k + c]. Every affine value an atom compares is an exact integer in T's range,
  or the op is Unsupported, because the value would wrap. A bound check's constant may lie outside T (the index is
  compared as an int value), and it is compared with the same exact value.
- **Atoms** become sets of iteration numbers.
- **Cell map:** the explicit index tuple, with no byte read twice and every index in [0, n).

**Both classes:**
- **Unsupported** covers everything else, and the reason is recorded in the model's comment line. That includes: a
  second loop, a second cell, a wide or non-integer element, a call result or any other term in a condition, a stale
  body, and paths that do not partition the samples.
- **Deciding** follows rule Y7. The ops of a law share one cell map. The candidates are the shortest panic witness,
  then the continue values, and for S1 the empty sequence too.
- **No proof route (G6).** A law is REFUTED only by a counter-law Bend accepts.

### (3) Replay and counts

- **goreplay** replays an S2 witness on the real function: cell k goes to byte idx_k, and the other bytes are 0. An S1
  witness is recorded as `not_run`, with the reason: a generated test does not build a slice carrier.
- **`tools/i122_shapes.py`** writes `results/M6/I122/loop_shapes.json`. These are model-generation counts, by class
  and by reason category, with no name in them: pre-decision, Q72. On I116's committed documents it gives 40 ops, 13
  with a loop and 0 loop bodies, which matches the count.

## Soundness

- **Each class is the specification's rule.** Every planted op in a class is compared with the pinned toolchain by
  running the real function on every enumerated edge input. The S2 trip sequences are compared with the real headers.
- **An op outside the classes has no definitions,** so every law naming it is unbound (I115's check) and UNKNOWN.
- **Neither class can make a law PROVED:** there is no proof route. A REFUTED needs a counter-law Bend accepts at a
  concrete witness. The record's difference is the compiled model's, and the planted tests replay every witness as
  real Go.
- **No kept or pruned branch depends on unbounded integers.** Both classes need `ops "typed"`, whose reasoner reads
  sized arithmetic as opaque. S1 has no arithmetic. S2 evaluates the trip sequence and the indices concretely in Go's
  semantics (`goint.fit`), and refuses any affine value that would leave T. The removed init <= iv fact could only
  have pruned, so removing it can only keep paths. Each class therefore uses the opaque reading. The narrow-arithmetic
  loop mode is unchanged (Q93 (1)).
- **Declared abstractions** (the model's ledger bundle):
  - `A-goshapes-range`: only the ranged slice's elements are modelled; every other field, and a nil receiver, is not.
  - `A-goshapes-stride`: only the bytes the trip reads; the others are 0 on replay.
  Leaving bytes out can only lose refutations: every witness is one concrete value.

## Surprises

1. **The Go frontend writes a range loop's index as (iv - 1) + 1.** SSA's range index starts at -1, and the opaque
   reasoner does not fold it. goloop's affine reading folds it exactly, since the index is an int. This is why S1 needs
   no new index rule.
2. **A bound check on a narrow index compares with a constant outside its type** (uint8 i against 256). My first
   draft refused it as non-representable. In Go the comparison is between the index's int value and the length, so
   the exact integer comparison is right.

3. **The baseline extracted two entries fewer than the counted run** (c06: a network refusal from `sum.golang.org`;
   c08: packages did not load). So a same-code baseline is only as good as its environment, and P9's PAR comparison
   misses for this reason, not for anything this key changes.
4. **Two of my corpus tests could not fail as written** (P9 compared absent keys; P10 read absent fields). I only
