  own message (`kernel_message`, `construct_of`):

    `- name: why`.
  - It then runs the pinned kernel binary on that translation, with the stack bend2's `kernel_check` gives it. The

- **The records (S3).** `holon/bundle/lawrun.py::check` is the bend2-then-BendTT check shared by the Go laws

### F-M3-14: the checker's environment (A1-A3)

- **A1: the env-file rule.** `holon.bend.unsafe_env_files`, which GENV reads, refuses `bunfig.toml` and every name
  that starts with `.env`, at any depth outside `.git`. That is AGENTS.md rule 8 as `holon/consumers.py` already
  reads it. Before, it refused only the exact names `bunfig.toml` and `.env`. The lead's tree holds none.
- **A2: the run.**
  - **An allowlisted environment** (`checker_env`). Only `ENV_ALLOW` (`PATH`, `HOME`, `TMPDIR`, `LANG`, `LC_ALL`,
    `LC_CTYPE`) passes from the caller's environment. HOLON then sets `BEND_NO_TELEMETRY`, the registered
    JavaScriptCore stack, and `BENDTT` as the pinned toolchain's kernel, once built (`pinned_kernel_path`:
    `verdict_kernel_path` of the resolved checkout). Until then, bend2 builds the kernel at that same path.
  - **A foreign BENDTT is refused.** An inherited `BENDTT` never reaches bun. One that names another path raises
    `EnvRefused`, which names it. GENV still refuses any inherited `BENDTT`.
  - **The working directory.** `check` and `check_verdict` run in a fresh empty working directory, with the file
    given by its absolute path. The classifier's emission and its kernel run use their own temp directory. Every
    other run (`run`, `run_budgeted`) refuses a working directory that holds a name A1 refuses.
  - **Why this closes it.** Probed on the pinned bun 1.4.2:
    - bun reads `bunfig.toml` and `.env*` from its working directory only, not from the file's directory or a
      parent;
    - with `NODE_ENV` unset it loads `.env.development`;
    - the process environment wins over `.env.local`, but unset names are filled from the file.
  - **No output changes.** bend2 resolves imports relative to the file and prints no path in its verdicts. A
    relative-name run and an absolute-path run from an empty directory gave byte-identical output, and wrote nothing
    to the working directory.
- **Also changed.**
  - `holon/kcache.py` takes the kernel's sha256 from the pinned path only, never from an inherited `BENDTT`.
  - `verdict_available` no longer counts an inherited `BENDTT`.
- **A3: the round-4 repro.** `abc1cbb9:audit/rounds/M3/round4/a7/repro.sh`, run on scratch copies (`git archive` of
  `046464a4` with `holon/`, `config/` and the four files it copies):

**Minimization** (local, the pinned toolchain, 13/13 pins).
- **Each failing definition is a closed equation proved by reflexivity.** The kernel has to evaluate both sides. Cut
  after that definition, the proof's text still has bend2 accept and the kernel stop in the same definition. This
  was checked for the four member laws; for the Go laws, `cz` is the first definition.
- **The Go laws.** `cz` evaluates the branch predicate at the witness. Its helper `cb` computes `Nat.sub(131072n, n)`
  at n = 126976. That subtraction alone is the registered repro.
- **The member laws.** Each definition is one model step, or one predicate, over a concrete state and the witness's
  keccak table `t_kh`, a 200-400 KB literal. They are cut to the definition, not to one primitive operation. The
  kernel's own message is out of fuel in each.
- **What the kernel evaluates within its fuel, by probing.**
  - Pass: `Nat.add`, `Nat.mul`, `Nat.le`, literal equality, small `Nat.sub` and `Nat.div`, and U32 limb arithmetic.
  - Out of fuel: `Nat.sub(131072n, 126976n)` and `Nat.div(20000n, 256n)`.
  - Nat literals reach the kernel in unary (`Succ`/`Zero`, with add and mul decomposition).
- **I94 met the same limit.** BendTT ran out of fuel in `cz` on the cutover's O13 and O20, which stayed UNKNOWN by
