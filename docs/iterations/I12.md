## Done

- **The encoding: oracle tables (the plan's fallback).** A Bend function value is `Type`, never `Data`, so `run` cannot take a hash as a function parameter and apply it at every step (I7 Surprises). A modelled parameter `p : Fn<A,B>` is held as Data instead: a table `List<&2, HO_p>` of entries `HO_p{k: A, v: B}`, applied by `ap_p(t, x)`, the `v` of the first entry whose `k` is `x`, else the default of `B` (`0n`, `False{}`, `Nil{}`).
  - Tables are reusable (`+`), so `step`, `run`, `obs` and `runs_ok` thread them. Each generated function takes only the tables it needs: `exec_<a>` those its effects apply, `decide_<a>` and its chain those its guards apply, `d_<name>`, observers and migrations those their bodies apply.
  - `Reach` is indexed by the threaded tables (`type Reach<-agg: .., -dec: .., -s: HSt>`). Bend accepts it.
  - **Locality** is the model assumption this rests on. Every function agrees with some table on any finite set of points. A statement's evaluation (Bend is total) queries `p` at finitely many points, and running with the graph of `f` on those points makes the same queries and gets the same answers. So a law proved for all tables holds for every function, and a refuting table is itself a function. It is documented as ledger entry `oracle-tables` (new top-level `encodings` section of `spec/ledger/assumptions.json`). It is not a premise and not an axiom: laws assume nothing about tables beyond their own CF and hyp premises.
- **`holon/gen/oracles.py`.** It loads the sidecar (`F/../../lib/oracles.json`; only M2+ milestones pass one, `mpipeline.m2plus`), lists the modelled parameters, and provides:
  - `hypothesis_premises` (§8.5);
  - `expand_hyps` (a hyp premise as its predicate, for the refuter);
  - `check_law` (a hyp premise must name a modelled kind-hyp hypothesis whose parameter the law binds with the sidecar's type);
  - `splits` (holon-splits/0.1).
- **`holon/gen/machine.py`.** For M2+ facts with a sidecar, a facts call to a modelled parameter applies `ap_p` on the table, never a builtin (`Machine(.., oracles=)`). Without a sidecar the model is byte-identical to before: `gen/M0` and `gen/M1` are unchanged.
- **`holon/gen/mlaws.py`.** A `Fn<A,B>` binder named like a modelled parameter *is* that parameter:
  - it is emitted as its table, `for +p: List<&2, M.HO_p>`;
  - `{"app": p, ..}` becomes `M.ap_p(p, x)`;
  - every `run`/`step`/`obs`/`obsv`/`mig`/`runs_ok` term passes the tables that function takes, each the law's binder of that name (a statement that needs an unbound table is Unsupported);
  - `{"hyp": {"name": H}}` is rendered from H's predicate, each item emitted like any other premise (one `for hN:` line per equation).

  A Fn binder that is no modelled parameter keeps its I7 meaning (`L3_cf` unchanged).
- **Statement hashes (`holon/gen/refs.py`).** `law_hash(law, facts, oracles=None)`: a hyp premise adds ref `hyp:H`, the content hash of H's entry restricted to `{parameter, hypothesis}`. Editing HypD-pad restales exactly the two laws that name it. A not_in_scope entry, an instance, an instance doc and a ledger citation change no hash. `check_registry_multi` and `audit regress` pass the sidecar (at the commit, for regress).
- **Proofs (`holon/gen/mproofs.py`).** New class `param_premise`, for laws whose binders are all forall parameters. Once the model has run on the symbolic tables, only lookups `ap_p(p, x)` remain. So each conjunct is closed either by `{==}` or by a premise that is equal to it after computation. The candidates are `{==}`, `h0`, `h1`, .., and Bend picks (`mpipeline.param_search`, after the existing classes).
  - **No new lemma was needed.** For example, `got_of(step(post 1, s0, agg, dec)) == 1n` reduces to `ap_dec(dec, 9n) == 1n`, which is HypD-pad's `h0`.
  - `reach_invariant` refuses a model that threads tables (Unsupported, recorded).
- **Refuter (`holon/js/explore.mjs`).**
  - **Candidates.** For a parameter: the sidecar's concrete instances, in sidecar order, then the empty table. Instance values come from an *instance module*, the compiled model plus one `inst_<entry>` def per instance (`CompiledMachine.instance_module`). An instance that does not compile is not tried, and the run continues.
  - **Materialising an instance as a table.** The evaluation runs on an instrumented copy of the compiled model whose `$ap_p$` logs its argument (return values unchanged). It repeats with the instance's values at every logged point until no new point appears.
  - **Output.** `tables`, the table each witness denotes. The witness records `{"instance": <entry id>}` or `{"table": [...]}`.
  - **Counter-laws.** They supply that table, with the instance applied at each point (`inst_<entry>(k)`, defined in the proof from the template). So Bend re-computes the instance's values. Example, the witness of `L_orc_dec_exact`: `[HO_dec{1n, inst_dec_exact(1n)}, HO_dec{2n, ..}, HO_dec{9n, ..}]`. Points 1 and 2 are the premise's, and point 9 is the claim's query, found by the instrumentation.
- **Inhabitants (`holon/inhabit.py`).**
  - A parameter that a hypothesis premise constrains takes the instance of the entry whose hypothesis it is, and only that. A parameter no premise mentions takes the empty table.
  - The proof supplies the instance's table at the points the premises query (`premise_points`, static, so G11V can regenerate it from IR and witness).
  - When nothing else is left to search, the refuter is not consulted: Bend alone decides whether the instance satisfies the premises. In the canary, the inhabitant is built and rejected by Bend ("expected True{}, observed False{}"). A failed inhabitant on an instance records no witness.
- **Records.** For M2+ laws, `model_assumptions` is exactly the sorted set of hypothesis premises. The fixture ledger's abstraction entry meets every cone and is not listed.
- **Splits.** `holon run` writes `<out>/splits.json` for M2+ milestones. Laws pair when they name different hypotheses of one family, have the same facts file, and have equal statements once the family's hyp names are replaced by the family. The pairing reads statements, never ids.
- **`holon/oracle_check.py`.**
  - `validate(doc)` checks the holon-oracles/0.1 rules. G3 rejects a cf over `"*"`. Predicates must be ground IR 0.3 premises over the entry's own parameter and the IR equality builtins.

## Surprises

- **The term-size margin mostly measures BendTT's text format.** BendTT prints a Nat literal in unary. The stand-in's `exec_commit` entry carries `AGG_BASE = 1000` as 1000 nested `.Succ`: 15,474 of the stand-in's roughly 20,900 characters.
  - The parametric model has no such literal, because the instance is not in the model. That gives ratios of 0.30 to 0.34.
  - With `AGG_BASE = 1`, the ratio is 1.07 to 1.08. This was measured on a scratch copy of the facts, not a fixture, and is not a test. On this machine the parameters cost about 8% when the literal does not dominate: the table types, `ap_agg`, `ap_dec`, `eq_list_nat`, `ite` and the extra arguments, against the stand-in's `b_enc`, `b_pair` and Nat division.
  - The prediction holds either way. The preregistered measure is used as written.
- **A function parameter was impossible, as the prereg anticipated.** The table fallback needed no new lemma or proof technique. Once the model runs on symbolic tables, every claim of the fixture reduces by computation to `{==}` or to one of its premises, and Bend's conversion check does the rest.
- **Query points come from instrumentation of the compiled JS.** The refuter wraps `$ap_p$` in a logging shim, which relies on bend 2.0.36's JS backend calling recursive user defs by name rather than inlining them. If a later bend inlined them, the instrumentation is skipped (the patch must find exactly one definition), and tables would hold only the premise points. Bend would still decide every counter-law; only the `{"instance": e}` label could then overstate.
- **Single-point inhabitants are decided by Bend, not the refuter.** The first version let the (untrusted) refuter reject an instance that violates its hypothesis before any inhabitant was written. That is sound, but the contract says the inhabitant "does not check". Now, when only fixed instances remain, the inhabitant is generated and checked.
- **The scratch directory is shared.** The session scratchpad is shared with the agents running beside this one: another agent wrote into a subdirectory name used here. Work moved to a private subdirectory. No repository file was affected.

## Questions for the human

- **What does the hyp ref hash?** The contract says the ref of a hyp premise is the entry "restricted to {parameter, hypothesis}", and also that editing "an entry's instance or doc changes no hash". I hash `parameter` and the whole `hypothesis`, `hypothesis.doc` included. So editing a hypothesis' prose restales the laws that name it, while an instance doc does not. If prose edits should not restale laws, an amendment would drop `hypothesis.doc` from the ref.
- **The KZG entry uses hypothesis id `Hyp-Z0-kzg` and is `not_in_scope`.** KZG commitments are no model parameter. Meanwhile `results/M2/hypotheses.json` keeps I3's `checked` record for that id: the one KZG fact the models use is checked against the code. The test skips Hyp-Z0-kzg when it pairs sidecar entries with results, so both readings pass. Should KZG get its own hypothesis id instead?
- **`real_oracle` extends holon-oracles/0.1.** It is an optional entry key naming an implementation of the real oracle for A4 (only `keccak256` exists). The preregistered format does not forbid extra keys. Please confirm the extension, or name the field.
- **ISubmitter and messenger are `not_in_scope`.** They are stateful stand-ins kept inside the model, cited in `ledger`. Should either become a modelled parameter before I36?
- **G11V for M2+ inhabitants.** This predates I12. A gate process regenerates a proof without `mproofs.CORE_MODE` set, so the core import lines of an M2+ inhabitant would differ (I8). No M2 gate exists yet. The regeneration matches when the mode is set.
- **Merge note.** `spec/ledger/assumptions.json` gained an `encodings` section. Any branch that edits the ledger must regenerate `gen/M2/diagram` (I11 coupling).

## Not done

- **Laws mixing parameters with other binders.** Existing proof classes (`nat_split`, `noninterference`, `deadline`, `chain_revert`, `act_split`, `reach_invariant`) are not extended to laws whose binders mix parameters with states, traces, actions or Reach. Such laws stay UNKNOWN unless the refuter finds a witness.
- **The refuter's reach into parametric models.**
  - Reachable prefixes are explored with the empty tables. This is a heuristic: state witnesses are re-run from their traces under the candidate tables.
  - The parameter candidates are only the instances and the empty table.
- **Points that need computation.** Inhabitants whose premise points need computation (an oracle applied to a model term or to another oracle's answer) are Unsupported.
- **Other consumers.** The implication generator (I10) and `decide_negation` do not use `param_premise`.
- **No M2 facts or laws exist.** `spec/M2/lib/oracles.json` is checked (A4, G11V) but no model reads it yet.
- **The diagram still records HASH edges as coverage debt.** It does not read the oracle sidecar.
- **The sidecar is self-certified.** `spec/M2/lib/oracles.json`, `holon/oracle_check.py` and `holon/gen/oracles.py` are agent-writable until Q1.
