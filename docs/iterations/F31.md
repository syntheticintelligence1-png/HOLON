## Done

### a. The criterion, and why it is sound

A law's binding pins the BendTT kernel form of every definition its emitted statement reaches. The **roots** are the
model definitions the emitted statement names (`M.<name>`, with a constructor mapped to its datatype; this is the same
resolution `holon.bindings.kernel_cone` uses). A binding change leaves the meaning unchanged when every root is
extensionally the same, old and new:

- **Function root `f`:** `{Old.f(x) == New.f(x)}` for every input `x` of its parameter types, proved in the kernel.
  The parameter and result types must be the same datatypes on both sides.
- **Datatype root:** either its kernel form and its whole cone are unchanged, or, for an inductive family whose
  constructors' fields mention changed functions (`Reach<kh, s>`), `Old.T<i>` and `New.T<i>` are inter-derivable for
  every index `i`. That takes two transport laws, both proved by induction over the family.
- **Root with an unchanged cone:** nothing to prove. Its kernel forms are byte-identical.

**Why this is sound.** The emitted statement is a term built from its roots, Base, and law-local definitions. The
binding already pins the law-local definitions through `statement_sha256`, and a binding change must leave that hash,
`counter_sha256`, the statement hash and the model path unchanged. Replace each root by one that agrees on every input
(or, for a type used as a binder or premise, by an inter-derivable one). Then every instance of the statement is the
same proposition. Every proof, witness and counter-law transports both ways. Internal helpers may differ freely,
because only the roots' behaviour reaches the statement.

**What is not allowed.** Equality only on "realistic" inputs, on reachable or duplicate-free states, on byte-valued
limbs, by testing, or by a supplied proof. The statement quantifies over every value of its binder types (for
example `a: HAct` is unconstrained), so a root that differs anywhere changes some instance.

### b. The generator (`holon/gen/equivalence.py`, `holon/js/equiv.mjs`)

**One pair module, not two imports.** The task suggested importing both models under distinct module names. A probe
showed this cannot work: Bend's datatypes are nominal per module, so `{O.kw_set(..) != N.kw_set(..) : List<O.KW>}` is
refused with `expected : List<&2, N.KW> observed : List<&2, O.KW>`. The generator therefore writes one `pair.bend`:

- the new model, verbatim;
- every old definition and datatype whose kernel form differs from the new one, or that reaches one that does (the
  "dirty" set), renamed `o__<name>`. Constructors of a renamed datatype are renamed too, because Bend requires fresh
  constructor names per file.

Clean old definitions are shared with the new side, since their kernel forms are byte-identical.

**Linkage.** The pair module is tied to both models by the kernel itself. Its BendTT translation, with `o__` removed,
must give exactly the old model's entry for every definition of the old cone, and exactly the new model's entry for
every definition of the new cone. `statement_diff` compares those entries with the two bindings, so a proof about
the pair module is a proof about the two bound models.

**Files.** Each run writes these to a temporary directory; nothing is committed:
- `LAWS.bend`: only the root laws, `eq_<f>` and `to_<T>` / `from_<T>`;
- `PROOF.bend`: imports `LAWS.bend`; lemmas are typed defs `q_<f> : {P.o__f(x) == P.f(x)}`, plus a proved core block.

An obligation counts only when all of these hold:
- bend accepts it;
- BendTT `--verdict` accepts it;
- the law names are exactly the expected ones;
- no escape hatch appears in the pair module, the laws or the proof.

**Proof classes** (untrusted; the kernel decides; one per class of transformation):

| class | what it proves |
|---|---|
| `unchanged` | A root whose whole cone is byte-identical in kernel form. |
| `normalize` | Finite case analysis: every parameter of a finite type (Bool, enumerations, records of finite fields) is opened, then `{==}`. |
| `congruence` | Mirrors either side's match tree, optionally with multi-value wildcards split into constructors. In each leaf, every call of a changed definition already proven equal is rewritten (`%q_g(..) : motive`, innermost first; through `Equal.sym` for the old tree), then `{==}`. |
| `induction` | Congruence in which a rewrite is the definition's own recursive call, i.e. the induction hypothesis. |
| `... with Base identities` | Also rewrites Base facts proved in the core block by induction over `Word(n)`. Today that is one fact: `U32.add(x, 1) == U32.inc(x)`. |
| `family` | Transport of an inductive family both ways, by induction. Equality fields are rewritten with the function lemmas, recursive fields use the hypothesis. |
| `counter` | Refutation. The compiled pair module is run on generated inputs (fixed seed; values of a type are reused within a candidate, so keys repeat). At the first input where `o__f` and `f` differ, a counter-law `{o__f(W) != f(W)}` is stated and proved through a generated discriminator along the first differing path. |

Lemmas are attempted bottom-up: a changed definition is tried only once every changed definition it calls (through
unchanged helpers) is proven. Failures are attributed through bend's `Location:` line, and every class's kernel
message is kept.

**Determinism.** Iteration is sorted, the seed is fixed, and lemmas are emitted in proof order, so a repeated run
gives byte-identical output (tested).

### c. Wiring (`holon/statement_diff.py`, `holon/bindings.py`)

**Acceptance check.** An unsigned `binding_change` entry carries `milestone`, `bound_commit` and `defs`.
`_binding_change` re-derives everything and never reads a proof from the entry:
- `bound_commit` must be in HEAD's history;
- the law's binding at `bound_commit` is compared with `holon.bindings.bind_law` on the tree (new; `derive` uses it).
  Only the cone may differ, and `defs` must be exactly the changed definitions;
- the old model is read from git at `bound_commit`, following symlinks;
- both models' kernel entries must hash to the two bindings' cones, entry by entry;
- `equivalence.prove` must give PROVED.

**Acceptance record.** It holds:
- the generator name and `bound_commit`;
- the sha256 of both models;
- the kernels that checked it;
- the sha256 of the pair module, the laws and the proof;
- each root's class.

**Committed lines.** A committed line is verified against that record, never re-proved (F-M2-22). The old model must
still be the one at `bound_commit`, and the new one the file at the appending commit.

**Rebind tool.** `python -m holon.statement_diff rebind --milestone M [--append] [--report FILE]` builds the entries.
Each entry's `bound_commit` is the oldest commit, in HEAD's history of the bindings file, from which the law's binding
has had its current value. For M3 that is `2778fa0` (F30's rebinding of the I30 model). The model there was verified
against the binding.

`holon bind` and G2's change-log check already accept a `binding_change` naming every changed definition, and are
unchanged.

## Surprises

1. **Two imports cannot compare models.** Bend types are nominal per module, so `Old.KW` and `New.KW` differ. Hence
   the pair module and its linkage check. Constructor names must also be fresh per file, so renamed datatypes rename
   their constructors.
2. **Definition order matters once a file imports `LAWS.bend`.** A def that uses a later def fails with "expected : a
   filled definition (an unfilled law is a dead claim: live code cannot use it)". A lemma-only file without the import
   accepted the same order. Lemmas and discriminators are now emitted in dependency order.
3. **The rewrite direction.** `%e : P` with `e : {a == b}` needs `P[b]` to be the current goal and leaves `P[a]`. So the
   lemma `{o__g == g}` turns new calls into old ones, and the old tree goes through `Equal.sym`.
4. **The kernel prints full normal forms** in `expected` / `observed`. Opening `u_b4`'s argument into bits shows that
   the two sides differ only by `Bool.and(b_i, True{})` against `b_i`. Base's `Bool.and` matches on its first argument,
   so this is stuck. This is the hook for a future bit-blast class.
5. **The JavaScript runtime encodes `Bool` as a JS boolean,** not `{$: "True"}` as BEND_PRIMER §5.6 says (frozen; see
   Questions).
6. **The 1,300 changed definitions are mostly mechanical** (context binders opened, quantities dropped), and plain
   congruence proves them as soon as their callees are proven. Everything that is blocked is blocked by the 7
   UNKNOWN and 9 REFUTED definitions above.
