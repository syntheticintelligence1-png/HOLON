**B1. cosmos:004 was judged a duplicate against the protocol's literal definition; not changed.**
- **The definition:** the protocol defines a duplicate as "a fix of the same code for the same defect". cosmos:004's fix (`4effdd6f`, `modules/core/04-channel/keeper/packet.go`) changes different code from cosmos:007's (`9869b3c6`, `modules/apps/transfer/ibc_module.go`). The collector cited the advisory, which calls it an extension of the same patch from the same report, and named the doubt in its report.
- **The counterfactual:** under the literal reading, cosmos:004 is eligible and cosmos stops at cosmos:012. The selection would then take cosmos:004 into the corpus and drop cosmos:008 (c18).
- **Why the data stays:** the contract forbids re-running the selection after labelling, and the duplicate rule is a judgment channel (E-G1). So nothing was changed. Question 6 asks the human for a ruling.

**M1. c13's recorded fix is not the defect's fix; not changed.**
- **What happened:** the advisory of cosmos:007 names two commits. The frozen named-fix rule picks the earliest by committer date, `9869b3c6`, which removes the receive-path re-marshal check. The real fix of the described defect, `cc6fe556`, is the first parent of c13's pre-fix commit. So the defect is already absent at c13's pre-fix tree.
- **Effect on the predictions:** P4 still passes without c13 (7 entries).
- **Same rule, no corpus effect:** go-ethereum:009 (GETH-2020-01, a 2017 ethash commit) and optimism:001 have the same problem, but both are past_n.
- **Why the data stays:** this is the frozen rule working as written (E-G1 says it "picks the earliest named commit even when a source names a non-fix commit"). c13 is flagged here as invalid ground truth for I51. Question 7 asks whether to amend the rule before I51.

## Surprises

1. **Compound yields one entry.** Its 104 audit findings produced one eligible candidate. Most findings were never fixed in the public repository, and many fixes are outside the Go/Solidity reach (the 2019–2020 repository mixes Solidity with JavaScript tests and scenarios). The corpus's DeFi system is therefore represented by a single Solidity entry.
2. **The named-fix rule gives wrong fixes.** It picks the earliest named commit. Once in the corpus that means c13, whose defect is already fixed at its pre-fix tree, and twice more among past_n candidates (build review M1).
3. **No advisories for three systems.** The pinned advisory database holds none naming OffchainLabs/nitro, nitro-contracts, compound-protocol or wormhole, and one for ethereum-optimism/optimism. Those systems' candidates come from audit reports, where most findings are acknowledged and never fixed.
4. **Two entries share one fix commit.** c10 and c15 are two OPCMv2 findings fixed by one squash commit (`56ee47e5`). They have the same code and files, and different defects and labels (PAR and FACT). That is allowed by the protocol.
5. **The geth list's source.** The second prereg fold named ethereum/geth-website, which stopped in 2023 with 10 entries. The served list (12 entries) is on branch `website` of ethereum/go-ethereum, and the third fold pinned that.
6. **The bare CLI mode cannot authenticate here.** `claude -p --bare` fails to authenticate in this environment. The frozen invocation therefore turns settings, MCP, tools and slash commands off explicitly, and runs from an empty directory with the CLAUDE.md variables removed. The process still sees the date and its own working directory.
7. **Labelling was clean.** All 44 calls answered on the first try, and every response parsed.
8. **Instrument quirks the renaming stream found.** None affects the corpus.
   - The instrument decodes byte escapes in string literals (`\xNN`, octal) as Latin-1 code points, where the contract speaks of the value's bytes. Only non-ASCII words differ, and the tool follows the instrument.
   - The instrument's `sol_ast` decodes solc's output strictly as UTF-8. A `.sol` file that solc rejects, with a non-UTF-8 byte on the reported line, raises `UnicodeDecodeError`, so `check_renaming` would error for that entry whatever the tool does.
9. **A sealed-target name in a diff.** One ineligible wormhole fix commit, `9af1fac9`, mentions a `ChainIDScroll` constant in its diff, which the collector read. Nothing of the sealed target was opened, and its name appears in no record.
10. **Where the instrument deviates from the Solidity grammar.** The clean-room lexer (build review M2) shows three places where the instrument departs from solc 0.8.24's lexical grammar: `1ether`, `\v`, and CR in line comments and strings. None occurs in the corpus, and no test outcome depends on them.
