## The change

`holon/eval/holon_run.py` gets three functions: `store_scope`, `store_documents` and `commit_documents`.

- **Default `"evaluate"`, the behaviour of every earlier protocol:** a Go document over `store_max_bytes` is
  removed from the working tree right after extraction, as before.
- **`"commit"`:** nothing is removed during evaluation. The committed-output limit is applied once the entry's row
  is measured, after `law_rows` and `withhold`:
  1. `commit_documents` removes each document that is not stored from `<id>/facts/`, keeping the whole document in
     the vault.
  2. `store_large` then records every other file over the limit in `large_files.json`, as before.
- **Any other value is refused.**

The ordering was found by the planted P2 test while building, before any measured run. In the first build,
`store_large` still ran before `law_rows` read the committed records, so a record over the limit read as UNKNOWN,
and a limit on the committed output still moved the measured aggregate. Under the opt-in, no field of the row depends
on the limit except `stored`.

`holon_run.py` is in no generator closure (`holon.records.generator_files`, every IR version), so this key needs no
re-stamp.

## Soundness

The change moves no law toward PROVED by itself. It only lets every stage read the document that extraction already
wrote, byte for byte the document a run without the limit reads. P2 checks this on the planted entry: the derived
laws, the aggregate, the bundle commitment and every committed byte are identical on either side of the limit.

Every law is still decided only by derive, bind and run and by the checker, whose word is final. Every REFUTED still
needs its replay. The new failures are stage crashes, which leave laws UNKNOWN (weaker, never wrongly PROVED).

What is committed is decided by the limit exactly as before: a document over it is committed by sha256 and bytes
only, and every other file over it goes in `large_files.json`. The record therefore never holds what the limit
excludes. The full documents stay in the run's working tree and the vault, outside the repository.
