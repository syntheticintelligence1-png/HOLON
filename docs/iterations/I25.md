## Surprises

1. **I25-P5 misses: the frozen `core_inj_push` has no proof in Bend 2.**
   - **The cause.** The statement binds `for -X: Type`, and Bend's `Type` is `Kind(&1)`: a value `x : X` is affine. The pushing direction must apply both `cf` and `e` at the same point, `x => cf(x, e(x))`, so it uses `x` twice.
   - **Bend's verdict.** bend2 rejects it (`x (consumed more than once)`). `bend --verdict` stops with the same message, because bend2's front end runs before the kernel and fails first.
   - **Why `+x` does not help.** A reusable binder needs `Data`: `+x => …` gives `expected : Data, observed : Type`, with the note "+x can be used many times, so its type must be Data".
   - **Every other route also consumes x twice.** A rewrite with `e(x)` (`%e(x) : …`) is checked at the same demand (bend2's check-rwt, `bend.ts`). An erased lambda does not fit the relevant claim `@x:X`. Equation evidence is erased (`{a == b}` is `Data`), but the variable `x` is not.
   - **The theory explains it.** In an affine theory, `λx. cf x (e x)` is contraction on `x`, which the theory does not have. The lemma is true as mathematics, and the statement was only ever checked as well-typed at the prereg ("no proof was attempted").
   - **The rest of the core.** The generated proofs of `core_inj_pull` (whisker) and `core_cf_succ` (successor injectivity) check in both kernels.
   - **What a restatement would give.** With `for -X: Data`, the same generator emits `+x => cf(x, e(x))`, and all three laws check in bend and `bend --verdict` (a scratch run, not committed).
   - **No restatement here.** That restatement narrows the law to duplicable X, so it is a weaker statement, and AGENTS rule 2 forbids editing law statements. The committed `core/PROOF.bend` therefore holds the generated attempt, and Bend rejects it. The core law is not PROVED.
   - **The canary.** Its test passes only because removing `cf` leaves `cf` unbound. With the base proof rejected, that result carries no information.
2. **I15's rule-code honesty check forbids the contract's own key.**
