## The rules, as implemented

- **The packet** is `truth_prompt.md` with its one `{{TEXT}}` slot replaced, in one pass, by the entry's text. Nothing else goes in. The packets of roles a and b of one entry are byte-identical; each is pinned on its own.
- **The answer** is the labeller's final message: one JSON object, the whole message or the whole message inside one fenced block (I48's `parse_response`).
  - The shape check needs exactly the three questions, each exactly `{value, quote}`, with value a string and quote a string or null.
  - A value outside its list is not a shape error. Q1 makes it undocumented, so it does not buy a retry.
- **Q1:** a value outside its list, or a non-null quote with undocumented, makes that answer undocumented.
- **Q2:** a quote that is not a string, or whose whitespace-collapsed form is not a substring of the text's collapsed form, makes that answer undocumented.
  - Collapsing replaces each run of Python's `\s` with one space. Nothing is stripped, and case, punctuation and Unicode are exact.
  - A non-undocumented value with a null quote fails Q2.
- **Q3:** the final value is a's only when both labellers answered, both pass Q1-Q2 and they give the same value. Otherwise it is undocumented. There is no adjudicator. Every disagreement and every rule failure is listed in the run sidecar and is never resolved.
- **The derivations:** `l6` and `l10` exactly as the protocol's `derived`.
- **The retry rule** is I48's, with this protocol's answer.
  - An attempt that gave no answer (`cli_error`, or `no_response` for a session) is retried, at most 5 times.
  - An attempt that is not an answer (`turns`, `unparsable`, `invalid`) is followed by exactly one more.
  - The answer is the last attempt's when it is ok, else null, and then every question is undocumented.
  - A retry is a new fresh process or session, never a follow-up message.
- **c13** is labelled like every entry. The protocol's `known_exclusions` removes it from scoring, not from labelling.

## How many labellers

The protocol's independence rule (I48's `labelling_invocation.process`) is one fresh process per prompt, where a prompt is an entry and a role. So **the labelling takes exactly 40 fresh labellers: 20 entries times 2 roles.** No labeller may see two packets.

## Runbook for the coordinator

From a checkout of this branch, with Python 3:

**Path 1, protocol-exact (recommended).** This is the frozen invocation: 40 tool-less `claude -p` processes and no cloud session.

```
python -m tests_m5._i54b run --role a --model <A: the family's most capable model>
python -m tests_m5._i54b run --role b --model <B: a smaller model of the same family>
python -m tests_m5._i54b collect --family same
```

- Each packet goes to its own fresh process, with `labelling_invocation`'s argv, system prompt, environment and timeout. It gets the packet on stdin and a fresh empty directory under `/tmp`.
- The model each call reports is checked per tag outside the repository (`~/.holon/eval/truth_labellers.json`): `one_model_per_role` and `a_differs_from_b`.
- Model names never reach the repository.
- `run` resumes: an answer file that is already finished is left as it is.

**Path 2, cloud sessions (a disclosed deviation).** These are 40 fresh cloud sessions, one per packet file `spec/M5/truth/packets/<id>.<role>.txt`.

1. Create each session with no repository. Give the role's model (A for `.a`, B for `.b`), and append `labelling_invocation.system_prompt` to the system prompt. Its first and only message is the packet file's exact bytes.
2. Save the session's final message verbatim to a file, then record it:

   ```
   python -m tests_m5._i54b answer --family same --invocation cloud_session --entry <id> --role <a|b> --session <session name> --response-file <file>
   ```

   Use `--no-response` instead of `--response-file` when the session gave no final message.
3. If the command says "the retry rule needs another fresh session", launch a new session for that packet and record its answer the same way.
4. `python -m tests_m5._i54b status` lists what is still missing.
5. Then run `python -m tests_m5._i54b collect --family same`.

**After either path:**
- Commit all 40 answer files and the two outputs **in one commit** (T5 checks this), and only after all 40 are recorded.
- The outputs are `spec/M5/truth/corpus.json` (the protocol's output path) and `spec/M5/truth/corpus.run.json`.
- Until then, no answer is pushed. Otherwise a later labeller could read an earlier one.

**Different family (Q9a), only if the human runs one.**
- The external agent reads the same 40 packets, with one fresh context per packet and no repository access.
- Record its answers with `--family different --invocation external`.
- Run `collect --family different`, then `compare`. This writes `corpus_different.json` and `family_comparison.json` (`"pooled": false`).
- The same-family file stays the protocol's truth. The other is reported beside it.

## The collector

`collect` refuses, writing nothing, unless all of these hold:
- every frozen input hashes to its pin;
- each of the 40 answer files passes the schema, its path, its role tag, its invocation for the family, and its packet path and `packet_sha256`, against both the pin and the packet file's bytes;
- every attempt's outcome recomputes to what is recorded;
- the attempts follow the retry rule;
- `answer` is the last ok attempt's parsed message.

A missing file or a stray file is a refusal. The output is deterministic: canonical JSON, sorted, no timestamps.

The run sidecar records:
- the invocations, and `protocol_exact_invocation` (true only when every answer came by `cli`);
- `model_check`: observed for `cli`, declared for sessions;
- the disagreements, the rule failures and the empty quotes;
- the l6 and l10 tallies;
- every answer's outcomes and file sha256.

## The adversarial phase

I ran it myself, with no subagent. Most of it ran before the freeze and was folded into the prereg; I re-ran it after.

**Leaks through a packet:**
- **What T2 checks.** Each packet is exactly the template plus the text. No field of the entry other than its title and description reaches a packet, unless the verbatim text itself holds it: id, candidate, repository, fix and pre-fix commits, fix date, files, source URLs, I48's labels and their justifications. Neither does `HOLON`, `spec/`, or an iteration name.
- **The verbatim texts hold what they hold.** c04, c14 and c19 carry a link to their GitHub security advisory, and most texts name their project. Under the frozen invocation the labeller has no tools, so the link cannot be opened.
- **Cloud sessions are not tool-less.** A cloud labeller could open those advisories, and it could reach the account's repositories, so it could read this repository. That is why path 2 is a disclosed deviation and path 1 is recommended.
- **Labels through the repository.** An answer committed before every labeller has run would be readable by a later labeller on path 2. It would also be readable by a different-family agent with repository access. Folded: the 40 answer files of a family land in one commit (T5), and a different-family labeller is never given repository access.

**Every quote rule fails when it should**, on fixtures and on the 20 real texts:
- Q1: a value outside the list, wrong case, a quote with undocumented.
- Q2: a paraphrase, a case change, added punctuation, a null quote with a value, a quote that invents a space. Each of the 20 texts accepts a verbatim excerpt and rejects the same excerpt with one character changed.
- Q3: a disagreement, one labeller failing Q2, a missing answer.
- The derivations, exhaustively over all 12 (trigger, actor_flow) pairs and all 3 doc_contradiction values.

**The collector refuses:**
- a changed packet hash, entry, tag, invocation, outcome, answer or packet path;
- an extra field;
- an attempt after ok;
- a changed packet byte, a changed corpus, a changed prompt;
- a missing or stray file.

**The runner** was tested with a stubbed CLI. A garbage reply is retried once, and a timeout waits 60 s. The same model for A and B is refused, and so is a call that reports two models. No model name appears in the answer file.
