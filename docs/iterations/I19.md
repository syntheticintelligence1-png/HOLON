## Done

### Storage families (`holon/frontends/solidity/storage.py`)

Storage comes from the compiler: a sidecar with `"transitions"` makes `compile.py` select `{"*": {"*": ["storageLayout"], "": ["ast"]}}` (a layout sidecar keeps I17's AST-only selection, so `morph_header.extracted.json` is byte-identical). A family is a state variable the contract declares itself, in declaration order, with the compiler's `slot` and `offset`, `kind` scalar / mapping / array, the mapping `key`, the `value` type label, `width` = 8 × `numberOfBytes` for an elementary value, and `fields` (name, type, width) for a struct value. Constants and immutables are not storage. The contract's own constants are folded from the AST (I17 W4, plus `keccak256` of a literal) and written as `0x`-hex (bytesN, address, literals) or decimal strings.

Rollup: 24 families at slots 151–174, names, kinds, types and widths as P1 lists; `constants` = `{EIP1967_PROXY_ADMIN_SLOT, ZERO_VERSIONED_HASH}`.

### Transitions (`holon/frontends/solidity/transitions.py`)

One structured symbolic walk per external or public function the contract declares (29 for Rollup, `receive` included under its kind's name):
- modifiers inlined in order (`_` walks the next modifier, then the body), internal, private, public and library-internal calls inlined with virtual dispatch over the contract's linearization, storage pointers bound by reference;
- both branches of every `if` walked, then before else, under the branch condition; locals, storage and memory merged after the `if` into `["?", c, a, b]`; a branch that always reverts contributes nothing to the merge; a branch that may leave by `return`, `break` or `continue` puts the condition under which control goes on into the context of what follows (early returns of inlined functions are merged into the caller's value and state);
- storage as a functional store: a read is `["storage", f]` (with `["map", …]`, `["member", …]`, `["index", …]` paths) before any write, the written value after a write of the same path, `["store", base, path, v]` when a write may alias;
- memory as I17's regions (W5), with writes kept per region: `mload` resolves to the stored word or, over a `calldatacopy`, to `["word", input, k]`; `keccak256` over a region that is exactly an input's copy is `["keccak256", input]`;
- loops: a dry run that records nothing finds what the body writes; locals it changes become `["phi", loop, name]` (pointers keep their region), written families `["phi", loop, ["storage", f]]`, written regions get a `["loop", span]` entry; then the body is walked once, recording;
- Yul: I17's subset plus `sload`, `blobhash`, `YulIf`, `revert`/`invalid` and a few environment builtins; `YulForLoop`, `YulSwitch`, Yul functions and other builtins are debt (`unsupported`), what they assign is havocked to `["unknown", span, name]`.

Per action: `selector`, `src`, `modifiers`, `principal`, `guards` (first reach, one per span; `expr` carries the branch context: `["||", ["!", K], c]` for a require under K, `["!", K]` for a revert), `effects` (sorted by (src, family) as strings), `cost.terms`, `edges`. The document is canonical (184 797 bytes) and byte-identical across runs; `assumptions` names A-env, A-implicit, A-loop, A-reentrancy and A-span.

### Coverage and G8 (`holon/coverage.py`)

`python -m holon coverage --milestone M2` re-runs the walk of every statement-accounting sidecar (the frontend's `coverage_document`) and writes `gen/M2/coverage.json`. Statements are every Solidity Statement node in the bodies of the actions and of every function and modifier they reach. Extracted: the walk used the statement for a guard, an effect, a cost term, an edge or a principal, or it is control flow, an inlined call, or local computation whose local is read by a walked statement (or is a return variable, or writes memory). Debt: `external_call`, `value_transfer`, `loop_storage_write`, `unsupported` (with the node type). Anything else, including a statement the walk never reaches, is unaccounted. A probe contract (unused local, a statement after `return`, a bare expression statement) gives exactly those three as unaccounted.

   The order part of P2 holds in every action. Nothing was changed to make P2 pass.
2. **R1 miss, on both roles.**
   - `header_length`: the frozen role takes the Solidity value from the loader edge `load_sol`, whose version-0 ok path accepts every length ≥ 249 (`len >= 249` in `morph_header.extracted.json`), while Go's `validate` accepts exactly 249. Read exactly, the accepted pairs differ: this is the M0 finding `L_dom_hdr` (REFUTED: a 250-byte version-0 header, Solidity true, Go false), found again by the linker from two extracted documents. The encoder edge `enc_sol` has lengths 249/257/257 and would agree; the role does not name it.
   - `zero_versioned_hash`: the Go value is not in any extracted document. I18's contract excludes package initializers, so `morph_genesis.go.extracted.json` holds `["global", "…genesis.emptyBlobVersionedHash"]` references and no value (`common.HexToHash("0x0106…")` lives in the package initializer; `HexToHash` is not among the sidecar's primitives either). The prediction's premise "the values are already recorded in the I17 and I18 documents" is false for Go's Z (and for Solidity's Z, which is first recorded by this iteration's rollup document). The link is reported with `go: null`, `equal: false` (an explicit unlinked assumption, §7.7 step 5).
3. **P5 depends on a boundary I kept from I17.** `_computeBlobVersionedHash` (reached by commitBatch and commitBatchWithProof) holds a Yul `for {} 1 {}` loop over `blobhash(i)` (:901–908). I17's W7 leaves `YulForLoop` outside the walker, and I19's cost terms are for Solidity loop statements, so it is `unsupported` debt, the loop's assignments are havocked (the guard at :913 reads `["unknown", "…Rollup.sol:901-908", "i"]`), and the `blobhash` inside it is not an edge. Had Yul loops been walked like Solidity ones, the two actions would have a second cost term (with no derivable bound) and P5 would miss. I decided the boundary from I17's contract, not from P5, but the outcome depends on it.
4. **One entry per span loses a second load's checks.** commitBatchWithProof loads two headers through `_loadBatchHeader` (the parent at :402, `_batchHeader` at :414). Their requires share spans, so the guards keep the first reach (the parent's) and the second header's length/version checks have no entry of their own (A-span). The contract fixes one entry per span.
5. **Terms can be large.** commitBatchWithProof's guard at :418 (`committedBatches[index] == batchHash` after the action wrote `committedBatches[parent + 1]`) is 5 436 characters: the store of the new header's keccak, whose memory term lists the header's 11 writes (12 for versions 1 and 2) under both version branches. It is exact; the next largest guard is 426 characters.
6. **Events are debt.** 30 of the 43 debt entries are `EmitStatement`: the document has no place for events, so the walk does not represent them. A local read only by an event counts as feeding it.
7. **Effects order.** "sorted by (src, family)" is applied to the strings, so `PausableUpgradeable.sol:107` sorts before `:95` in setPause.
