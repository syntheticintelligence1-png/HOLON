## Done

### The lane (`python -m holon intent atomize|compile|requests|run|metrics`, each with `--check`)

- **Atomizer** (`holon/intent/atomize.py`, scope from `holon/intent/scope.py`). NatSpec `///` runs and `/** */` blocks, and Go doc comments, cut at tags and blank lines, then into sentences (abbreviations kept whole). A sentence is an atom when it holds one of 38 markers, with a noun-use filter: a verb marker right after a determiner (`the revert request`) does not count. Each atom records its pieces: per line, the raw column range its characters came from. `tests_m5/_i55.span_problems` rebuilds every atom's text from the file at its commit.
  - **82 target atoms** in the census's scope (the lane recomputes the scope from the facts documents at I54's base; it equals the census's). 12 control atoms.
  - Against the census: one atom is not in it ("... is allowed;", batch_storage.go:257, a marker the census lacks); one census clause is not met ("@notice The index of the revert request.", the noun-use filter's intended drop, a false positive I54 named).
- **Independence (the lead's G2(a)), checked three ways by A3.** The atomizer's static closure has no `holon.m5` module and no file naming the census. Under an audit hook its run opens, passes and writes nothing naming `l10_census`. In a git worktree of HEAD with the census deleted, it writes identical bytes. A4: compile and run never open a control's `.json` (its truth) or the census, and no module of `holon/intent` names `right` or `wrong` (control file stems carry the truth).
- **Compiler** (`holon/intent/compile.py`). Three templates (bound, access, monotone), each an English pattern. A match compiles only when:
  - the file is Solidity;
  - the comment documents a function;
  - the factory's own frontend (`holon.frontends.solidity`, a generated transitions sidecar) extracts the contract;
  - the clause's nouns bind to that contract's own names (a parameter, an address or uint scalar);
  - the lane model supports the actions.

  Every law names exactly one atom. Outcomes are in `results/M5/intent/compile.json`. Target: 79 no_template, 2 decl_not_function, 1 not_solidity.
- **Model** (`holon/intent/model.py`). Generated from the extracted transitions document over the factory's 256-bit word prelude (`holon.sorts.prelude3`). It defines St, X_a, chk_a, post_a and ret_a. Checks follow `holon.machine.build_program`'s order. Checked arithmetic uses the fits-256 panics.
- **Runner** (`holon/intent/run.py`).
  - **Proof classes.** First computation, then bool_cases: the statement's Bool atoms, with chk unfolded, are abstracted into a lemma proved by exhaustive match and then instantiated.
  - **Refutation.** A witness search over the compiled model (bend → mjs → node). Its counter-law form is accepted by both kernels (Surprise 2).
  - **Q22.** PROVED and REFUTED need BendTT's acceptance too.
  - **Checks on every PROVED law (TT).** A twin, with the action functions turned into binders, and an inhabitant.
- **Review (W2).** `results/M5/intent/review_requests.json` gives each law its clause, the declaration it documents, a plain reading and the statement. It carries no control id and no truth. **Exactly one fresh reviewer** (a subagent of the builder's family, E-I4) got only the pinned prompt and the requests, and answered once: 12 of 12 faithful. The answer is recorded verbatim in `spec/M5/intent/reviews.json` with its disclosure.

2. **Truth leak by file name.** A control's file stem holds `_right_` or `_wrong_`. The lane takes an id only as an opaque label, and A4 forbids either word in `holon/intent`.
3. **Truth by reading.** The design (S0, I2) says the lane opens a control's `.sol` only. Only the metric stage reads the `.json`.

## Surprises

1. **P7 missed: the denominator.** I predicted "0 of 2", thinking only of the PROVED control laws. The key's TT definition (and the pinned instrument) counts every control law that passes W1 and W2, and W1 admits REFUTED. So the share is 0 of 8. The numerator held.
2. **BendTT rejected the bound counter-laws twice. Both fixes are in the generators (Q22).**
   - First, `w_div`'s 256-step long division exceeded BendTT's budget. The lane now divides by a literal below 2^16 limb by limb (`w_div_small`, `w_mod_small`), as the factory's M3 generator does (`holon.sorts.model3` t_div).
   - Second, the primer's motive `is_true(Bool.not(_))` reduces the statement under the hypothesis's open context (I89's kernel behaviour 4). Each part of the statement checked alone in both kernels, but the whole counter-law did not.
   - The generator now emits a closed value lemma `{holds(W) == False}`, rewrites `e` with the motive `{_ == False}`, and ends with `ip_is_true(_)`. No motive reduces the statement.
   - Before these fixes the two bound-wrong laws were UNKNOWN with "a blocking cross-kernel disagreement" recorded. bend2 alone accepted them, and Q22 forbids bend2-only refutations.
3. **The computation class timed out** (180 s) on the fee laws: symbolic division. A timeout's place depends on the machine, so attempt texts now say "not accepted" without the marker. That keeps records byte-identical across machines.
4. **One amendment (`spec/M5/amendments/I55.jsonl`).** After I merged the lead (`f32c206b`), R2's test (`git diff base HEAD` over the M0–M4 paths) named four files that the lead changed. Each is byte-identical to the lead's. The test now walks HEAD's first-parent chain: an I55 commit may change none of the paths, and a merge may bring only its second parent's bytes. The claim and the path list are unchanged.
5. **The target compiles nothing**, and P8 predicted it. Its 82 clauses are mostly about Go off-chain code (69) and system behaviour. Of the three that match a template, two document a modifier and one is Go. The lane models Solidity functions only.

## Questions for the human

1. **O10's drift candidate.** Rollup.sol's `_computeBlobVersionedHash` doc says "At most one blob is allowed: extra blobs are ignored by this hash but would still be delivered to L2 derivation". The V0/V1 path has `require(blobhash(1) == bytes32(0), "legacy batches support exactly 1 blob")`, which rejects extra blobs rather than ignoring them. I read it as documentation drift. No template covers it, so it is not mechanized. Should a later key add a template, or record it by hand as an intent question?
2. **Modifiers.** "Only an active submitter is allowed." and "Only challenger allowed." document modifiers. Should the access template bind a modifier to every action that uses it? That would be laws over the M3 Rollup model, which the lane's model cannot express (mappings, external calls). The expected result is a trivially-true law, because the modifier's guard is its own definition: exactly what the TT share is for.
3. **BendTT's mismatch message.** Should the factory carry the closed-value-lemma counter-law form (Surprise 2) back into the primer (§5.4), since the primer's motive fails BendTT on non-trivial statements?
