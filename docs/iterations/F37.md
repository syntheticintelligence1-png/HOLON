The rewritten functions are `kappa`, `final_label` (new: the contract names an instrument function), `build`, `_read_labels` and `cli_agree`.

`holon/eval/label.py::parse_response` was also rewritten clean-room, from the prompt templates and `labels.schema.json`. It had the highest similarity in the I48 build review (0.94).

**Definitions used** (they are stated in the module docstring):
- Rows of the table are a's labels, columns are b's, over all nine categories.
- p_o is the diagonal's share of n.
- p_e is Σ row·col / n².
- kappa = (p_o − p_e)/(1 − p_e). It is undefined when n = 0 or p_e = 1.
- se is Cohen's large-sample error, sqrt(p_o(1−p_o) / (n(1−p_e)²)).
- ci95 is kappa ± 1.96·se.
- The final label is the shared primary if a and b agree, else the adjudicator's.
- Every statistic is computed exactly, using fractions, and 50-digit decimals for the root and the interval. It is then rounded once to the nearest float.

### 2. Labelling separation: model identity and role stored per call

**What is recorded.** `holon eval label` now writes `spec/eval/labels/<role>.calls.json`, validated against the new schema `spec/eval/label_calls.schema.json`. It holds one record per call:
- entry and attempt index;
- role, labeller and tag;
- session_id and outcome;
- `models_reported`: the keys of the call's own CLI JSON `modelUsage`. These are the models the runtime says the call ran on, never the `--model` it was configured with.

**Why a separate file.** The preregistered `labels.schema.json` sets `additionalProperties: false` at every level, so the label file cannot carry the field.

**The protocol conflict.** The frozen protocol (`labelling_invocation.recorded`), gap E-G2 and `prompts/I48_eval_corpus.md` all say model names are never recorded in the repository. One append-only line in `spec/M4/amendments.jsonl` names this extension (kind `recording_extension`). It is additive: the label files, tags, checks and assertions are unchanged. See Question 1.

**The 44 existing calls are unchanged.** No per-call record was made or reconstructed for them. They still carry only what I48 recorded. That includes the one inherited session id `36cc748b-…` on all 44 attempts (counted from the label files).

**Shown offline, no paid call.** A scratch driver (`b2-f37/demo_calls.py`, not committed) ran `cli_label` for all three roles over a 3-entry copy of the corpus. The CLI and the fix diff were stubbed, and one call returned a cli_error.
- Each call was recorded with its role, tag and reported model.
- The cli_error call was recorded with `models_reported: []`, and its retry with the model.
- The files validated.
- `agree --root` built the corpus from them.

## Surprises

1. **Four recorded responses are not "exactly one JSON object and nothing else".**
   - **What.** Labeller a on c14 and c19, and the adjudicator on c05 and c12, answered inside a ```` ```json ```` fence. I48 recorded all four as `ok` on the first attempt, and its Surprise 7 says "every response parsed". So the instrument's `parse_response`, and I48's old one, accept fences.
   - **Which side the contract favours.** The contract defines "parses" only by naming the instrument function. The text that does exist favours the strict reading: the prompt asks for exactly one JSON object and nothing else, and the protocol makes "parses" the test of format. Under that reading, each of these four attempts was `unparsable`, and the retry rule required a second counted attempt.
   - **Effect if strict.** a's c14 and c19 labels, and the adjudications of c05 and c12, would not be protocol labels as recorded. c05 and c12 are 2 of the 4 adjudications, and c14 and c19 count as a/b agreements in kappa.
   - **What was done.** Nothing in the data was changed: labels are never edited or re-run. holon keeps the strict parser. It affects only future labelling, where a fenced answer is retried. This is Question 2.
2. **The one-ulp drift.** The previous agreement floats were not correctly rounded (see the table). No assertion is affected.
3. **The tests clone large repositories.** A whole-module run of the I48 tests starts fetching the advisory database and the entries' repositories into `~/.holon/eval/` at once. The run was stopped at `test_holon_verify_agrees`. The 538 MB it had made was removed afterwards (`~/.holon/eval/` did not exist before the run).

## Questions for the human

1. **Model names in the repository.** The lead asked for the model identity per call. The frozen protocol and prompt say names are never recorded. The amendment line records them in `<role>.calls.json` from F37 on. Is that acceptable? The alternative is to store a keyed digest per call, with the key outside the repository, which shows separation without naming the models.
2. **Fenced answers.** Is a response wrapped in a Markdown code fence "one JSON object and nothing else"?
   - If not, the four labels in Surprise 1 are not protocol-compliant.
   - If so, the protocol needs one amendment saying so, and holon's parser follows the amendment, not the instrument.
3. **The inherited session id.** All 44 calls carry one `session_id`. The frozen invocation passes the build's environment minus two variables, so the CLI likely inherits the parent's session identity. Should a later labelling run also remove that variable? That is a change to the frozen invocation.
