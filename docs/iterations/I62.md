## Surprises

1. **P1 missed on its own-input clause, for a path-only reason.** The baseline's M0 own-input hashes differ from
   I61's for all 8 M0 laws. The M1x and M2 hashes are equal.
   - **Cause.** `holon/mutate/m0.py` keys the M0 facts by `PROJECTION_KEY = C.PROJECTED.as_posix()`. That path names
     the key: gen/M2/mutation_i62/header.projected.json, where I61 had gen/M2/mutation_i61/.
   - **Evidence.** I recomputed the cones with `holon run --milestone M0` on a scratch copy of the projection. With
     the same statement, projection bytes and cone, `own_input_sha` gives I62's committed hash under I62's path. Under
     I61's path it gives I61's committed hash. This holds for each of the 8 laws.
   - **What it changes.** No decision. A mutant's `changed` flag compares with its own key's baseline. The forecast
     missed it. I did not change the test.
2. **P5's claim text miscounts I61's list.** It says "I61's 82 mutants plus these five (87)". I61's summary lists
   80, so the list is 85. The check, which compares the lists themselves, holds.
3. **F35 sits between the two pipeline commits, and F38 came after the run.**
   - **F35** changed the timeout handling in `holon/bend.py` and the M3 equivalence-proof helpers. It is not an I62
     change. The review found that it changes no decision rule of M0, M1x or M2 (soundness advisory 9), and no
     record moved outside the fixes.
   - **F38** reached the integration branch while the 242 mutants ran, and I merged it into this branch after the
     report. It changes how the checker runs (its stack, in its own process), G2's signature check, and which proofs
     each gate re-runs. It is not in P, so no I62 record was computed with it.
