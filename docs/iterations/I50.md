## What happened on the held-out target

1. `holon target derive --target scroll` wrote the sidecars by rules Q1-Q4 (`gen/targets/scroll/lib/`). It then ran
   the milestone's own first step, `holon sorts --milestone T50`. The pinned sort pass refused the document:

   ```
   holon sorts: gen/targets/scroll/facts/ScrollChain.extracted.json: commitAndFinalizeBatch (writes[1]): term 'update' has no sorts rule
   ```

   - `update` is a documented term of the pinned Solidity frontend: `["update", base, target, v]`, a write into a
     member of a memory copy of a storage struct (`holon/frontends/solidity/transitions.py`, line 79). ScrollChain
     uses it 316 times, in `commitAndFinalizeBatch` and `finalizeBundlePostEuclidV2`. The pattern is
     `ScrollChainMiscData memory cachedMiscData = miscData; cachedMiscData.x = ...; miscData = cachedMiscData`.
   - The development target's documents never use it, so `holon/sorts/extracted.py` (`ExtractedError`, line 500)
     has no rule for it.
   - It is the only gap of this kind. Every other term head in the held-out document is one the development target
     uses, or one the sort pass handles (the new `^` among them).
2. The refusal is the derivation's outcome. It is recorded in `results/targets/scroll/derive_refusal.json`, and
   `holon target derive --check` reproduces it byte for byte. No law exists, so:
   - `holon target run` decides nothing: `results/targets/scroll/records/summary.json` is `{}`;
   - `results/targets/scroll/replay.json` has no entry;
   - the size report's held-out row is `pending` with the refusal's text.
3. **Nothing was changed to make it pass.**
   - `holon/sorts/extracted.py` is record-pinned. A rule for `update` would move the generator digest of every
     committed M3 record (I49-R1 and I50-R3 forbid that).
   - It would also be a post-seal change to the machinery every producer of the pinned catalog stands on, made after
     seeing the target, which the seal protocol forbids counting.
   - So the gap is coverage debt with its reason. It is not excluded, and it is not worked around.

## Surprises

1. **The first foreign construct stops the whole typed pipeline.**
   - The extraction (I49) went cleanly. Then the typed machinery, which every producer of holon-rules/1.15 except
     PAR stands on, refuses the entire document because of one term in two actions.
   - The sort pass is all-or-nothing per document: an unknown term raises, and nothing is derived.
   - This is the strongest generality signal M4 has produced so far. The factory's later stages were fitted to the
     constructs Morph uses.
2. **The prereg's predictions assumed the route would run.** None of the five allowed for a refused first step. A
   prereg for a foreign target should predict whether each stage runs at all, before predicting what it outputs.
3. **The development-target dry run hid the gap.** On Morph's document the same route gives 125 laws. The route is
   sound where its inputs are familiar, which is exactly what a held-out target is meant to test.

## Questions for the human

1. **A sort rule for `update`.** Should the sort pass get one (a member write into a struct value: the sort of the
   base, with the member's sort), and with it whatever else the typed producers need for the term? It is a change to
   record-pinned files (`holon/sorts/extracted.py` and likely `holon/sorts/model3.py`), so:
   - every M3 record's generator digest moves, and they must be re-made;
   - on this target it is a post-seal change, so a held-out run after it carries the contamination caveat and needs
     a new key.

   The alternative is to accept the refusal as the held-out result.
2. **A deployment for the held-out target.** Even with a derivation, `binding: null` gives Reach the zero storage, and
   no witness can be replayed. Building a deployment harness for the target (constructor immutables, proxy,
   initialize) is target-specific code written after the seal. May a later key do it, labelled?
3. **The sort pass refuses a whole document over one term.** Should an unknown term become coverage debt on the
   action that holds it (leaving that action's laws underived) instead of a refusal of the document? That is a
   change to the pinned machinery too.
