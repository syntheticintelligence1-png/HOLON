## Done

- **Schema and hash.** `spec/schemas/law_ir_0_3.schema.json` extends 0.2: hashed `rule_catalog_version`, `Fn<A,B>`, `Bytes(n)` and `Reach` binder types, the `app` term, premises `cf` (finite set), `hyp` and `neq`, `statement.scope`, structured `maps_to`.
  - `holon/ir.py`: the 0.3 statement hash covers `{ir_version, law_id, rule, rule_catalog_version, statement, refs}`. Notes are not hashed. 0.1 and 0.2 hashes are unchanged (24/24).
  - `holon/gen/refs.py` computes `refs`: each definition the statement names (observer, migration, action, consumer, builtin, `s0`, `step`), mapped to the content hash of its source entry in the fact document, never the whole bundle.
- **Premise rules.** `ir.check_premises` rejects a `cf` premise over a non-finite set (`"*"`, empty, missing) and a `cf` over a name that is not a `Fn` binder. The pipeline does not run such a law, and G3 now applies the rule to every law of the milestone.
- **Emitter (`holon/gen/mlaws.py`).**
  - `Fn<A,B>` binders are emitted **erased** (`for -h: A -> B`); see Surprises.
  - `a != b` and each pair of a `cf` set are emitted in decidable form, `eq_T(a, b) == False{}`, through the type's equality (`Nat.is_eq`, `M.eq_bool`, `M.eq_list_nat`).
  - IR builtins `eq_nat`, `eq_bool`, `eq_nats`.
  - **Counter-laws of conjunctions** state the negation of one conjunct: the first conjunct the compiled model evaluates false at the witness. The record carries `failing_conjunct`.
  - **Negation of an ∃-law** (`Emitter.negation_ir`): the same binders made universal, and the claim tested by its decidable equality, `== false`. Its id is `<law_id>_neg`, and it gets its own 0.3 statement hash.
- **Pipeline (`holon/mpipeline.py`).** An ∃-law is never REFUTED. When the search finds no witness, the law stays UNKNOWN with `bounded_negative: {H, space}` (the search bound and the number of candidates tried). Its negation is run through the proof generators; the result is recorded as `negation: {law_id, statement_hash, status, laws, proof, generator, statement, attempts}`, and its files are kept under `gen/<law>/neg/`.
- **Proof classes (`holon/gen/mproofs.py`).** They are appended after the existing ones, so M0 and M1 dispatch is unchanged.
  - `act_split`: one ∀ binder of type `Act` and no premises. It matches the action constructor, then proves each conjunct by `{==}`.
  - `hyp`: the claim is one of the rendered premises.
- **Explorer (`holon/js/explore.mjs`).**
  - It evaluates the builtins, `app` terms, `cf` and `neq`.
  - `Fn<Nat,Nat>` candidates are the fixed family {id, zero, succ}.
  - ∃-laws over finite candidate sets (Act, Nat, Bool, Fn) are enumerated.
  - A trace whose success the statement tests (`runs_ok(p, s0)`) now also gets candidates that end in one failing action. Before this, only successful prefixes were tried, so a `runs_ok` claim could never be refuted. No M0/M1 law has this shape, and every M1 witness is unchanged.
- **Non-vacuity.** The `cf` premise of `L3_cf` is inhabited by the identity (`exs h: Nat -> Nat`, witness `(x => x)`, CF by `{==}`), found by the explorer's search and checked by bend and BendTT.
- **Probe `bend/notes/p_ir03_fn_verdict/`.** It is hand-written and checks under bend and `--verdict`. It holds four laws:
  - the decidable rendering of `L3_cf`;
  - the `!=` form with an erased binder (CF is symmetric);
  - both directions of `h(a) != h(b)` ⟺ `Nat.is_eq(h(a), h(b)) == False` over all Nat.

## Surprises

- **Bend function binders cannot be reusable.** A function value is `Type`, never `Data`. So `for +h: Nat -> Nat` is rejected ("its type must be Data"), and an affine `for h` cannot be applied twice ("consumed more than once"). A statement that applies `h` at two points, which every CF statement does, can only reason through equations about `h`, never by running it.
  - The prompt asked for CF "emitted as pairwise inequality premises". The emitter uses the equivalent decidable form instead, `Nat.is_eq(h(a), h(b)) == False{}`, because a proof cannot compute `Nat.is_eq(h(a), h(b))` from `h(a) != h(b)` without running `h` twice.
  - The probe proves the two forms equivalent on every pair of Nat. The `!=` form still works for statements that need no computation on `h` (probe law `cf_sym`).
  - This bounds what M2 can say about hash parameters: a model that calls `h` more than once per step cannot take `h` as a binder. Such models need `h` as a top-level definition (a stand-in, as today) or an erased parameter used only in equations.
- **A `runs_ok` claim was unrefutable** by the 0.2 search, which tried only successful prefixes for a trace from s0 (see Done). A planted false conjunction exposed it.
