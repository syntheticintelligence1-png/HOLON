### The toolchain: `holon/frontends/go/ssadump/{main.go, go.mod, go.sum}`

- A generic Go program, module `holon.local/ssadump`, `go 1.24.0`, requiring `golang.org/x/tools v0.36.0` directly. Its `go.sum` is exactly the eight lines of `_i18.GO_SUM_ALLOWED` (the two required x/tools lines among them). x/tools resolved through the network proxy into the user's module cache (`/root/go/pkg/mod`); there is no `vendor/` anywhere under `holon/frontends`.
- `ssadump -dir DIR PATTERN...` loads the matched packages with `go/packages` (syntax and type information for them, type information of dependencies from export data), creates SSA packages for every imported package from types only, builds go/ssa for the matched packages and prints one JSON document, `holon-ssadump/0.1`:
  - `packages` (import path, name, directory, compiled files relative to `-dir`);
  - `globals`;
  - `functions`, all of `ssautil.AllFunctions` that belong to a matched package, sorted by `Function.String()`. Each carries its `Synthetic` text, parent, position, parameters, free variables, results, blocks (predecessors, successors, immediate dominator) and instructions (operands as `{"v"}`, `{"param"}`, `{"free"}`, `{"const"}`, `{"global"}`, `{"func"}`, `{"builtin"}`; type; position; the kind's own fields: binop/unop, field name, alloc heap/comment, phi edges, extract index, assert type, call mode/callee/method/args/`(` position, closure function). It also lists the For/Range statements of its own body (position, end, and whether the statement has a loop condition), closures excluded;
  - `types`, every type mentioned, keyed by its `go/types` string with full package paths (kind, underlying, element, length, fields, integer size and signedness).
  It names no target and prints no absolute path, time or host name.
- The extractor builds it with `go build -trimpath` (`GOWORK=off GOFLAGS=-mod=readonly GOTOOLCHAIN=local`, cwd `holon/frontends/go/ssadump`, output outside the repo) into `~/.holon/tools/ssadump/<first 16 hex of sha256(main.go+go.mod+go.sum)>/ssadump`. The go toolchain is the `go` on PATH, else `/usr/local/go/bin/go`. `go version` must print `config/holon.json` `replay.go_version`, else exit 2 and nothing written.

### The extractor: `holon/frontends/go/` (pure Python over the ssadump output)

- `extract.py`: the CLI `python -m holon extract go [--milestone M2] [--root DIR] [--config PATH] [--src DIR] [--out-dir DIR] [--doc STEM ...]` and the API `FRONTEND_VERSION = "holon-go/0.1"`, `main`, `extract(config_path, src, root=None) -> {stem: doc}`, `render(doc)`. It also does:
  - config validation;
  - source resolution (`{"path"}` or `{"config", "key"}`);
  - the scratch workspace: `go.work`, `go.work.sum` and every `use` directory, else the whole tree, skipping `.git`, `node_modules`, `.env*` and `bunfig.toml`; `--src` is never written;
  - the provenance (`extraction.tool`, `config`, `inputs`) and the assumptions (four generic, plus `go-prim:<name>` for every primitive named in the document's `go` section).
  Every package of every document is analyzed in every run, and all documents are rendered before any is written. Exit 2 (nothing written) covers a missing or wrong toolchain, a helper that cannot be built, packages that do not load or type-check, and missing or malformed inputs.
- `ssaload.py`: the ssadump document as functions, blocks and instructions, with referrers, dominance, CFG reachability, back edges and the types table.
- `terms.py`: terms, atoms and cells as tuples. It folds constants (Go integer semantics, wrapped to the operation's type) and len/cap. It holds the linear normal form of atoms and the reasoner:
  - assumed atoms by normal form;
  - one-variable interval reasoning (`len` ≥ 0; `cap(x)` ≥ the lower bound of `len(x)`; points substituted as constants; `v != c` endpoint removal; iterated to a fixpoint in fact order);
  - nil folding by the error rule.
- `flow.py` (the flow-insensitive view of one function):
  - terms built from definitions, phis as `["var", name, comment]`;
  - loads from the function's own memory by the one dominating store with no other store on the way;
  - dominator-tree edge atoms;
  - natural loops with span, depth, counted/range/unbounded, iv, init, step, cmp, limit, fuel and exits;
  - the loop facts;
  - the bounds-checked sites (`index`, `slice`, `prim`, `convert`, `panic`, `assert`) with their bound atoms.
- `paths.py`: path enumeration of loop-free functions. It runs depth first with true successors first and a 512-path limit. Static calls of loop-free, non-recursive analyzed functions are inlined to depth 4, closures included (their bindings become the free variables). Memory is modelled per path:
  - arrays as cells (zero when fresh);
  - structs as fields;
  - a by-value parameter's copy reads as field terms of the parameter until stored;
  - Put*/copy/index writes become cells;
  - memory passed to an opaque call is havocked.
  At each site every bound atom the reasoner does not imply splits off a panic path. The layout of a function's own fixed-length byte allocation is recorded at every return that returns it.
- `analyses.py`: the sections:
  - functions (paths, `paths_reason`, sites with status and witness);
  - encoders, decoders, predicates, matches, absences, patches;
  - backing cases, writes, stores, lost writes;
  - call edges, flows (uses, `held_across`, `opaque_between`, `into` to `flow_depth`);
  - loops;
  - coverage and debt.
- `spec/schemas/facts_0_3_go.schema.json` closes the document. It uses only the mini-schema keywords (type, required, properties, additionalProperties, enum, const, pattern, items, min/maxItems, $ref). It rejects a bare envelope and any frontend other than `go`. The five documents also validate against I17's `spec/schemas/facts_0_3.schema.json` as it stands in the I17 worktree (checked read-only before the merge).

## Surprises

1. **The prereg grammar checker could not run on any document** (instrument bug; amended). `tests_m2/_i18.py::term_problems` built its sub-term table as a dict literal, so every value was evaluated before `.get(tag)`. `a[1]` raised `IndexError` for every term with fewer than two arguments (`["const", v]`, `["param", p]`, `["len", X]`, `["nil"]`). As a result `TestExtraction.test_terms_atoms_cells_and_sections_follow_the_grammar` and `TestToyDocuments.test_two_documents_valid_and_deterministic` crashed for every extractor. The fix wraps each entry in a lambda and calls only the selected one; the sub-terms checked per tag are unchanged. The line is in `spec/M2/amendments.jsonl` (iteration I18, test `tests_m2/_i18.py::term_problems`), and the prereg audit prints it as amended.
2. **Contract interpretations.** Each is generic and documented in the code; each is a point the contract leaves open or states more narrowly.
   - *Capacity folds like length.* `cap(s[lo:hi:max])` and `cap` of a fixed allocation fold to constants when the bounds and the length are constant. The contract names only `len` folding. Without the cap rule, `copy(data[i*31:i*31+31], …)` (blob.go:51) would stay open: `cap(data)` would be a second variable beside `i`.
   - *The universal facts fold.* Atoms that hold for every x by `0 <= len(x) <= cap(x)` (and `0 <= cap(x)`) are dropped from bounds like constant-true atoms, so `b[:]` and `x[a:]`'s `len(x) <= cap(x)` are not sites.
   - *Refutation by a negated assumption.* An atom whose negation has the normal form of an assumed atom is refuted, besides the contract's interval rule, so path sets hold no branch contradicting its own condition.
   - *Allocations are not nil.* In path enumeration, a pointer to or slice of memory the path allocated compares unequal to nil, besides the error rule's nil folding.
   - *Dynamic callees.* `dynamic:<value>` names a function-typed field by its selection `(T).f` (as go/ssa names selections), a parameter or free variable by its name, a package variable by its qualified name, and any other value by its SSA name; an interface call is `dynamic:<method>`. R2's guard check expects a name ending in `).isBatchV2Upgraded`, and the field `isBatchV2Upgraded func(uint64) bool` is not a method.
   - *Go and defer sites.* The site of a `go` or `defer` edge is the go/ssa position of the Go/Defer instruction (the keyword). Calls use the `(`. For `go func(){…}()` the `(` is on the closing line of the literal, and P12 names derivation.go:200, the `go` keyword.
   - *Header exits.* A loop has a header exit only when its statement has a loop condition (every range statement, a for statement with a condition). In `for {}` the header's first `if` belongs to the body, and its exits classify as return/panic/other. This matches the toy's `Forever` and P14's DecodeTxsFromBytes.
   - *Witness loops.* The loop whose induction variable gives a witness is chosen the way the loop facts are: its in-loop header successor dominates the site. The error branch of RetrieveBlobBytes returns, so it lies outside the natural loop.
   - *Zero values.* An unset field of a composite literal reads as the zero of its type: `["const", 0]`, `["bool", false]`, `["str", ""]`, `["nil"]`, or `["zero", T]` for structs and arrays. The contract says `["zero", type]`, which the term grammar reserves for composite zero values.
   - *Opaque calls havoc.* Local memory passed to an opaque call (a call that is not a primitive, not encoding/binary and not inlined) has unknown cells afterwards. The contract does not say; it is the sound reading of go-opaque-calls.
   - *Decoders and predicates.* "Exactly one parameter of a byte-slice type" is read as exactly one of the parameters having that type.
   - *Every loop-free function is enumerated.* Path sets are computed for every loop-free function, not only the codec-shaped ones whose paths are listed. The contract makes a loop-free function's site open iff a path ends at it. So loop-free non-codec functions over 512 paths get `paths_reason: "path_limit"` and a path_limit debt entry (5 of the 9).
   - *Unsupported constructs.* Only `select`, `range`/`next` (impossible in a loop-free function) and a deferred call that may recover count as unsupported: an analyzed deferred callee whose body calls `recover`, or a dynamic one. go/ssa gives every function with a `defer` a recover block, so "has a recover block" would have flagged every mutex unlock.
3. **The length registry is per function.** A first version kept one global registry from terms to array lengths. `["param", "b"]` then picked up the 131072-byte length of an unrelated `b *kzg4844.Blob`, which folded `len(b) == 0` in `Version` and dropped its error path. Terms over parameters are scoped to their function (path enumeration substitutes callee parameters), so each function and each enumeration now keeps its own. The bug was found before any document was committed.
4. **All 14 predictions passed on the first full Morph extraction after the dynamic-callee naming and the go/defer site rule above.** Before those two rules, P12 (go edge site) and R2 (guard name) failed. Both rules are generic, so they are reported here, not hidden.
5. **Document size.** morph_batch is 12.8 MB (see Done). The contract bounds paths only by `max_paths` per function. The prereg note expected "a few MB"; the lead may want a size rule rather than a limit.
6. `spec/M2/facts/` did not exist at the base. I17 also writes there (`morph_header.extracted.json`), and the `.extracted.json` exclusion keeps all of these out of `fact_documents('M2')`.
7. **The shared `fact_documents` hunk moves the generator hash of every M1 and M2 record.** `holon.records.generator_files` reaches `holon/diagram/__init__.py` from the holon-ir/0.2 and 0.3 generators.
