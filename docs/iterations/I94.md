## Surprises
- **BendTT's budget is per definition, and its conversion check evaluates.** I tried four shapes:
  1. The first proof checked the whole claim in one definition. It ran out of fuel in `cz`.
  2. A core-plus-lemmas proof (`hm` the migration, `ha` and `hb` the two answers, `hc` the core) moved the failure to
     `ha`. That is the legacy registry's run of `slash`, whose 256-bit products the kernel evaluates bit by bit.
  3. EXT1's small-factor products made `ha` fit. But the rewriting of `cz` from the lemmas then ran out of fuel too:
     the kernel's conversion check normalizes the claim itself.
  4. Evaluating the claim once (the migration no longer computed twice) with match-based shifts still runs out in
     `cz`.

  Measured alone, the migration, `getStakersFromBitmap` and the slash answer each fit the budget.
- **model3 had no return data.** Before EXT1's return term, every callee answer was empty, so the linked commit
  reverted ("only active staker allowed").
- **The migration needs the callees' code.** V11's `initialize4` checks that the Submitter holds code, so the linked
  machine gives each callee I83's stand-in code.
- **The prereg's witness held exactly:** committer s1, bitmap 2, k = 1, and the 0.2 ether answer.
- **The record's top-level `replay` reads `not_applicable`, as an UNKNOWN record's does.** The passed replay is in the
  record's `attempts` and in `replay/M3/cutover/report.json`.
