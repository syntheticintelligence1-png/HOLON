# I104: role inference. `holon roles` writes the role sidecars for any target from its extracted documents

**The gap.** On every target but Morph, the rule producers have no input. PAR's Go sub-forms read
`spec/<M>/lib/go_laws.json`, the codec layer reads `link.json` and the Go-op layer reads `go_ops.json`. Each assigns
roles (which extracted fact plays which part) and states no value. Only Morph has them, written by hand.

## What was built

- **`holon roles`** (`holon/roles/`, outside every generator closure). It reads the extracted documents and writes the
  manifest `roles.json` (holon-roles/0.1) and every sidecar it has a role for, in the readers' own formats:
  - `go_laws.json` (holon.gox.basis);
  - `link.json` (holon.frontends.link and the codec layer);
  - `go_ops.json` (holon.diagram.goops);
  - `derive_extracted.json` (the adoption list);
  - the typed `sort_types.json`, `disch.json`, `undo.json` and `fact.json`, with no hypothesis.
- **The static inferencer** (`holon/roles/infer.py`), the primary channel. Every role records its rule and the facts it
  rests on:
  - `link_tag_length`: a Solidity loader edge and a Go tagged predicate whose accepted (first byte, length) pairs
    intersect, read by `holon.frontends.link`'s own readers.
  - `link_value`: a Solidity constant and a Go package variable with equal bytes. A value with fewer than two distinct
    bytes is no evidence.
  - `go_ops_carrier`: goops' own definition (one parameter of type T, last result error), applied to every
    non-builtin, non-stdlib carrier.
  - `gox_document`: the Go document with the most go_round_trip and go_branch basis elements.
  - `hash_store`: the Go functions returning the config's hash primitive over one preimage, paired with a Solidity
    keccak256-over-memory store. A function that holon.gox's basis or model refuses is rejected, because it would make
    the whole Go part refuse.
  - `transitions_documents`: the typed sidecars.

  Names are tie-breakers only. Rule R3's test renames every constant and global and gets the same link roles. Two
  facts with equal names and unequal values get no link.
- **The AI proposal channel** (`holon/roles/propose.py`). A proposal file (holon-roles-proposed/0.1) is data, read with
  its sha256:
  - proposer `"agent"`; a `model` key anywhere refuses the file;
  - merged in mode `static+ai` only, and static wins on an id or on a fact it already assigns;
  - a proposal the producer cannot build is dropped, with its reason.
- **Wiring.**
  - `--install` places each sidecar under `spec/<M>/lib/` only where none exists, so a hand sidecar wins.
  - `--install --roles auto` replaces the three role sidecars (for a scratch root), never the typed ones.
  - `holon eval holon --roles static|static+ai [--proposed P]` is an opt-in for I107. It defaults to off, so I51's run
    is unchanged.
- **Provenance** (`holon/roles/provenance.py`). Each law gets `roles_source` (`static`, `ai_proposal` or `hand`) from
  the role it was derived through. `classify` makes a REFUTED law through a generated role a `role_defect`, unless its
  replay confirms, in which case it is `candidate_role_unconfirmed`. Neither is ever a finding.
- **The instrument** `tools/i104_roles_experiment.py` (morph, planted, smoke) writes `results/M6/I104/`.

## Soundness argument

1. A role selects facts and never states a value. A law produced through a role is a claim about the selected facts,
   and Bend decides it. A wrong role therefore changes *which* claim is made, never *whether* a claim is checked.
2. PROVED means the checker accepted the proof of the stated claim. Through a wrong role, that claim concerns facts
   nobody meant: true, so not a false PROVED. It is reported with `roles_source` and never read as the intended
   property.
3. A REFUTED needs a replay on the real code (G6). Through a generated role, a REFUTED whose replay does not confirm
   is a `role_defect`. One whose replay confirms is `candidate_role_unconfirmed`, a real behaviour on an input a
   generated role chose, which a person must judge (in particular the carrier's reach). Neither is a finding. Observed:
   the two go_branch counter-laws checked, the replay was of another witness, and the laws ended UNKNOWN.
4. No premise is ever added. The generated `go_laws.json` has no compression role (enc null, `hypz_len` null) and the
   typed sidecars have no hypotheses. A law is at most stronger than the hand one, so it is more often UNKNOWN or
   REFUTED-unreplayed, never wrongly PROVED.
5. A role the producer would refuse is rejected or dropped before it is written: goops' carrier and op checks, gox's
   basis reasons and model debt. A wrong proposal cannot block derive.
6. Inference never overrides a hand sidecar outside `--roles auto`, which is used only in scratch roots. Morph's
   committed sidecars are unchanged (R1), and no M0-M3 output moved (R2).
7. Limit: a `link_value` role is equal by construction. It adds a link but can never reveal a value mismatch, which is
   a coverage loss, not a false finding.

## Surprises

- **Derive cannot take a Go-only target even with roles** (P4's miss above). The I51 gap "no producer" has a second
  layer behind the missing sidecars: the codec-layer rebuild.
- **Several Morph Go documents carry the same facts.** M2's batch, nodetypes and both M3 documents all hold `validate`,
  and the two M3 documents are supersets of one another. Single-document sidecars (go_ops, go_laws) force a choice
  that no semantic rule makes. Ties are broken by codec facts, op count and path, and the choice is recorded.
- **The first static run crashed the whole Go part.** `aggregateBlobHashes` passes the basis but gox's model refuses
  its preimage. The same happened with a planted `[]byte` carrier in codecs. Both led to producer checks in the
  inferencer, and to the two contract amendments:
  - `test_b5`: R4 did not foresee that refusal;
  - `test_p2`: the prereg's role-dependence rule counted `l1_counts` (from the hand `go_counts.json`) and
    `link_domain` (which reads none of the generated sidecars), and both are truthfully `roles_source: hand`.
- **`holon land dirty --milestone M3` reports 204 dirty laws** ("read config/holon.json changed") on the base `5bae37d7`
  itself. This branch's set is identical, so it adds none.
- The new Go-op laws over own-package carriers mostly fail at binding: the op's ok-domain names no kernel entry. They
  end UNKNOWN (the run refuses them), one law at a time and about a minute each.
