The text:

RevertToSnapshot after Finalise causes a panic in extraPostTxFilter error path
The extraPostTxFilter hook in the block production loop calls RevertToSnapshot on a snapshot ID that has already been invalidated by Finalise, causing a guaranteed panic if the filter ever returns an error. During block production, ProduceBlockAdvanced creates a state snapshot before applying each transaction, then calls ApplyTransactionWithResultFilter to execute the transaction. Inside ApplyTransactionWithResultFilter, after the result filter callback succeeds, Finalise is called on the StateDB. Finalise clears the journal via clearJournalAndRefund, which calls journal.reset(), wiping all valid revision IDs.
